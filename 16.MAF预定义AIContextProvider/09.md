# [MAF预定义的AIContextProvider-09]AgentModeProvider:自由切换行为模式

LLM面对不同的任务，或者同一任务的不同阶段，可能需要不同的行为模式。通过`AgentModeProvider`，我们为Agent预定义了一套行为模式，每一种模式具有对应的系统指令。`AgentModeProvider`提供了工具让LLM自主地切换适合的行为模式，从而使得Agent能够更灵活地应对不同的任务和场景。如果不相信LLM能够正确地切换模式，我们也可以从外部调用对应的方法强行切换行为模式。

## 1. 在任务的不同阶段切换不同的行为模式

大部分情况下，交给Agent的任务都不是一蹴而就的，大都会涉及一个跨越多阶段的执行流程。以[上篇](https://blog.csdn.net/JaydenAI/article/details/161674778?spm=1001.2014.3001.5502)为演示`BackgroundAgentsProvider`提供的差旅助手为例，我们可以**出差行程安排**任务划为两个阶段：

- **行程规划阶段**:在这个阶段，Agent需要和用户进行多轮的交互来确认出差的需求和偏好，并根据这些信息制定一个详细的行程规划方案。在这个阶段，Agent需要表现得像一个贴心的秘书，善于倾听和理解用户的需求，并能够清晰地表达自己的建议；
- **行程执行阶段**:在这个阶段，Agent需要根据已经确认的行程规划方案来完成机票和酒店的预订工作。在这个阶段，Agent需要表现得像一个高效的执行者，能够迅速地完成任务，并且在遇到问题时能够及时地向用户反馈。

`AgentModeProvider`在默认情况下就提供了这两种模式：`plan`和`execute`，刚好适用于这个场景。为此我们将演示程序改写成如下的形式：我们在创建Agent的时候注册了用于购买机票和预订酒店的工具和一个`AgentModeProvider`对象。我们利用指定的系统指令明确告诉LLM分别采用`plan`和`execute`两种模式来完成行程规划和行程执行两个阶段的任务，并且告诉它可以通过调用`mode_set`工具来切换模式。

## 2. AgentModeProviderOptions

当我们创建`AgentModeProvider`的时候，可以传入作为其配置选项的`AgentModeProviderOptions`对象。作为最核心的配置选项，`AgentModeProviderOptions`的`Modes`属性提供了预设定的行为模式。具体的模式通过内嵌的`AgentMode`定义，每个模式包含一个`Name`和`Description`。我们可以通过`DefaultMode`属性设置默认的模式，还可以通过`Instructions`属性针对这种基于模式的推理方案设置一个系统提示词。

```csharp
public sealed class AgentModeProvider : AIContextProvider
{
    public AgentModeProvider(AgentModeProviderOptions? options = null);
}

public sealed class AgentModeProviderOptions
{
	public sealed class AgentMode
	{
		public string Name { get; }
		public string Description { get; }
		public AgentMode(string name, string description);
	}

	public string? Instructions { get; set; }
	public IReadOnlyList<AgentMode>? Modes { get; set; }
	public string? DefaultMode { get; set; }
}
```

### 2.1 默认模式

如果没有显式指定`AgentModeProviderOptions`，默认采用`plan`和`execute`两种模式，它们对应的描述文本如下：

plan:

```markdown
Use this mode when analyzing requirements, breaking down tasks, and creating plans. This is the interactive mode — ask clarifying questions, discuss options, and get user approval before proceeding.

Process to follow when in plan mode:
1. Analyze the request with the purpose of building a research plan.
2. Create a list of todo items.
3. If needed, use the provided tools to do some exploratory checks to help build a plan and determine what clarifying questions you may need from the user.
4. Ask for clarifications from the user where needed.
  1. Ask each clarification one by one.
  2. When asking for clarification and you have specific options in mind, present them to the user, so they can choose the option instead of having to retype the entire response.
  3. Do not proceed until you have received all the needed clarifications.
  4. Do short exploratory research if it helps with being able to ask sensible clarifications from the user.
  5. Write the plan to a memory file, so that it is retained even if compaction happens. Make sure to update the plan file if the user requests changes.
  6. Present the plan to the user and ask for approval to switch to execute mode and process the plan.
  7. When approval is granted, always switch to execute mode (using the `mode_set` tool), and follow the steps for *Execute mode*.
```

execute:

```markdown
Use this mode when carrying out approved plans. Work autonomously using your best judgment — do not ask the user questions or wait for feedback.

Process to follow when in execute mode:
1. If you don't have a plan or tasks yet, analyze the user request and create tasks and a plan. (**Skip this step if you came from plan mode**)
2. Work autonomously — use your best judgment to make decisions and keep progressing without asking the user questions. The goal is to have a complete, useful result ready when the user returns.
3. If you encounter ambiguity or an unexpected situation during execution, choose the most reasonable option, note your choice, and keep going.
4. Mark tasks as completed as you finish them.
5. Continue working, thinking and calling tools until you have the research result for the user.
```

### 2.2 默认系统指令

如果没有通过`AgentModeProviderOptions`的`Instructions`属性指定系统指令，会默认采用如下的指令文本。`{current_mode}`和`{available_modes}`是两个占位符，系统会在运行时将它们替换成当前的模式和可用的模式列表。

```markdown
## Agent Mode

- You can operate in different modes. Depending on the mode you are in, you will be required to follow different processes.
- You must check the current mode after any user input, since the user may have changed the mode themselves,
  e.g. the user may have switched to 'plan' mode after a previous research task finished in 'execute' mode, meaning they want to review a plan first before execution.
  
Use the mode_get tool to check your current operating mode.
Use the mode_set tool to switch between modes as your work progresses. Only use mode_set if the user explicitly instructs/allows you to change modes.

You are currently operating in the {current_mode} mode.

### Mandatory Mode based Workflow

For every new substantive user request, including short factual questions, your behavior is determined by the mode you are in.

{available_modes}
```

## 3. AgentModeProvider

`AgentModeProvider`核心思路就是根据当前的行为模式，动态指定系统指令来引导LLM采用我们希望的方式进行推理。所以它需要将当前状态存储在Session中。

### 3.1 模式状态的维持

除了需要维持当前模式之外，上一个模式也会被保存下来用于实现针对模式切换的通知。这两个模式被封装在如下这个`AgentModeState`对象中。`AgentModeProvider`的`_sessionState`字段返回的`ProviderSessionState<AgentModeState>`用于实现针对此状态的读写。`StateKeys`属性返回此Session状态项对应的键为`AgentModeProvider`类型名称，

```csharp
internal sealed class AgentModeState
{
	public string CurrentMode { get; set; } = "plan";
	public string? PreviousModeForNotification { get; set; }
}

public sealed class AgentModeProvider : AIContextProvider
{
    private readonly ProviderSessionState<AgentModeState> _sessionState;
    private IReadOnlyList<string>? _stateKeys;
	public override IReadOnlyList<string> StateKeys => _stateKeys ?? [_sessionState.StateKey];

    public string GetMode(AgentSession? session);
	public void SetMode(AgentSession? session, string mode);
}
```

`AgentModeProvider`定义了`GetMode`和`SetMode`两个方法来获取和设置当前的模式，它们正式借助`_sessionState`字段返回的`ProviderSessionState<AgentModeState>`来实现的。

### 3.2 系统指令设置和工具注册

`AgentModeProvider`针对工具(用于提取当前模式和切换模式)的注册和基于当前模式针对系统指令的指定实现在重写的`ProvideAIContextAsync`方法中完成的。

```csharp
public sealed class AgentModeProvider : AIContextProvider
{
    protected override ValueTask<AIContext> ProvideAIContextAsync(
        InvokingContext context, 
        CancellationToken cancellationToken = default);
}
```

系统指令模板中的`{current_mode}`占位符会被当前模式替换，`{available_modes}`占位符会被所有可用模式的列表替换，替换的文本通过调用如下这个`BuildInstructions`方法来生成。

```csharp
public sealed class AgentModeProvider : AIContextProvider
{ 
	private string BuildInstructions(string currentMode)
	{
		StringBuilder stringBuilder = new StringBuilder();
		foreach (AgentModeProviderOptions.AgentMode mode in _modes)
		{
			StringBuilder stringBuilder2 = stringBuilder;
			StringBuilder.AppendInterpolatedStringHandler handler = new StringBuilder.AppendInterpolatedStringHandler(5, 1, stringBuilder2);
			handler.AppendLiteral("#### ");
			handler.AppendFormatted(mode.Name);
			stringBuilder2.AppendLine(ref handler);
			stringBuilder.AppendLine();
			stringBuilder.AppendLine(mode.Description.TrimEnd());
			stringBuilder.AppendLine();
		}
		string newValue = stringBuilder.ToString();
		return new StringBuilder(_instructions).Replace("{available_modes}", newValue).Replace("{current_mode}", currentMode).ToString();
	}
}
```

我们可以利用如下这个自定义的`AIContextProvider`来查看由`AgentModeProvider`提供的系统指令和工具信息。

```markdown
  4. Do short exploratory research if it helps with being able to ask sensible clarifications from the user.
5. Write the plan to a memory file, so that it is retained even if compaction happens. Make sure to update the plan file if the user requests changes.
6. Present the plan to the user and ask for approval to switch to execute mode and process the plan.
7. When approval is granted, always switch to execute mode (using the `mode_set` tool), and follow the steps for *Execute mode*.

#### execute

Use this mode when carrying out approved plans. Work autonomously using your best judgment — do not ask the user questions or wait for feedback.

Process to follow when in execute mode:
1. If you don't have a plan or tasks yet, analyze the user request and create tasks and a plan. (**Skip this step if you came from plan mode**)
2. Work autonomously — use your best judgment to make decisions and keep progressing without asking the user questions. The goal is to have a complete, useful result ready when the user returns.
3. If you encounter ambiguity or an unexpected situation during execution, choose the most reasonable option, note your choice, and keep going.
4. Mark tasks as completed as you finish them.
5. Continue working, thinking and calling tools until you have the research result for the user.
```
