# [MAF预定义的AIContextProvider-11]ShellEnvironmentProvider：为LLM提供当前的Shell环境信息

 让LLM直接生成Shell命令来执行是一个很常见的用例场景了，但是Shell多种多样，生成怎样的Shell命令应该取决于当前的Shell环境（比如bash、powershell、cmd等）。`ShellEnvironmentProvider`就是为LLM提供当前的Shell环境信息的一个`AIContextProvider`实现。`ShellEnvironmentProvider`提供了探测本地Shell环境的能力，它不仅能够探测当前的`ShellFamily`的类型，还能检测指定CLI工具（比如`Python`、`NodeJS`和`dotnet`等）是否存在。

## 1. 生成于当前Shell环境兼容的命令

在如下这个演示实例中，我们创建了两个Agent，并为它们注册两个不同的`ShellEnvironmentProvider`。虽然这两个`ShellEnvironmentProvider`都使用同一个Shell执行器（`LocalShellExecutor`），但是我们通过提供的`ShellEnvironmentProviderOptions`将它们的`OverrideFamily`分别设置为`Posix`和`PowerShell`。

 ```csharp
using dotenv.net;
using Microsoft.Agents.AI;
using Microsoft.Agents.AI.Tools.Shell;
using Microsoft.Agents.AI.Workflows;
using Microsoft.Extensions.AI;
using OpenAI;
using System.ClientModel;

DotEnv.Load();

var model = Environment.GetEnvironmentVariable("MODEL")!;
var apiKey = Environment.GetEnvironmentVariable("API_KEY")!;
var endpoint = Environment.GetEnvironmentVariable("OPENAI_URL")!;

var executor = new LocalShellExecutor();
var shellEnvironmentProviderWithPosix = new ShellEnvironmentProvider(executor, new ShellEnvironmentProviderOptions { OverrideFamily = ShellFamily.Posix });
var shellEnvironmentProviderWithPowerShell = new ShellEnvironmentProvider(executor, new ShellEnvironmentProviderOptions { OverrideFamily = ShellFamily.PowerShell });
var trackingProvider = new TrackingProvider();
var chatClient = new OpenAIClient(new ApiKeyCredential(apiKey), new OpenAIClientOptions { Endpoint = new Uri(endpoint) })
    .GetChatClient(model)
    .AsIChatClient();
var agentWithPosix = chatClient
    .AsAIAgent(options: new ChatClientAgentOptions { AIContextProviders = [shellEnvironmentProviderWithPosix] });
var agentWithPowerShell = chatClient
    .AsAIAgent(options: new ChatClientAgentOptions { AIContextProviders = [shellEnvironmentProviderWithPowerShell] });
var prompt = """
    为下面的任务生成一段完整的shell脚本：

    在当前工具目录下创建子目录 app
    将子目录设置为当前工作目录
    将文本内容`print('Hello World!')` 写入创建的文件`hello.py`
    """;

var response = await agentWithPosix.RunAsync(prompt);
Console.WriteLine($"""
    Posix:
    {response}

    """);


response = await agentWithPowerShell.RunAsync(prompt);
Console.WriteLine($"""
    PowerShell:
    {response}

    """);
```

我们指定相同的提示词，调用两个搭载不同的`ShellEnvironmentProvider`的Agent。从如下的输出可以看出，LLM生成的Shell脚本是完全不同的，分别适配了它们各自的Shell环境：

````markdown

```sh

# 进入子目录
cd app || exit 1

# 将文本写入 hello.py 文件

```

PowerShell:
下面是一段符合 **PowerShell** 规范的完整脚本：

````

## 2. 将Shell环境信息转换成系统指令

`ShellEnvironmentProvider`通过将探测到的Shell环境信息转换成系统指令提供给LLM，由此来指导它生成怎样的Shell命令。我们可以通过如下的方式来查看`ShellEnvironmentProvider`转换给LLM的系统指令是什么样子的：我们根据指定的`ShellFamily`自定义了一个派生自`AIContextProvider`的`TrackingProvider`，并利用重写的`InvokingCoreAsync`方法输出当前设置的系统指令。我们将这个`TrackingProvider`和`ShellEnvironmentProvider`一起注册到Agent中，并将其置于`ShellEnvironmentProvider`之后，这样就能在Agent的请求流经`ShellEnvironmentProvider`将Shell环境信息转换成系统指令后，立刻通过`TrackingProvider`将这些系统指令输出到控制台上了。

```csharp
using dotenv.net;
using Microsoft.Agents.AI;
using Microsoft.Agents.AI.Tools.Shell;
using Microsoft.Agents.AI.Workflows;
using Microsoft.Extensions.AI;
using OpenAI;
using System.ClientModel;

DotEnv.Load();

var model = Environment.GetEnvironmentVariable("MODEL")!;
var apiKey = Environment.GetEnvironmentVariable("API_KEY")!;
var endpoint = Environment.GetEnvironmentVariable("OPENAI_URL")!;

var executor = new LocalShellExecutor();
var ShellEnvironmentProviderWithPosix = new ShellEnvironmentProvider(executor, new ShellEnvironmentProviderOptions { OverrideFamily = ShellFamily.Posix });
var ShellEnvironmentProviderWithPowerShell = new ShellEnvironmentProvider(executor, new ShellEnvironmentProviderOptions { OverrideFamily = ShellFamily.PowerShell });
var chatClient = new OpenAIClient(new ApiKeyCredential(apiKey), new OpenAIClientOptions { Endpoint = new Uri(endpoint) })
    .GetChatClient(model)
    .AsIChatClient();
var agentWithPosix = chatClient
    .AsAIAgent(options: new ChatClientAgentOptions { AIContextProviders = [ShellEnvironmentProviderWithPosix, new TrackingProvider(ShellFamily.Posix)] });
var agentWithPowerShell = chatClient
    .AsAIAgent(options: new ChatClientAgentOptions { AIContextProviders = [ShellEnvironmentProviderWithPowerShell, new TrackingProvider(ShellFamily.PowerShell)] });
var prompt = """
    为下面的任务生成一段完整的shell脚本：

    在当前工具目录下创建子目录 app
    将子目录设置为当前工作目录
    将文本内容`print('Hello World!')` 写入创建的文件`hello.py`
    """;

await agentWithPosix.RunAsync(prompt);
await agentWithPowerShell.RunAsync(prompt);

class TrackingProvider(ShellFamily shellFamily) : AIContextProvider
{
    protected override ValueTask<AIContext> InvokingCoreAsync(InvokingContext context, CancellationToken cancellationToken = default)
    {
        Console.WriteLine($"""
            {shellFamily}: 
            {context.AIContext.Instructions}

            """);
        return base.InvokingCoreAsync(context, cancellationToken);
    }
}
```

## 3. Shell执行器

MAF利用如下这个`ShellExecutor`类型提供了一个抽象的Shell执行器接口，`ShellEnvironmentProvider`就是通过这个接口来探测Shell环境的。MAF还提供了一个`LocalShellExecutor`的实现类，它是基于本地系统的Shell来执行命令的。Shell命令的执行体现在`RunAsync`方法中，通过重写虚方法`InitializeAsync`方法可以提供一些初始化的逻辑。

```csharp
public abstract class ShellExecutor : IAsyncDisposable
{
    public virtual Task InitializeAsync(CancellationToken cancellationToken = default(CancellationToken));
    public abstract Task<ShellResult> RunAsync(string command, CancellationToken cancellationToken = default);
    public abstract AIFunction AsAIFunction(string name = "run_shell", string? description = null, bool requireApproval = true);
    public abstract ValueTask DisposeAsync();
}
```

`ShellEnvironmentProvider`的功能很单一：通过系统指令为LLM提供当前的Shell环境信息，它并没有执行生成的Shell命令的能力。如果我们需要提供与之配套的能力，需要注册对应工具函数作为执行器。此时`ShellExecutor`的`AsAIFunction`方法就派上用场了，我们可以通过这个方法将`ShellExecutor`封装成一个工具函数。调用`AsAIFunction`方法的时候我们需要指定工具函数的名称、描述信息以及是否需要审批。考虑到执行Shell命令的潜在风险，`requireApproval`参数的默认值是true，所以生成的`AIFunction`会通过装饰一个`ApprovalRequiredAIFunction`引入审批流程。

## 3.1 LocalShellExecutor

作为MAF提供的针对`ShellExecutor`的实现之一，`LocalShellExecutor`允许Agent在本地系统的Shell环境中直接执行命令，它允许Agent在本地操作系统中直接执行终端/命令行脚本的核心工具组件。

```csharp
public sealed class LocalShellExecutor : ShellExecutor
{
    public LocalShellExecutor();
    public LocalShellExecutor(LocalShellExecutorOptions options);

    public override async Task<ShellResult> RunAsync(string command, CancellationToken cancellationToken = default);
    public override Task InitializeAsync(CancellationToken cancellationToken = default);
    public override AIFunction AsAIFunction(string name = "run_shell", string? description = null, bool requireApproval = true);
    public override async ValueTask DisposeAsync();
}
```

在调用构造函数创建`LocalShellExecutor`实例的时候，我们可以利用指定的`LocalShellExecutorOptions`来做一些定制化的设置，该类型定义如下：

```csharp
public sealed class LocalShellExecutorOptions
{
	public ShellMode Mode { get; set; } = ShellMode.Persistent;
	public string? Shell { get; set; }
	public IReadOnlyList<string>? ShellArgv { get; set; }
	public string? WorkingDirectory { get; set; }
	public bool ConfineWorkingDirectory { get; set; } = true;
	public IReadOnlyDictionary<string, string?>? Environment { get; set; }
	public bool CleanEnvironment { get; set; }
	public ShellPolicy? Policy { get; set; }
	public TimeSpan? Timeout { get; set; }
	public int MaxOutputBytes { get; set; } = 65536;
	public bool AcknowledgeUnsafe { get; set; }
}

public enum ShellMode
{
	Stateless,
	Persistent
}

```

具体配置选项说明如下：

- **Mode**：Shell的模式，支持`Stateless`和`Persistent`两种模式；
- **Shell**和**ShellArgv**：指定Shell的路径和启动参数，这是两个互斥的配置选项：
  - **Shell**：直接指定Shell编排文件的路径（如指定特定路径的`pwsh`）。不指定时，会读取环境变量`AGENT_FRAMEWORK_SHELL`，最后退回到系统默认值;
  - **ShellArgv**：以以数组形式传递更复杂的启动参数（第一个元素为可执行文件，后续为启动前缀参数）。
- **WorkingDirectory**: 指定生成的Shell的初始工作目录，默认为当前目录；
- **ConfineWorkingDirectory**：工作目录锁定。在持久化模式下，若将它设置为true，Agent执行每条命令前都会被自动强制`cd`回到`WorkingDirectory`。这样可以防止Agent在上一条命令中**迷路**（比如执行了cd.. 破坏了相对路径），导致下一条命令在错误的路径下运行失败；
- **Environment**：用于自定义添加或删除环境变量（传入null值可以显式删除继承过来的某个环境变量）；
- **CleanEnvironment**：若设为true，启动的Shell将不会继承宿主机当前进程的环境变量，实现环境变量级别的净化；
- **Policy**：命令拦截策略;
- **Timeout**：单条命令的超时时间。默认不超时，官方建议显式配置该值以防止Agent执行死循环或挂起的脚本；
- **MaxOutputBytes**：单次命令输出流的最大截断阈值。防止Agent因为打印海量日志（如`cat`一个大文件）而导致内存溢出，超出时会自动进行**头+尾拼接**截断；
- **AcknowledgeUnsafe**：安全确认开关。必须显式设为true，执行器才允许生成不带人工审批外壳（`ApprovalRequiredAIFunction`）的裸`AIFunction`。这是防止开发者在无意中暴露出远程代码执行漏洞的强制契约。

Mode的两种模式的差异在于：

- **Stateless**：Agent每发送一条命令，系统就会启动一个全新的、独立的终端子进程，命令执行完毕后立即销毁该进程。两次调用之间不保留任何状态。如果Agent在第一次调用时执行了`cd /app`，在第二次调用时执行`ls`，由于是全新的进程，`ls`依然会在默认路径下执行，完全感知不到上一步的`cd`。这种模式适合执行孤立的、一次性的系统查询。如果需要在多个并发用户或多租户之间共享同一个执行器实例的安全场景，因为无状态模式天然不会发生数据泄露；
- **Persistent**：在整个Agent会话期间，框架只启动一个常驻后台的终端子进程。多次调用之间，通过一种哨兵协议来标记`stdout`输出的边界，从而精准判断命令何时执行完毕并保持通道存活。调用之间的状态会得到保留，工作目录（cd）、导出的环境变量、临时定义的Shell函数以及命令历史记录，都会在后续的调用中持续生效。这种模式适合执行需要保留状态的Shell命令序列，比如先执行`cd /app`切换到某个目录下，然后执行`ls`来列出这个目录下的文件。

针对Shell命令执行的拦截策略体现在`Policy`属性返回的`ShellPolicy`对象上，`ShellPolicy`利用`Evaluate`解析待执行的命令和指定的工具目录，确定最终是否允许执行该命令。默认情况下如果指定的命令文本为空或者仅包含空白字符，会被拒绝执行。我们可以通过`denyList`和`allowList`来指定正则表达式来匹配一些被允许或拒绝的命令文本。需要注意的是，`allowList`的优先级是高于`denyList`的，也就是说如果某条命令同时匹配了`allowList`和`denyList`，那么最终的结果是允许执行。

```csharp
public sealed class ShellPolicy
{
	public ShellPolicy(
        IEnumerable<string>? denyList = null, 
        IEnumerable<string>? allowList = null);
	public ShellPolicyOutcome Evaluate(ShellRequest request);
}

public readonly struct ShellRequest(string command, string? workingDirectory = null) : IEquatable<ShellRequest>
{
	public string Command { get; } 
	public string? WorkingDirectory { get; } 
}

public readonly struct ShellPolicyOutcome(bool allowed, string? reason = null) : IEquatable<ShellPolicyOutcome>
{
	public bool Allowed { get; }
	public string? Reason { get; } 
	public static ShellPolicyOutcome Allow { get; } 
	public static ShellPolicyOutcome Deny(string reason);
}
```

**基于正则的黑白名单**在Agent安全中只是**防呆护栏**，而绝对不能作为**安全边界**。没有任何主流的Agent框架会把模式匹配（正则）作为主要的Shell防御手段。因为通过正则表达式拦截命令，可以被极其轻易地绕过。真正的安全边界只有两条：

- **人工审批**：每条命令由人类看一眼再执行；
- **容器隔离**：直接扔进Docker容器里，随便它怎么破坏。

## 3.2 DockerShellExecutor

`DockerShellExecutor`旨在Docker容器内运行shell命令。它允许 AI 代理在沙盒环境中执行代码或脚本，而不会对宿主机系统造成损害。这是一种更安全的执行环境，特别适合需要执行不受信任的代码或命令的场景。

```csharp
public sealed class DockerShellExecutor : ShellExecutor
{
	public const string DefaultImage = "mcr.microsoft.com/azurelinux/base/core:3.0";
	public DockerShellExecutor();
	public DockerShellExecutor(DockerShellExecutorOptions options);

	public override async Task InitializeAsync(CancellationToken cancellationToken = default(CancellationToken));
	public override async Task<ShellResult> RunAsync(string command, CancellationToken cancellationToken = default(CancellationToken));
	public AIFunction AsAIFunction(string name = "run_shell", string? description = null, bool? requireApproval = null);        
	public override async ValueTask DisposeAsync();
}
```

`DockerShellExecutor`的配置选项（`DockerShellExecutorOptions`）涵盖了镜像选择、容器命名、网络设置、资源限制等多个方面，允许用户根据实际需求定制化地创建和管理Docker容器来执行Shell命令。通过使用`DockerShellExecutor`，Agent可以在一个隔离的环境中安全地执行命令，避免了对宿主机系统的潜在风险。

```csharp
public sealed class DockerShellExecutorOptions
{
	public string Image { get; set; } = "mcr.microsoft.com/azurelinux/base/core:3.0";
	public string? ContainerName { get; set; }
	public ShellMode Mode { get; set; } = ShellMode.Persistent;
	public string? HostWorkdir { get; set; }
	public string ContainerWorkdir { get; set; } = "/workspace";
	public bool MountReadonly { get; set; } = true;
	public string Network { get; set; } = "none";
	public long? MemoryBytes { get; set; }
	public int PidsLimit { get; set; } = 256;
	public ContainerUser User { get; set; } = ContainerUser.Default;
	public bool ReadOnlyRoot { get; set; } = true;
	public IReadOnlyList<string>? ExtraRunArgs { get; set; }
	public IReadOnlyDictionary<string, string>? Environment { get; set; }
	public ShellPolicy? Policy { get; set; }
	public TimeSpan? Timeout { get; set; }
	public int MaxOutputBytes { get; set; } = 65536;
	public string DockerBinary { get; set; } = "docker";
}
```

各配置选项的具体含义如下：

- **Image**：指定Docker镜像，默认为微软官方提供的轻量级Linux基础镜像；
- **ContainerName**：指定容器名称，如果不指定，系统会自动生成一个随机名称；
- **Mode**：Shell的模式，支持`Stateless`和`Persistent`两种模式，含义同`LocalShellExecutorOptions`的Mode配置项；
- **HostWorkdir**和**ContainerWorkdir**：分别指定宿主机和容器内的工作目录，容器内的工作目录会被挂载到宿主机的指定路径上。`HostWorkdir`默认为当前目录，`ContainerWorkdir`默认为`/workspace`；
- **MountReadonly**：是否以只读方式挂载工作目录，默认为true；   
- **Network**：指定容器的网络设置，默认为none表示不连接网络；
- **MemoryBytes**：指定容器的内存限制，单位为字节；
- **PidsLimit**：指定容器的PID限制，默认为256；
- **User**：指定容器内运行命令的用户，默认为`ContainerUser.Default`表示使用镜像的默认用户；
- **ReadOnlyRoot**：是否以只读方式挂载根文件系统，默认为true；
- **ExtraRunArgs**：指定额外的docker run参数，以字符串数组的形式传入；
- **Environment**：指定容器内的环境变量，以键值对的形式传入；
- **Policy**：命令拦截策略，含义同`LocalShellExecutorOptions`的Policy配置项；
- **Timeout**：单条命令的超时时间；
- **MaxOutputBytes**：单次命令输出流的最大截断阈值；
- **DockerBinary**：指定Docker CLI的路径，默认为系统环境变量中的docker命令。

## 4. ShellEnvironmentProviderOptions

`ShellEnvironmentProviderOptions`承载了`ShellEnvironmentProvider`的配置选项，具体定义如下：

```csharp
public sealed class ShellEnvironmentProviderOptions
{
	public IReadOnlyList<string> ProbeTools { get; init; } = [ "git", "dotnet", "node", "python", "docker" ];
	public ShellFamily? OverrideFamily { get; init; }
	public TimeSpan ProbeTimeout { get; init; } = TimeSpan.FromSeconds(5L);
	public Func<ShellEnvironmentSnapshot, string>? InstructionsFormatter { get; init; }
}

public sealed record ShellEnvironmentSnapshot(
    ShellFamily Family, 
    string OSDescription, 
    string? ShellVersion, 
    string WorkingDirectory, 
    IReadOnlyDictionary<string, string?> ToolVersions);

```

各配置选项的具体含义如下：

- **ProbeTools**：指定一组工具的名称，`ShellEnvironmentProvider`会探测这些工具是否在当前Shell环境中可用，并将结果提供给LLM。默认会探测`git`、`dotnet`、`node`、`python`和`docker`这五个工具；
- **OverrideFamily**：覆盖探测到的`ShellFamily`类型，强制`ShellEnvironmentProvider`按照指定的`ShellFamily`来生成系统指令。这个选项主要用于测试和演示，实际使用中一般不需要设置；
- **ProbeTimeout**：探测Shell环境的超时时间，默认是5秒；
- **InstructionsFormatter**：一个可选的委托函数，用于自定义格式化提供给LLM的系统指令文本。默认会使用内置的格式化逻辑来生成系统指令文本，如果提供了这个委托函数，`ShellEnvironmentProvider`就会调用它来生成系统指令文本。

## 5. ShellEnvironmentProvider

由于`ShellEnvironmentProvider`需要通过执行Shell命令来探测Shell环境，所需在构建`ShellEnvironmentProvider`实例的时候，除了可以提供作为配置选项的`ShellEnvironmentProviderOptions`对象外，还需要提供一个`ShellExecutor`对象，探测配置选择`ProbeTools`中指定的工具是否可用也依赖于这个`ShellExecutor`对象来执行相应的Shell命令。

```csharp
public sealed class ShellEnvironmentProvider : AIContextProvider
{
	public ShellEnvironmentSnapshot? CurrentSnapshot { get;  }
	public ShellEnvironmentProvider(ShellExecutor executor, ShellEnvironmentProviderOptions? options = null);
	public async Task<ShellEnvironmentSnapshot> RefreshAsync(CancellationToken cancellationToken = default(CancellationToken));
	protected override async ValueTask<AIContext> ProvideAIContextAsync(InvokingContext context, CancellationToken cancellationToken = default(CancellationToken));
}
```

`ShellEnvironmentProvider`的使命是根据探测Shell环境并将其体现生成的系统指令上。从`ShellEnvironmentProviderOptions`的`InstructionsFormatter`属性类型可以看出，这个用于格式化系统指令的委托将`ShellEnvironmentSnapshot`作为输入参数。`ShellEnvironmentSnapshot`可视为`ShellEnvironmentProvider`探测到的Shell环境信息的一个快照，它包含了当前`Shell`环境的`ShellFamily`类型、操作系统描述信息、Shell版本信息、当前工作目录以及指定工具的版本信息等。`ShellEnvironmentProvider`的`CurrentSnapshot`属性返回的正是作为Shell环境快照的`ShellEnvironmentSnapshot`对象。`RefreshAsync`方法会强制`ShellEnvironmentProvider`重新探测Shell环境并返回最新的`ShellEnvironmentSnapshot`对象。

在重写的`ProvideAIContextAsync`方法中，它会对探测到的`ShellEnvironmentSnapshot`进行格式化来生成系统指令，并体现在返回的`AIContext`对象的`Instructions`属性中。如果通过`ShellEnvironmentProviderOptions`的`InstructionsFormatter`属性提供了自定义的系统指令格式化函数，则会直接使用它来完成系统指令的格式化。否则会调用如下这个静态方法`DefaultInstructionsFormatter`来根据`ShellEnvironmentSnapshot`生成系统指令文本。

```csharp
public sealed class ShellEnvironmentProvider : AIContextProvider
{
    public static string DefaultInstructionsFormatter(ShellEnvironmentSnapshot snapshot)
	{
		StringBuilder stringBuilder = new StringBuilder();
		stringBuilder.AppendLine("## Shell environment");
		if (snapshot.Family == ShellFamily.PowerShell)
		{
			string value = ((snapshot.ShellVersion == null) ? string.Empty : (" " + snapshot.ShellVersion));
			stringBuilder.Append("You are operating a PowerShell").Append(value).Append(" session on ")
				.Append(snapshot.OSDescription)
				.AppendLine(".");
			stringBuilder.AppendLine("Use PowerShell idioms, NOT bash:");
			stringBuilder.AppendLine("- Set environment variables with `$env:NAME = 'value'` (NOT `NAME=value`).");
			stringBuilder.AppendLine("- Change directory with `Set-Location` or `cd`. Paths use `\\` separators.");
			stringBuilder.AppendLine("- Reference environment variables as `$env:NAME` (NOT `$NAME`).");
			stringBuilder.AppendLine("- The system temp directory is `[System.IO.Path]::GetTempPath()` (NOT `/tmp`).");
			stringBuilder.AppendLine("- Pipe to `Out-Null` to suppress output (NOT `> /dev/null`).");
		}
		else
		{
			string value2 = ((snapshot.ShellVersion == null) ? string.Empty : (" " + snapshot.ShellVersion));
			stringBuilder.Append("You are operating a POSIX shell").Append(value2).Append(" session on ")
				.Append(snapshot.OSDescription)
				.AppendLine(".");
			stringBuilder.AppendLine("Use POSIX shell idioms (bash/sh).");
			stringBuilder.AppendLine("- Set environment variables for the next command with `export NAME=value`.");
			stringBuilder.AppendLine("- Reference environment variables as `$NAME` or `${NAME}`.");
			stringBuilder.AppendLine("- Paths use `/` separators.");
		}
		if (!string.IsNullOrEmpty(snapshot.WorkingDirectory))
		{
			stringBuilder.Append("Working directory: ").AppendLine(snapshot.WorkingDirectory);
		}
		List<string> list = (from kv in snapshot.ToolVersions
			where kv.Value != null
			select kv.Key + " (" + kv.Value + ")").ToList();
		List<string> list2 = (from kv in snapshot.ToolVersions
			where kv.Value == null
			select kv.Key).ToList();
		if (list.Count > 0)
		{
			stringBuilder.Append("Available CLIs: ").AppendLine(string.Join(", ", list));
		}
		if (list2.Count > 0)
		{
			stringBuilder.Append("Not installed: ").AppendLine(string.Join(", ", list2));
		}
		return stringBuilder.ToString().TrimEnd();
	}
}
```

## 5. 注册Shell执行工具

由于`ShellEnvironmentProvider`的功能单一，它只负责探测Shell环境并将其转换成系统指令提供给LLM，它并不具备执行Shell命令的能力。如果我们需要提供与之配套的能力，需要注册对应工具函数。此时`ShellExecutor`的`AsAIFunction`方法就派上用场了，我们可以通过这个方法将`ShellExecutor`封装成一个工具函数，并注册到Agent中。

```csharp
using dotenv.net;
using Microsoft.Agents.AI;
using Microsoft.Agents.AI.Tools.Shell;
using Microsoft.Agents.AI.Workflows;
using Microsoft.Extensions.AI;
using OpenAI;
using System.ClientModel;

DotEnv.Load();

var model = Environment.GetEnvironmentVariable("MODEL")!;
var apiKey = Environment.GetEnvironmentVariable("API_KEY")!;
var endpoint = Environment.GetEnvironmentVariable("OPENAI_URL")!;

var executor = new LocalShellExecutor(options: new LocalShellExecutorOptions {  AcknowledgeUnsafe = true});
var shellEnvironmentProvider = new ShellEnvironmentProvider(executor, new ShellEnvironmentProviderOptions { OverrideFamily = ShellFamily.PowerShell });
var agent = new OpenAIClient(new ApiKeyCredential(apiKey), new OpenAIClientOptions { Endpoint = new Uri(endpoint) })
    .GetChatClient(model)
    .AsIChatClient()
    .AsAIAgent(options: new ChatClientAgentOptions { 
        AIContextProviders = [shellEnvironmentProvider],
        ChatOptions = new ChatOptions {Tools= [executor.AsAIFunction(requireApproval:false)]}
    });

var prompt = """
    为如下的任务生成一段完整的shell脚本，并执行：

    - 在当前工具目录下创建子目录 app
    - 将子目录设置为当前工作目录
    - 将文本内容`print('Hello World!')` 写入创建的文件`hello.py`
    -执行命令`python hello.py`，并返回命令的输出结果
    """;

var response = await agent.RunAsync(prompt);
var index = 1;
foreach (var message in response.Messages)
{
    Console.WriteLine($"""
        {new string('-', 30)} Message {index++} {new string('-', 30)}
        Role: {message.Role}
        Contents:
        """);

    foreach (var content in message.Contents)
    { 
        var contentText = content switch
        {
            TextContent textContent => textContent.Text,
            FunctionCallContent functionCallContent => $"Function Call: {functionCallContent.Name}[{functionCallContent.CallId}]",
            FunctionResultContent functionResultContent => $"Function Result:{functionResultContent.Result}",
            _ => content.ToString() ?? ""
        };
        Console.WriteLine(contentText);
        if (content is FunctionCallContent callContent)
        { 
            foreach(var (k,v) in callContent.Arguments!)
            {
                Console.WriteLine($"    {k}: {v}");
            }
        }
    }

}
Console.WriteLine($"""
    Response:
    {response}

    """);
```

为了运行在不经过审批的情况下执行Shell命令，我们在创建`LocalShellExecutor`实例的时候，提供了一个对应的`LocalShellExecutorOptions`，并将`AcknowledgeUnsafe`设置为`true`。在调用`AsAIFunction`方法的时候将`requireApproval`设置为`false`。需要注意的是，这样做会存在安全风险，可能会导致远程代码执行漏洞，所以一定要确保在安全的环境下使用，并且不要在生产环境中暴露这样的功能。在作为调用Agent的提示词中，我们利用自然语言的方式告诉Agent利用Shell命令生成并执行一个Python脚本。为了更清晰地展示Agent的执行过程，我们输出了响应携带的所有消息，如下所示的是输出结果：
