# [MAF工作流框架揭秘-03]形式多样的各种Executor类型

当我们在利用`WorkflowBuilder`构建Workflow的时候，不论是指定的初始节点，还是通过添加边的形式引入其他节点，所有的节点都是一个`ExecutorBinding`，而非`Executor`。但是`ExecutorBinding`自身并不执行具体的功能操作，它总是利用绑定的工厂函数创建的`Executor`来做事。我们可以通过继承`Executor`这个抽象类，利用注册的路由处理器来完成所需的业务功能。MAF自身定义了一系列预定义的`Executor`类型，可以直接拿来为我所用。为了能够灵活地使用这些预定义的`Executor`类型，我们有必要整体了解一下`Executor`相关的类型定义体系。

## 1. 派生自Executor的基类

由于`Executor`总是根据预定义的`ExecutorProtocol`协议进行消息路由，所以具体的`Executor`只需要通过重写的`ConfigureProtocol`方法完成针对`ExecutorProtocol`的配置就可以了。针对`ExecutorProtocol`的配置，除了作为核心的路由注册之外，还包括针对输出消息类型（`Send`和`Yields`）的声明。MAF通过定义的一些抽象类，它们分担了一些通用协议的配置功能，进而简化了我们在实现具体的`Executor`时的工作量，同时也对一些规则提供了硬性的约束。

### 1.1 `Executor<TInput>`

很明显，`Executor<TInput>`利用泛型参数`TInput`来声明这个`Executor`的输入消息类型。输入消息类型固定下来，作为路由的处理函数的签名自然也就是固定下来，对应着如下所示的抽象方法`HandleAsync`。

```csharp
public abstract class Executor<TInput> : Executor, IMessageHandler<TInput>
{
	protected Executor(
        string id, 
        ExecutorOptions? options = null,
         bool declareCrossRunShareable = false)
		: base(id, options, declareCrossRunShareable)
	{
	}

	protected override ProtocolBuilder ConfigureProtocol(ProtocolBuilder protocolBuilder)
	{
		Func<TInput, IWorkflowContext, CancellationToken, ValueTask> handlerDelegate = HandleAsync;
		return protocolBuilder
            .ConfigureRoutes(routeBuilder=>routeBuilder.AddHandler(handlerDelegate))
            .AddMethodAttributeTypes(handlerDelegate.Method)
            .AddClassAttributeTypes(GetType());
	}

	public abstract ValueTask HandleAsync(
        TInput message, 
        IWorkflowContext context, 
        CancellationToken cancellationToken = default);
}
```

`Executor<TInput>`利用重写的`ConfigureProtocol`方法完整了针对`HandleAsync`的路由注册。于此同时，它还针对指定的路由处理方法和当前类型调用了`ProtocolBuilder`的`AddMethodAttributeTypes`和`AddClassAttributeTypes`方法，所以我们可以利用标注在方法和类上的`SendsMessageAttribute`和`YieldsOutputAttribute`来声明输出类型。

`Executor<TInput>`实现的`IMessageHandler<TMessage, TResult>`接口定义如下，可以看出这是一个已经被标注为废弃的接口，并且提示推荐的编程方式是利用`MessageHandlerAttribute`采用Source Generation的方式自行实现此接口，而不是自行实现它。

```csharp
[Obsolete("Use [MessageHandler] attribute on methods in a partial class deriving from Executor. This interface will be removed in a future version.")]
public interface IMessageHandler<TMessage, TResult>
{
	ValueTask<TResult> HandleAsync(
        TMessage message, 
        IWorkflowContext context, CancellationToken cancellationToken = default);
}
```

### 1.2 `Executor<TInput, TOutput>`

`Executor<TInput, TOutput>`同时限制了输入和输出消息的类型。相较于`Executor<TInput>`，除了作为路由处理方法的`HandleAsync`方法的返回类型从`ValueTask`变成`ValueTask<TOutput>`外，其他的完全一样。

```csharp
public abstract class Executor<TInput, TOutput> : Executor, IMessageHandler<TInput, TOutput>
{
	protected Executor(
        string id, 
        ExecutorOptions? options = null, 
        bool declareCrossRunShareable = false)
		: base(id, options ?? ExecutorOptions.Default, declareCrossRunShareable)
	{
	}

	protected override ProtocolBuilder ConfigureProtocol(ProtocolBuilder protocolBuilder)
	{
		Func<TInput, IWorkflowContext, CancellationToken, ValueTask> handlerDelegate = HandleAsync;
		return protocolBuilder
            .ConfigureRoutes(routeBuilder=>routeBuilder.AddHandler(handlerDelegate))
            .AddMethodAttributeTypes(handlerDelegate.Method)
            .AddClassAttributeTypes(GetType());
	}

	public abstract ValueTask<TOutput> HandleAsync(
        TInput message, 
        IWorkflowContext context, 
        CancellationToken cancellationToken = default);
}
```

### 1.3 `StatefulExecutor<TState>`

`StatefulExecutor<TState>`赋予了同一个`Executor`可以在多次调用中被复用，并能够维护其状态的能力。泛型参数`TState`代表维护状态的类型。对于MAF的Workflow来说，状态的读写功能是通过`IWorkflowContext`对象如下这些重载的`ReadStateAsync`和`QueueStateUpdateAsync`方法来完成的。当我们在调用`QueueStateUpdateAsync`方法来更新状态的时候，除了指定存储状态的Key之外，还可以指定一个`scopeName`参数，可以将它视为状态的**命名空间**。如果没有指定，方法使用一个默认的`scopeName`。在调用`ReadStateAsync`方法来读取状态的时候，需要指定对应的`scopeName`才能得到正确的状态值。

```csharp
public interface IWorkflowContext
{
	ValueTask<T?> ReadStateAsync<T>(
		string key, 
		string? scopeName = null, 
		CancellationToken cancellationToken = default);
    ValueTask<T> ReadOrInitStateAsync<T>(
		string key, 
		Func<T> initialStateFactory, 
		string? scopeName = null, 
        CancellationToken cancellationToken = default);
    ValueTask<T?> ReadStateAsync<T>(
		string key, 
		CancellationToken cancellationToken);
    ValueTask<T> ReadOrInitStateAsync<T>(
		string key, 
		Func<T> initialStateFactory, 
		CancellationToken cancellationToken) ;
    ValueTask<HashSet<string>> ReadStateKeysAsync(
		string? scopeName = null, 
		CancellationToken cancellationToken = default);

    ValueTask QueueStateUpdateAsync<T>(
		string key, 
		T? value, 
		string? scopeName = null, 
		CancellationToken cancellationToken = default);
    ValueTask QueueStateUpdateAsync<T>(
		string key, 
		T? value, 
		CancellationToken cancellationToken) ;
    ValueTask QueueClearScopeAsync(
		string? scopeName = null, 
		CancellationToken cancellationToken = default);
    ValueTask QueueClearScopeAsync(CancellationToken cancellationToken) ;
}
```

`StatefulExecutor<TState>`具有自己对应的配置选项类型`StatefulExecutorOptions`，它在基类`ExecutorOptions`的基础上增加了`StateKey`和`ScopeName`两个属性，分别用来指定存储状态采用的`Key`和`ScopeName`。

```csharp
public class StatefulExecutorOptions : ExecutorOptions
{
	public string? StateKey { get; set; }
	public string? ScopeName { get; set; }
}
```

我们在调用构造函数创建`StatefulExecutor<TState>`对象的时候，需要指定一个`Func<TState>`类型的参数来提供状态的初始值,`ResetAsync`方法利用这个委托对象重置状态。我们也可以利用提供的`StatefulExecutorOptions`来指定状态的`Key`和`ScopeName`。如果没有对这两个属性进行显式指定，`ScopeName`默认为`null`，`StateKey`默认为`{类型名称}.State`(对应`StateKey`属性)。

```csharp
public abstract class StatefulExecutor<TState> : Executor
{
    private TState? _stateCache;
    protected StatefulExecutor(
		string id,        
		Func<TState> initialStateFactory,        
		StatefulExecutorOptions? options = null,
        bool declareCrossRunShareable = false);

    protected new StatefulExecutorOptions Options { get; }
    protected string StateKey => this.Options.StateKey ?? this.DefaultStateKey;

    protected async ValueTask<TState> ReadStateAsync(
		IWorkflowContext context, 
		bool skipCache = false, 
        CancellationToken cancellationToken = default);
    protected ValueTask QueueStateUpdateAsync(
		TState state, 
		IWorkflowContext context, 
        CancellationToken cancellationToken = default);   

    protected async ValueTask InvokeWithStateAsync(
        Func<TState, IWorkflowContext, CancellationToken, ValueTask<TState?>> invocation,
        IWorkflowContext context,
        bool skipCache = false,
        CancellationToken cancellationToken = default);

    protected virtual ValueTask ResetAsync();
}
```

`StatefulExecutor<TState>`利用字段`_stateCache`来缓存状态，以减少对状态存储的频繁访问。对于用于读取状态的`ReadStateAsync`方法来说，如果`skipCache`参数为`true`，它会直接调用`IWorkflowContext`的`ReadStateAsync`方法来读取状态；否则会优先从`_stateCache`字段中读取状态。如果缓存中没有，则调用`IWorkflowContext`的`ReadOrInitStateAsync`方法来读取状态并将其缓存到`_stateCache`字段中。`QueueStateUpdateAsync`方法在调用`IWorkflowContext`的`QueueStateUpdateAsync`方法来更新状态之前，如果`IWorkflowContext`的`ConcurrentRunsEnabled`属性为`false`，则会将新的状态值更新到`_stateCache`字段中。

核心方法`InvokeWithStateAsync`接受一个`Func<TState, IWorkflowContext, CancellationToken, ValueTask<TState?>>`类型的委托作为参数，这个委托表示带状态的调用逻辑。这个方法的指定逻辑如下：

- 如果`skipCache`参数为`true`或者`IWorkflowContext`的`ConcurrentRunsEnabled`属性为`true`，则直接调用`IWorkflowContext`的`InvokeWithStateAsync`方法来执行带状态的调用逻辑。
- 否则:
  - 如果`_stateCache`字段中没有状态值，则调用`IWorkflowContext`的`ReadOrInitStateAsync`方法来读取状态并将其缓存到`_stateCache`字段中；
  - 执行指定的`invocation`委托，并得到新的状态值；
  - 调用`IWorkflowContext`的`QueueStateUpdateAsync`方法来更新状态；
  - 将新的状态值更新到`_stateCache`字段中。

#### 1.3.1 `StatefulExecutor<TState, TInput>`

`StatefulExecutor<TState, TInput>`在基类`StatefulExecutor<TState>`的基础上增加了输入消息类型`TInput`的限制。构造函数除了指定用来初始化状态的委托和`StatefulExecutorOptions`之外，还可以指定额外用于声明`Send`和`Yield`消息类型的`sentMessageTypes`和`outputTypes`参数。

```csharp
public abstract class StatefulExecutor<TState, TInput>(
		string id, 
		Func<TState> initialStateFactory, 
		StatefulExecutorOptions? options = null, 
		IEnumerable<Type>? sentMessageTypes = null, 
		IEnumerable<Type>? outputTypes = null, 
		bool declareCrossRunShareable = false) 
	: StatefulExecutor<TState>(id, initialStateFactory, options, declareCrossRunShareable), 
	  IMessageHandler<TInput>
{
	protected override ProtocolBuilder ConfigureProtocol(ProtocolBuilder protocolBuilder)
	{
		Func<TInput, IWorkflowContext, CancellationToken, ValueTask> handlerDelegate = HandleAsync;
		return protocolBuilder
		    .ConfigureRoutes(routeBuilder=>routeBuilder.AddHandler(handlerDelegate))
			.AddMethodAttributeTypes(handlerDelegate.Method)
			.AddClassAttributeTypes(GetType())
			.SendsMessageTypes(sentMessageTypes ?? Array.Empty<Type>())
			.YieldsOutputTypes(outputTypes ?? Array.Empty<Type>());
	}

	public abstract ValueTask HandleAsync(
		TInput message, 
		IWorkflowContext context, 
		CancellationToken cancellationToken = default);
}
```

与`Executor<TInput>`类似，`StatefulExecutor<TState, TInput>`定义了抽象方法`HandleAsync`作为路由处理方法，并且在`ConfigureProtocol`方法中完成了针对`HandleAsync`的路由注册和输出类型的声明。

#### 1.3.2 `StatefulExecutor<TState, TInput, TOutput>`

`StatefulExecutor<TState, TInput, TOutput>`利用泛型参数类型同时限制了输入和输出消息类型。相较于`StatefulExecutor<TState, TInput>`，`StatefulExecutor<TState, TInput, TOutput>`除了将`HandleAsync`方法的返回类型改为`ValueTask<TOutput>`之外，其他方面别无二致。

```csharp
public abstract class StatefulExecutor<TState, TInput, TOutput>(
		string id, 
		Func<TState> initialStateFactory, 
		StatefulExecutorOptions? options = null, 
		IEnumerable<Type>? sentMessageTypes = null, 
		IEnumerable<Type>? outputTypes = null, 
		bool declareCrossRunShareable = false) 
	: StatefulExecutor<TState>(id, initialStateFactory, options, declareCrossRunShareable), 
	IMessageHandler<TInput, TOutput> where TOutput : notnull
{
	protected override ProtocolBuilder ConfigureProtocol(ProtocolBuilder protocolBuilder)
	{
		Func<TInput, IWorkflowContext, CancellationToken, ValueTask> handlerDelegate = HandleAsync;
		return protocolBuilder
		    .ConfigureRoutes(routeBuilder=>routeBuilder.AddHandler(handlerDelegate))
			.AddMethodAttributeTypes(handlerDelegate.Method)
			.AddClassAttributeTypes(GetType())
			.SendsMessageTypes(sentMessageTypes ?? Array.Empty<Type>())
			.YieldsOutputTypes(outputTypes ?? Array.Empty<Type>());
	}

	public abstract ValueTask<TOutput> HandleAsync(
		TInput message, 
		IWorkflowContext context, 
		CancellationToken cancellationToken = default);
}
```

#### 1.3.3. ChatProtocolExecutor

对于一个采用基于对话的`ChatClientAgent`来说，它是有状态的，并且状态就是作为对话历史的`ChatMessage`列表。将Workflow的某个节点绑定为`ChatClientAgent`是很常见的场景，这也要求对应的`Executor`将`ChatMessage`列表作为状态来维护。这样的`Executor`可以将`ChatProtocolExecutor`作为基类,如下所示的是它对应的配置选项类型`ChatProtocolExecutorOptions`的定义。

```csharp
public class ChatProtocolExecutorOptions
{
    public ChatRole? StringMessageChatRole { get; set; }
    public bool AutoSendTurnToken { get; set; } = true;
}
```

配置选项`StringMessageChatRole`很好理解，就是为指定的消息文本创建对应`ChatMessage`对象时所使用的`ChatRole`。至于另一个配置选项`AutoSendTurnToken`，要理解它就得先了解一下`TurnToken`的概念。我们知道对于一个`ChatClientAgent`来说，它的输入是一个`ChatMessage`列表，我们可以采用如下两种形式的调用方式：

- 指定一个完整的`ChatMessage`列表作为输入，立即调用节点绑定的`ChatClientAgent`；
- 分多次向节点提供`ChatMessage`，后者将其缓存起来，直到某个时刻提供了一个特殊的消息（`TurnToken`）来触发节点绑定的`ChatClientAgent`的调用。

`ChatProtocolExecutor`采用的就是第二种调用方式，`AutoSendTurnToken`配置选项决定`ChatProtocolExecutor`在接收到这个作为**发令枪**的`TurnToken`后，是否自动通过调用`IWorkflowContext`对象的`SendMessageAsync`方法转发出去。如下面的代码所示，当我们通过继承`ChatProtocolExecutor`来实现一个与指定`ChatClientAgent`绑定的`Executor`时，我们只需要重写`TakeTurnAsync`方法将累积的`ChatMessage`列表交给`ChatClientAgent`来处理就可以了。

```csharp
public abstract class ChatProtocolExecutor : StatefulExecutor<List<ChatMessage>>
{   
	protected bool SupportsStringMessage { get; }
    protected ChatRole? StringMessageChatRole { get; }
    protected bool AutoSendTurnToken { get; }

    protected ChatProtocolExecutor(
		string id, 
		ChatProtocolExecutorOptions? options = null, 
		bool declareCrossRunShareable = false);    

    protected override ProtocolBuilder ConfigureProtocol(ProtocolBuilder protocolBuilder)
    {
        return protocolBuilder
			.ConfigureRoutes(ConfigureRoutes)
            .SendsMessage<List<ChatMessage>>()
            .SendsMessage<TurnToken>();

        void ConfigureRoutes(RouteBuilder routeBuilder)
        {
            if (SupportsStringMessage)
            {
                routeBuilder = routeBuilder.AddHandler<string>(
                    (message, context) => this.AddMessageAsync(new(this.StringMessageChatRole.Value, message), context));
            }

            routeBuilder.AddHandler<ChatMessage>(AddMessageAsync)
                        .AddHandler<IEnumerable<ChatMessage>>(AddMessagesAsync)
                        .AddHandler<ChatMessage[]>(AddMessagesAsync)
                        .AddHandler<TurnToken>(TakeTurnAsync);
        }
    }
    
    protected ValueTask AddMessageAsync(ChatMessage message, IWorkflowContext context, CancellationToken cancellationToken = default);
    protected ValueTask AddMessagesAsync(IEnumerable<ChatMessage> messages, IWorkflowContext context, CancellationToken cancellationToken = default);
    public ValueTask TakeTurnAsync(TurnToken token, IWorkflowContext context, CancellationToken cancellationToken = default);

    protected abstract ValueTask TakeTurnAsync(
		List<ChatMessage> messages, 
		IWorkflowContext context, bool? emitEvents, 
		CancellationToken cancellationToken = default);
}
```

正如我们在前面介绍`TurnToken`时说的一样，`ChatProtocolExecutor`的输入有两类：一类是`ChatMessage`或`ChatMessage`的集合，另一类是`TurnToken`。`ChatProtocolExecutor`利用重写的`ConfigureProtocol`方法来完成针对这两类输入的路由注册。为了支持单条`ChatMessage`和`ChatMessage`集合与数组，它针对这三种类型注册了三个不同的路由处理器。如果支持字符串消息输入的话，还会针对字符串消息注册一个路由处理器。这些处理器会将接收到的消息以`List<ChatMessage>`的形式存储在自己维护的状态中。

对于`TurnToken`类型的输入，`ChatProtocolExecutor`注册的路由处理器是`TakeTurnAsync`方法，这个方法的实现逻辑如下：

- 调用抽象方法`TakeTurnAsync`来真正将累积的`ChatMessage`列表发送出去；
- 如果配置选项`AutoSendTurnToken`为`true`，则创建一个新的`TurnToken`对象并通过调用`IWorkflowContext`的`SendMessageAsync`方法将其发送出去。

## 2. 封装Delegator的Executor类型

在介绍了上述几个派生自`Executor`的抽象基类之后，我们来介绍一些具体的可以直接使用的`Executor`类型。对于一个具体的`Executor`来说，它必须提供针对输入消息的处理函数，并被注册为路由处理器，所以我们也自然地会想到利用一个委托对象来表示这个处理函数。两个泛型的`FunctionExecutor`就是采用了这样的设计思路。

### 2.1 `FunctionExecutor<TInput>`

`FunctionExecutor<TInput>`是`Executor<TInput>`的子类，它利用构造函数提供的`Func<TInput, IWorkflowContext, CancellationToken, ValueTask>`类型的委托作为路由处理函数。除了这个核心的委托之外，构造函数还接受一些可选的参数来指定`Executor`的配置选项，以及声明Send和Yield消息类型的`sentMessageTypes`和`outputTypes`参数。

```csharp
public class FunctionExecutor<TInput>(
	string id, 
	Func<TInput, IWorkflowContext, CancellationToken, ValueTask> handlerAsync, 
	ExecutorOptions? options = null, 
	IEnumerable<Type>? sentMessageTypes = null, 
	IEnumerable<Type>? outputTypes = null, 
	bool declareCrossRunShareable = false) : Executor<TInput>(id, options, declareCrossRunShareable)
{
	protected override ProtocolBuilder ConfigureProtocol(ProtocolBuilder protocolBuilder)
	{
		return base.ConfigureProtocol(protocolBuilder)
		    .AddDelegateAttributeTypes(handlerAsync)
			.SendsMessageTypes(sentMessageTypes ?? Array.Empty<Type>())
			.YieldsOutputTypes(outputTypes ?? Array.Empty<Type>());
	}

	public override ValueTask HandleAsync(TInput message, IWorkflowContext context, CancellationToken cancellationToken);

	public FunctionExecutor(
		string id, 
		Action<TInput, IWorkflowContext, CancellationToken> handlerSync, 
		ExecutorOptions? options = null, 
		IEnumerable<Type>? sentMessageTypes = null, 
		IEnumerable<Type>? outputTypes = null, 
		bool declareCrossRunShareable = false);
}
```

`FunctionExecutor<TInput>`是`Executor<TInput>`还提供了另一个重载的构造函数，它接受一个`Action<TInput, IWorkflowContext, CancellationToken>`类型的同步委托对象。这个委托最终还是会被转换为`Func<TInput, IWorkflowContext, CancellationToken, ValueTask>`类型。它重写了`HandleAsync`方法，在方法中调用提供的委托对象来处理输入消息。由于构造函数中还提供了`sentMessageTypes`和`outputTypes`参数，所以还需要将两者的声明实现在重写的`ConfigureProtocol`方法中。

在如下所示的演示程序中，我们针对`UpperCaseAsync`方法创建了一个`FunctionExecutor<string>`对象，并将其作为Workflow的初始节点来构建Workflow。我们通过执行这个Workflow来将输入字符串转换为大写字符串。由于`UpperCaseAsync`的返回类型为`ValueTask`， 所以我们在创建`FunctionExecutor<string>`对象的时候还需要利用`outputTypes`参数输出类型声明为字符串。

```csharp
using Microsoft.Agents.AI.Workflows;
using System.Diagnostics;

var executor = new FunctionExecutor<string>(    
    id:"UpperCase",
    handlerAsync: UpperCaseAsync,
    outputTypes: [typeof(string)]);
var workflow = new WorkflowBuilder(executor)
    .WithOutputFrom(executor)
    .Build();

var run = await InProcessExecution.Default.RunAsync(workflow, "hello world");
var output = run.NewEvents.OfType<WorkflowOutputEvent>().Single().Data!;    
Debug.Assert(output.Equals("HELLO WORLD"));

static ValueTask UpperCaseAsync(string input, IWorkflowContext context, CancellationToken cancellationToken)
	=> context.YieldOutputAsync(input.ToUpper(), cancellationToken);
```

### 2.2 `FunctionExecutor<TInput, TOutput>`

`FunctionExecutor<TInput, TOutput>`派生于`Executor<TInput, TOutput>`，它利用构造函数提供的`Func<TInput, IWorkflowContext, CancellationToken, ValueTask<TOutput>>`类型的委托作为路由处理函数。与`FunctionExecutor<TInput>`类似，构造函数还接受一些可选的参数来指定Executor的配置选项，以及声明Send和Yield消息类型的`sentMessageTypes`和`outputTypes`参数。

```csharp
public class FunctionExecutor<TInput, TOutput>(string id,
        Func<TInput, IWorkflowContext, CancellationToken, ValueTask<TOutput>> handlerAsync,
        ExecutorOptions? options = null,
        IEnumerable<Type>? sentMessageTypes = null,
        IEnumerable<Type>? outputTypes = null,
        bool declareCrossRunShareable = false) 
	: Executor<TInput, TOutput>(id, options, declareCrossRunShareable);

    protected override ProtocolBuilder ConfigureProtocol(ProtocolBuilder protocolBuilder) 
	    => base.ConfigureProtocol(protocolBuilder)
            .AddDelegateAttributeTypes(handlerAsync)
            .SendsMessageTypes(sentMessageTypes ?? [])
            .YieldsOutputTypes(outputTypes ?? []);

    public override ValueTask<TOutput> HandleAsync(TInput message, IWorkflowContext context, CancellationToken cancellationToken);
    public FunctionExecutor(string id,
        Func<TInput, IWorkflowContext, CancellationToken, TOutput> handlerSync,
        ExecutorOptions? options = null,
        IEnumerable<Type>? sentMessageTypes = null,
        IEnumerable<Type>? outputTypes = null,
        bool declareCrossRunShareable = false) ;
}
```

`FunctionExecutor<TInput, TOutput>`同样定义了另一个重载的构造函数，它接受一个`Func<TInput, IWorkflowContext, CancellationToken, TOutput>`类型的同步委托对象。这个委托最终还是会被转换为`Func<TInput, IWorkflowContext, CancellationToken, ValueTask<TOutput>>`类型。它重写了`HandleAsync`方法，在方法中调用提供的委托对象来处理输入消息并返回结果。由于构造函数中还提供了`sentMessageTypes`和`outputTypes`参数，所以还需要将两者的声明实现在重写的`ConfigureProtocol`方法中。

上面演示的用来将输入字符串转换为大写字符串的Workflow同样也可以利用`FunctionExecutor<string, string>`来实现，而且更简单。具体实现如下所示：

```csharp
using Microsoft.Agents.AI.Workflows;
using System.Diagnostics;

var executor = new FunctionExecutor<string, string>(
    id: "UpperCase",
    handlerSync: UpperCase);
var workflow = new WorkflowBuilder(executor)
    .WithOutputFrom(executor)
    .Build();

var run = await InProcessExecution.Default.RunAsync(workflow, "hello world");
var output = run.NewEvents.OfType<WorkflowOutputEvent>().Single().Data!;    
Debug.Assert(output.Equals("HELLO WORLD"));

static string UpperCase(string input, IWorkflowContext context, CancellationToken cancellationToken)
=> input.ToUpper();
```

## 3. `AggregatingExecutor<TInput, TAggregate>`

`AggregatingExecutor<TInput, TAggregate>`对输入的多个输入进行聚合处理。它利用构造函数提供的`Func<TAggregate?, TInput, TAggregate?>`类型的委托作为聚合函数。如下面的代码所示，它是`Executor<TInput, TAggregate?>`的派生类。`AggregatingExecutor<TInput, TAggregate>`重写了HandleAsync方法，并在其中调用`IWorkflowContext`的`InvokeWithStateAsync`方法来执行实施聚合的`InvokeAggregatorAsync`方法。`AggregatingExecutor<TInput, TAggregate>`除了返回聚合结果之外，还将聚合结果存储在状态中，

```csharp
public class AggregatingExecutor<TInput, TAggregate>(
		string id, 
		Func<TAggregate?, TInput, TAggregate?> aggregator, 
		ExecutorOptions? options = null, 
		bool declareCrossRunShareable = false) 
	: Executor<TInput, TAggregate?>(id, options, declareCrossRunShareable)
{
	public override async ValueTask<TAggregate?> HandleAsync(
		TInput message, 
		IWorkflowContext context, 
		CancellationToken cancellationToken)
	{
		TAggregate runningAggregate = default;
		await context.InvokeWithStateAsync<PortableValue>(
				InvokeAggregatorAsync, 
				"Aggregate", 
				null, 
				cancellationToken)
			.ConfigureAwait(continueOnCapturedContext: false);
		return runningAggregate;

		ValueTask<PortableValue?> InvokeAggregatorAsync(
			PortableValue? maybeState, 
			IWorkflowContext workflowContext, 
			CancellationToken cancellationToken2)
		{
			if (maybeState == null || !maybeState.Is<TAggregate>(out runningAggregate))
			{
				runningAggregate = default;
			}
			runningAggregate = aggregator(runningAggregate, message);
			if (runningAggregate == null)
			{
				return new ValueTask<PortableValue>((PortableValue)null);
			}
			return new ValueTask<PortableValue>(new PortableValue(runningAggregate));
		}
	}
}
```

在如下这个演示程序中，我们创建了一个通过变量`generator`表示的`AggregatingExecutor<int, int>`对象来对输入的整数进行累加。我们构建的Workflow由两个节点组成，分别是`generator`和另一个随机生成整数的`FunctionExecutor<int>`对象，对应的变量为`randomGenerator`。我们在这两个节点之间添加了两条边，从`generator`到`randomGenerator`的条件边会在生成的随机数大于0的时候被触发，而从`randomGenerator`到`generator`的边构建了累加循环。也就是说整个累加循环会在生成的随机数小于等于0的时候终止。最终我们可以得到一个大于0的随机数的累加和。

```csharp
using Microsoft.Agents.AI.Workflows;

var random = new Random();

var generator = new FunctionExecutor<int,int>(
    id: "Generator",
    handlerSync: (_, _, _) => { 
        var num = random.Next(0, 6);
        Console.WriteLine($"Generated number: {num}");
        return num;
    });
var accumulator = new AggregatingExecutor<int, int>(
   id: "Accumulator",
   aggregator: (sum,num)=>sum + num);

var workflow = new WorkflowBuilder(generator)
    .AddEdge<int>(source: generator, target: accumulator, condition: input => input > 0)
    .AddEdge(source: accumulator, target: generator)
    .WithOutputFrom(accumulator)
    .Build();

var run = await InProcessExecution.Default.RunAsync(workflow, -1);
var output = run.NewEvents.OfType<WorkflowOutputEvent>().LastOrDefault()?.Data ?? 0;
Console.WriteLine("Sum: " + output);
```

Generated number: 5

## 4.ChatForwardingExecutor

`ChatForwardingExecutor`和`ChatProtocolExecutor`具有完全相同的输入，但是`ChatForwardingExecutor`仅仅是一个简单的转发器，它会将接收到的输入消息直接转发出去，而不会进行任何处理。`ChatForwardingExecutor`同样也支持字符串消息输入，并且它也会将字符串消息转换为`ChatMessage`对象进行转发，所以它的配置选项`ChatForwardingExecutorOptions`中同样也包含一个`StringMessageChatRole`属性来指定被转换的`ChatMessage`对象的`ChatRole`。但是没有`ChatProtocolExecutor`那样的`AutoSendTurnToken`配置选项。

```csharp
public class ChatForwardingExecutorOptions
{
	public ChatRole? StringMessageChatRole { get; set; }
}
```

`ChatForwardingExecutor`的实现也非常简单。如下面的代码所示，它重写了`ConfigureProtocol`方法注册了用于转发单条`ChatMessage`、`ChatMessage`集合、`ChatMessage`数组和`TurnToken`的路由处理器。如果配置选项`ChatForwardingExecutorOptions`中的`StringMessageChatRole`属性有值的话，还会注册一个用于转发字符串消息的路由处理器。这些处理器直接调用`IWorkflowContext`的`SendMessageAsync`方法将接收到的消息转发出去。除此之外，它还通过调用`ProtocolBuilder`的`SendsMessage`方法将`ChatMessage`、`ChatMessage`集合、`ChatMessage`数组和`TurnToken`声明为输出消息类型。

```csharp
public sealed class ChatForwardingExecutor(string id, ChatForwardingExecutorOptions? options = null) 
: Executor(id, declareCrossRunShareable: true), IResettableExecutor
{
    private readonly ChatRole? _stringMessageChatRole = options?.StringMessageChatRole;

    protected override ProtocolBuilder ConfigureProtocol(ProtocolBuilder protocolBuilder)
    {
        return protocolBuilder.ConfigureRoutes(ConfigureRoutes)
                              .SendsMessage<ChatMessage>()
                              .SendsMessage<List<ChatMessage>>()
                              .SendsMessage<ChatMessage[]>()
                              .SendsMessage<TurnToken>();

        void ConfigureRoutes(RouteBuilder routeBuilder)
        {
            if (this._stringMessageChatRole.HasValue)
            {
                routeBuilder = routeBuilder.AddHandler<string>(
                    (message, context) => context.SendMessageAsync(new ChatMessage(this._stringMessageChatRole.Value, message)));
            }

            routeBuilder.AddHandler<ChatMessage>(ForwardMessageAsync)
                        .AddHandler<IEnumerable<ChatMessage>>(ForwardMessagesAsync)
                        .AddHandler<ChatMessage[]>(ForwardMessagesAsync)
                        .AddHandler<TurnToken>(ForwardTurnTokenAsync);
        }
    }

    private static ValueTask ForwardMessageAsync(
		ChatMessage message, 
		IWorkflowContext context, 
		CancellationToken cancellationToken)
        => context.SendMessageAsync(message, cancellationToken);
    private static ValueTask ForwardTurnTokenAsync(
		TurnToken message, 
		IWorkflowContext context, 
		CancellationToken cancellationToken)
        => context.SendMessageAsync(message, cancellationToken);
    private static ValueTask ForwardMessagesAsync(
		IEnumerable<ChatMessage> messages, 
		IWorkflowContext context, 
		CancellationToken cancellationToken)
			=> context.SendMessageAsync(messages is List<ChatMessage> messageList 
			? messageList 
			: messages.ToList(), cancellationToken);

    private static ValueTask ForwardMessagesAsync(
		ChatMessage[] messages, 
		IWorkflowContext context, 
		CancellationToken cancellationToken)
        => context.SendMessageAsync(messages, cancellationToken);

    public ValueTask ResetAsync() => default;
}
```

在如下的演示程序中，我们创建了一个`ChatForwardingExecutor`对象，并将其作为初始节点来构建Workflow。我们创建了另一个`FunctionExecutor<ChatMessage>`对象实现针对LLM的调用，并将其作为Workflow的另一个节点。我们在这两个节点之间添加了一条边来连接它们。由于`ChatForwardingExecutor`会将接收到的输入消息直接转发出去，所以当我们执行这个Workflow并提供一个字符串输入的时候，这个字符串会被`ChatForwardingExecutor`转换为`ChatMessage`对象并转发给`FunctionExecutor<ChatMessage>`对象来处理。`FunctionExecutor<ChatMessage>`对象在处理完输入消息后会将LLM的响应作为输出返回，我们可以通过提取最后一个`WorkflowOutputEvent`事件来获取这个响应。

```csharp
using Microsoft.Agents.AI.Workflows;
using Microsoft.Extensions.AI;
using OpenAI;
using System.ClientModel;

dotenv.net.DotEnv.Load();

var endpoint = Environment.GetEnvironmentVariable("OPENAI_URL")!;

var apiKey = Environment.GetEnvironmentVariable("API_KEY")!; 

var chatClient = new OpenAIClient(
	    new ApiKeyCredential(apiKey), 
		new OpenAIClientOptions { Endpoint = new Uri(endpoint) })
    .GetChatClient(model)
    .AsIChatClient();

var forwarder = new ChatForwardingExecutor(
	"Forwarder", 
	new ChatForwardingExecutorOptions {  StringMessageChatRole = ChatRole.User});
var llm = new FunctionExecutor<ChatMessage>(
    id:"LLM",
    outputTypes: [typeof(ChatResponse)],
    handlerAsync: async (message, context, cancellationToken) =>
    {
      var response = await chatClient.GetResponseAsync(message,cancellationToken:cancellationToken);
      await context.YieldOutputAsync(response);
    });

var workflow = new WorkflowBuilder(forwarder)
    .AddEdge(forwarder, llm)
    .WithOutputFrom(llm)
    .Build();

var run = await InProcessExecution.Default.RunAsync(workflow, "凌烟阁二十四功臣前5位分别是谁？");
var output = run.NewEvents.OfType<WorkflowOutputEvent>().LastOrDefault()?.Data!;
Console.WriteLine(output);
```
