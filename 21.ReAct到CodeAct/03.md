# [从ReAct到CodeAct-03]直接使用本地Python解释器执行代码

在[从ReAct到CodeAct-02:基于本地Sandbox的代码解释器](https://blog.csdn.net/JaydenAI/article/details/161913096)中，我们演示了如何使用Hyperlight提供的Sandbox来执行LLM生成的Python代码。虽然这种方式可以为生成的代码提供了一个安全的执行环境，但它也带来了一些限制，例如无法使用额外的Python库、无法访问宿主机的文件系统等。整个解决方案由`HyperlightCodeActProvider`这个`AIContextProvider`来实现，其实MAF中还还有另一个与之类似的`LocalCodeActProvider`，它的实现原理与`HyperlightCodeActProvider`类似，但它不依赖于Hyperlight Sandbox，而是直接使用本地Python解释器来执行LLM生成的代码。

## 1. 重写库存检验与补货预警Agent

在[从ReAct到CodeAct-02:基于本地Sandbox的代码解释器](https://blog.csdn.net/JaydenAI/article/details/161913096)中，我们演示了一个库存检验与补货预警的Agent，它使用了`HyperlightCodeActProvider`来执行LLM生成的Python代码。现在我们将这个Agent重写为使用`LocalCodeActProvider`来执行代码。下面是完整的示例代码：

```csharp
using System.ClientModel;
using System.ComponentModel;
using System.Text.Json;
using Azure.AI.Projects;
using DotNetEnv;
using Microsoft.Agents.AI;
using Microsoft.Agents.AI.LocalCodeAct;
using Microsoft.Extensions.AI;
using OpenAI;

Env.Load();

var model = Environment.GetEnvironmentVariable("MODEL")!;
var apiKey = Environment.GetEnvironmentVariable("OPENAI_API_KEY")!;
var endpoint = Environment.GetEnvironmentVariable("OPENAI_BASE_URL")!;
var pythonExecutable = Environment.GetEnvironmentVariable("PYTHON_EXECUTABLE");

var options = new LocalCodeActProviderOptions
{
    Tools = [
        AIFunctionFactory.Create(LookupProductId, name: "LookupProductId"),
        AIFunctionFactory.Create(GetInventory, name: "GetInventory"),
        AIFunctionFactory.Create(TriggerRestockAlarm, name: "TriggerRestockAlarm")]
};
var provider = new LocalCodeActProvider(pythonExecutable, options);
var agent = new OpenAIClient(
        credential: new ApiKeyCredential(key: apiKey),
        options: new OpenAIClientOptions { Endpoint = new Uri(endpoint) })
    .GetChatClient(model: model)
    .AsIChatClient()
    .AsAIAgent(options: new ChatClientAgentOptions
    {
        AIContextProviders = [provider],
    });

var prompt = "帮我检查‘PC’的库存。如果存储<10，就立刻触发补货预警，并告诉我结果。";

var response = await agent.RunAsync(prompt);
var index = 1;
foreach (var message in response.Messages)
{
    Console.WriteLine($"{new string('-', 20)} Message {index++} {new string('-', 20)}");
    PrintMessage(message);
}
Console.ReadLine();

}
```

如上面的代码片段所示，我们定义了如下三个工具函数：

- **LookupProductId**：根据商品名称查询商品ID；
- **GetInventory**：根据商品ID查询库存数量；
- **TriggerRestockAlarm**：触发补货警报。

我们针对Python解释器的路径创建了一个`LocalCodeActProvider`实例，在对应的`LocalCodeActProviderOptions`中，我们注册了上述三个工具函数。然后我们创建了一个`OpenAIClient`实例针对它创建了对应的`AIAgent`实例。在调用的`AsAIAgent`方法中，我们将`LocalCodeActProvider`作为`AIContextProvider`进行了注册。我们最后调用`Agent`对象，并要求它：**帮我检查‘PC’的库存。如果存储<10，就立刻触发补货预警，并告诉我结果**。我们将整个过程涉及的消息都打印出来，针对消息的格式化输出由在[从ReAct到CodeAct-02:基于本地Sandbox的代码解释器](https://blog.csdn.net/JaydenAI/article/details/161913096)中提供的`PrintMessage`方法来实现。

## 2. 利用系统指令减少试错次数

为了减少LLM在生成代码时的试错次数，我们可以利用系统指令来指导LLM生成更符合要求的代码。比如根据最终生成的有效代码，我们可以总结出一些关键的规则，并将这些规则作为系统指令传递给LLM。下面是一个示例：

```csharp

        credential: new ApiKeyCredential(key: apiKey),

        options: new OpenAIClientOptions { Endpoint = new Uri(endpoint) })
    .GetChatClient(model: model)
    .AsIChatClient()
    .AsAIAgent(options: new ChatClientAgentOptions
    {
        ChatOptions = new ChatOptions
        {
            Instructions =
                """
                You are a helpful assistant. Prefer orchestrating your work in a single `execute_code` block.
                The sandbox exposes C# tools via `await call_tool(...)`. 
                
                CRITICAL RULES for your generated Python code:
                1. DO NOT use `import asyncio` or `asyncio.run()`.
                2. DO NOT define `async def main()`.
                3. Write top-level `await call_tool('ToolName', arg1=val1, ...)` directly in the script.
                
                Available Host Tools inside `call_tool`:
                - `LookupProductId(product_name: str) -> str`
                - `GetInventory(product_id: str) -> int`
                - `TriggerRestockAlarm(product_id: str) -> str`
                """
        },
        AIContextProviders = [provider],
    });
```

## 3. LocalCodeActProviderOptions

在正式介绍`LocalCodeActProvider`之前，我们不妨先来介绍它对应的配置选项类型`LocalCodeActProviderOptions`。

```csharp
public sealed class LocalCodeActProviderOptions
{
	public ProcessExecutionLimits? ExecutionLimits { get; set; }
	public IEnumerable<AIFunction>? Tools { get; set; }
	public IEnumerable<FileMount>? FileMounts { get; set; }
	public IReadOnlyDictionary<string, string>? Environment { get; set; }
	public string? WorkingDirectory { get; set; }
	public string? RunnerScriptPath { get; set; }
	public string? ValidatorScriptPath { get; set; }
	public bool ValidationDisabled { get; set; }
	public IEnumerable<string>? AllowedImports { get; set; }
	public IEnumerable<string>? BlockedImports { get; set; }
	public IEnumerable<string>? AllowedBuiltins { get; set; }
	public IEnumerable<string>? BlockedBuiltins { get; set; }
}
```

我们可以从如下四个问题来介绍一下定义在`LocalCodeActProviderOptions`中的各个具体的配置选项。

### 3.1  安全边界与沙盒行为控制

这组属性用来严格限制LLM生成的Python代码能做什么，防止AI写出恶意代码（如删除系统文件或占用过多资源）:

- **ExecutionLimits**：设置Python进程的资源限制。最常用的就是限制执行超时时间。这能防止大模型写出死循环导致服务器CPU被榨干;
- **AllowedImports/BlockedImports**：允许或禁止Python代码导入特定的模块。比如我们可以禁止导入`os`和`sys`等模块，防止LLM写出删除文件的代码;
- **AllowedBuiltins/BlockedBuiltins**：允许或禁止Python代码使用特定的内置函数。比如我们可以禁止使用`open`和`eval`等函数，防止LLM写出读取文件或执行任意代码的行为。

`ExecutionLimits`属性返回一个`ProcessExecutionLimits`对象对应用来定义Python进程的资源限制，该类型定义如下：

```csharp
public sealed class ProcessExecutionLimits
{
	public int TimeoutSeconds { get; set; } = 30;
	public int ValidationTimeoutSeconds { get; set; } = 10;
	public int MaxStdoutBytes { get; set; } = 10485760;
	public int MaxStderrBytes { get; set; } = 10485760;
	public int MaxResultBytes { get; set; } = 10485760;
	public int MaxCapturedFileBytes { get; set; } = 1048576;
	public int MaxTotalCapturedFileBytes { get; set; } = 10485760;
}
```

具体的资源限制属性说明如下：

- **TimeoutSeconds**：限制最大执行时间，单位为秒。超过这个时间，Python进程将被强制终止;
- **ValidationTimeoutSeconds**：限制Python代码验证的最大执行时间，单位为秒。超过这个时间，验证过程将被强制终止;
- **MaxStdoutBytes**：限制标准输出流的最大字节数。超过这个字节数，Python进程将被强制终止;
- **MaxStderrBytes**：限制标准错误流的最大字节数。超过这个字节数，Python进程将被强制终止;
- **MaxResultBytes**：限制返回结果的最大字节数。超过这个字节数，Python进程将被强制终止;
- **MaxCapturedFileBytes**：限制Python进程捕获的单个文件的最大字节数。超过这个字节数，Python进程将被强制终止;
- **MaxTotalCapturedFileBytes**：限制Python进程捕获的所有文件的总字节数。超过这个字节数，Python进程将被强制终止。

### 3.2  代码执行前的校验机制

在Python代码真正提交给解释器运行之前，框架支持对代码进行静态分析或安全审查:

- **ValidationDisabled**：允许禁用代码验证机制。如果设置为`true`，LLM生成的代码将直接提交给Python解释器执行，而不进行任何安全检查;
- **ValidatorScriptPath**：指定一个Python脚本路径，在代码执行前会调用这个脚本来验证生成的代码是否符合安全要求。这个脚本可以检查代码中是否包含禁止的导入或函数调用。

### 3.3  文件系统访问与挂载

LLM写代码时经常需要处理文件。这组属性决定了沙盒的生存环境:

- **FileMounts**：允许将宿主机的特定目录挂载到Python执行环境中。这样LLM生成的代码就可以访问这些目录下的文件;
- **WorkingDirectory**：指定Python代码执行时的工作目录。LLM生成的代码在执行时会以这个目录作为当前工作目录；
- **Environment**：允许设置Python执行环境的环境变量。LLM生成的代码在执行时可以访问这些环境变量。

定义文件/目录挂载的`FileMount`类型如下：

```csharp
public sealed class FileMount
{
	public string HostPath { get; }
	public string MountPath { get; }
	public FileMountMode Mode { get; }
	public long? WriteBytesLimit { get; }

	public FileMount(string hostPath, string mountPath, FileMountMode mode = FileMountMode.ReadWrite, long? writeBytesLimit = null);
}
public enum FileMountMode
{
	ReadOnly,
	ReadWrite
}
```

四个属性的含义如下：

- **HostPath**：宿主机上要挂载的目录路径;
- **MountPath**：挂载到Python执行环境中的路径;
- **Mode**：挂载模式，可以是只读（ReadOnly）或读写（ReadWrite）;
- **WriteBytesLimit**：限制LLM生成的代码在挂载目录中写入的字节数。这个限制可以防止LLM生成的代码写入过多数据，导致磁盘空间被占满。

### 3.4 核心功能与引导脚本

决定了沙盒内有哪些工具可用，以及底层是如何驱动这个沙盒的：

- **Tools**：注册给LLM使用的工具函数列表。每个工具函数都是一个`AIFunction`对象，LLM可以通过`call_tool`来调用这些工具函数;
- **RunnerScriptPath**：运行器脚本路径。这是整个LocalCodeAct的底层心脏。微软默认会内置一个Python脚本作为常驻网关，用来负责接收LLM的代码、注入`call_tool`函数、管理异步事件循环。如果你有极度高级的定制需求，可以通过这个属性替换掉微软默认的运行器脚本。

## 4. 执行代码的工具函数

`LocalCodeActProvider`提供的用于执行生成的Python代码的工具函数类型为`LocalExecuteCodeFunction`，它继承自`AIFunction`，其定义如下：

```csharp
public sealed class LocalExecuteCodeFunction : AIFunction
{    
	private readonly CodeExecutor _executor;

	private const string ExecuteCodeName = "execute_code";
	private readonly AIFunction _inner;
	public override string Name => _inner.Name;
	public override string Description => _inner.Description;
	public override JsonElement JsonSchema => _inner.JsonSchema;

	public LocalExecuteCodeFunction(string pythonExecutablePath, LocalCodeActProviderOptions? options = null);

	protected override ValueTask<object?> InvokeCoreAsync(AIFunctionArguments arguments, CancellationToken cancellationToken)
    =>_inner.InvokeAsync(arguments, cancellationToken);

    private async ValueTask<object?> ExecuteCodeAsync(
        [Description("Python source code to execute locally in the agent environment.")] string code, 
        CancellationToken cancellationToken)
	{
		return await _executor.ExecuteAsync(_snapshot, code, cancellationToken).ConfigureAwait(continueOnCapturedContext: false);
	}
}
```

可以看出`LocalExecuteCodeFunction`本质上对通过`_inner`字段表示的另一个`AIFunction`进行了封装。这个`AIFunction`通过`AIFunctionFactory`的`Create`方法针对私有方法`ExecuteCodeAsync`创建而来。`LocalExecuteCodeFunction`的名称、描述和`JsonSchema`都直接从`_inner`中获取。重写的`InvokeCoreAsync`方法会调用`_inner`的`InvokeAsync`方法来执行生成的Python代码。

从`ExecuteCodeAsync`的定义可以看出，它会调用`CodeExecutor`的`ExecuteAsync`方法来执行生成的Python代码。`CodeExecutor`是`LocalCodeActProvider`的核心组件，我们提供提供一段Python代码供其执行时，它在底层按以下4步完成安全、闭环的执行：

- **安检拦截**：代码运行前，先通过验证器进行静态扫描，如果发现黑名单里的危险代码（如`import os`），直接拦截报错；
- **环境拍照**：给允许读写的文件夹拍个**初始快照**，用来记录当前有哪些文件；
- **跨界桥接**：利用ProcessBridge真正启动底层的Python解释器。LLM生成的代码在这里运行，如果代码中写了`await call_tool(...)`，它会通过这架桥梁反向调用C#的宿主工具；
- **收尾打包**：执行完后，对比前后快照，抓取刚刚生成的新文件（如图片或报告），并收集 Python的打印输出（stdout/stderr）与返回值，统一包装成大模型能看懂的文本格式返回。

## 5. LocalCodeActProvider

`LocalCodeActProvider`的定义如下。我们在调用构造函数时需要传入本地Python解释器的路径，以及可选的`LocalCodeActProviderOptions`配置对象。供生成代码回调的工具函数列表和挂在的文件/目录除了通过`LocalCodeActProviderOptions`配置对象传入外，还可以通过相关的方法进行维护。

```csharp
public sealed class LocalCodeActProvider : AIContextProvider, IDisposable
{
	public LocalCodeActProvider(string pythonExecutablePath, LocalCodeActProviderOptions? options = null);

	public void AddTools(params AIFunction[] tools);
	public IReadOnlyList<AIFunction> GetTools();
	public void RemoveTools(params string[] names);
	public void ClearTools();

	public void AddFileMounts(params FileMount[] mounts);
	public IReadOnlyList<FileMount> GetFileMounts();
	public void RemoveFileMounts(params string[] mountPaths);
	public void ClearFileMounts();

	protected override ValueTask<AIContext> ProvideAIContextAsync(InvokingContext context, CancellationToken cancellationToken = default);
}
```

在重写的`ProvideAIContextAsync`方法中，它会创建一个`LocalExecuteCodeFunction`实例，并将其添加到返回`AIContext`的工具函数列表中。除此之外，`AIContext`的`Instructions`属性中还会包含一个默认的系统指令，指导LLM如何使用`execute_code`工具函数来执行生成的Python代码。具体的指令文本如下：

```markdown
You can execute Python code locally by calling the `execute_code` tool. Any tools listed in the tool's description are only accessible from within the executed code via `await call_tool(\"<name>\", **kwargs)` — they cannot be invoked directly. State does not persist between calls; pass any required values in the code you execute.
```
