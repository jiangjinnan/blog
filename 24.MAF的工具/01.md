# [MAF的工具-01]从AITool到AIFunction

MAF支持多种不同类型的工具，这些工具可以扩展Agent的功能。这些工具使Agent能够与外部系统交互、执行代码、搜索数据等等。MAF针对Tool的设计思路与LangChain不太一样，后者用来表示工具的基类的`BaseTool`是一个可执行的对象，意味着LangChain中的工具本质上就是在Agent端执行的一个函数。MAF的工具不限于此，工具可以在Agent端执行，也可以在承载LLM的服务端执行。即使需要在Agent端执行，也并不一定需要绑定一个可执行的对象。所以MAF针对工具类型的定义具有复杂的层次结构，具体的工具类型也五花八本。

## 1. 所有工具的基类：AITool

MAF所有的工具类型最终都继承自如下这个名为`AITool`的抽象基类，它仅仅提供了几个公共的属性和方法。

```csharp
public abstract class AITool
{
	public virtual string Name {get;}
	public virtual string Description  {get;}
	public virtual IReadOnlyDictionary<string, object?> AdditionalProperties  {get;}
	public virtual object? GetService(Type serviceType, object? serviceKey = null);
	public TService? GetService<TService>(object? serviceKey = null);
}
```

`AITool`定义的属性和方法说明如下：

- **Name**：工具的名称，通常用于标识工具的唯一性;
- **Description**：工具的描述信息，通常用于说明工具的功能和用途;
- **AdditionalProperties**：工具的附加属性，通常用于存储工具的自定义信息;
- **GetService**：获取工具的服务对象，通常用于获取工具的依赖服务;
- **`GetService<TService>`**：获取工具的服务对象，通常用于获取工具的依赖服务。

## 2. 可执行的工具AIFunction

顾名思义，`AIFunction`是一个绑定到某个目标函数的可执行工具，我们通过执行目标函数的方式来执行工具。`AIFunction`并没有直接继承自`AITool`，它们之间还有一个名为`AIFunctionDeclaration`的中间抽象类，用来定义函数的声明。对于一个工具函数来说，所谓的**声明（Declaration ）**，本质就是提交给LLM对其输入输出结构的描述。`AIFunctionDeclaration`利用`JsonSchema`和`ReturnJsonSchema`属性返回的`JsonElement`来描述函数的输入输出结构。由于`AIFunction`在Agent端执行，所以提供给LLM的工具只需要其声明就可以了。

```csharp
public abstract class AIFunctionDeclaration : AITool
{
	public virtual JsonElement JsonSchema {get;}
	public virtual JsonElement? ReturnJsonSchema {get;}
}
```

C#中所谓的函数本质上是一个方法，在反射体系中通过`MethodInfo`来表示。`AIFunction`本质上就是一个绑定了`MethodInfo`的可执行工具，它具有如下的定义：

```csharp
public abstract class AIFunction : AIFunctionDeclaration
{
	public virtual MethodInfo? UnderlyingMethod { get; }
	public virtual JsonSerializerOptions JsonSerializerOptions => AIJsonUtilities.DefaultOptions;
	public ValueTask<object?> InvokeAsync(AIFunctionArguments? arguments = null, CancellationToken cancellationToken = default);
	protected abstract ValueTask<object?> InvokeCoreAsync(AIFunctionArguments arguments, CancellationToken cancellationToken);
	public AIFunctionDeclaration AsDeclarationOnly();
}
public class AIFunctionArguments : IDictionary<string, object?>, IReadOnlyDictionary<string, object?>
```

相关成员定义如下：

- **UnderlyingMethod**：绑定的目标方法的`MethodInfo`对象;
- **InvokeCoreAsync**：真正用于完成工具执行的抽象方法；
- **JsonSerializerOptions**：用来控制输入输出序列化和反序列化的`JsonSerializerOptions`对象;
- **InvokeAsync**：对外提供的用来执行工具的方法，它会直接调用`InvokeCoreAsync`方法来完成工具的执行;
- **AsDeclarationOnly**：将`AIFunction`转换为`AIFunctionDeclaration`对象。

## 3. AIFunction中间件

MAF通过如下这个`DelegatingAIFunction`作为`AIFunction`的中间件将AOP的思想引入到工具的执行中，类似的设计同样被用于Agent和ChatClient执行管道，对应的中间件类型分别为`DelegatingAIAgent`和`DelegatingChatClient`。`DelegatingAIFunction`本质上是一个`AIFunction`的包装器，它将一个`AIFunction`对象作为参数传入，并在其内部调用该`AIFunction`对象的`InvokeCoreAsync`方法来完成工具的执行。

```csharp
public class DelegatingAIFunction : AIFunction
{
	protected AIFunction InnerFunction { get; }
	public override string Name => InnerFunction.Name;
	public override string Description => InnerFunction.Description;
	public override JsonElement JsonSchema => InnerFunction.JsonSchema;
	public override JsonElement? ReturnJsonSchema => InnerFunction.ReturnJsonSchema;
	public override JsonSerializerOptions JsonSerializerOptions => InnerFunction.JsonSerializerOptions;
	public override MethodInfo? UnderlyingMethod => InnerFunction.UnderlyingMethod;
	public override IReadOnlyDictionary<string, object?> AdditionalProperties => InnerFunction.AdditionalProperties;
	protected DelegatingAIFunction(AIFunction innerFunction)=>InnerFunction = innerFunction;
	public override string ToString()=> InnerFunction.ToString();
	protected override ValueTask<object?> InvokeCoreAsync(AIFunctionArguments arguments, CancellationToken cancellationToken)
	=>InnerFunction.InvokeAsync(arguments, cancellationToken);
	public override object? GetService(Type serviceType, object? serviceKey = null)
	{
		if (serviceKey != null || !serviceType.IsInstanceOfType(this))
		{
			return InnerFunction.GetService(serviceType, serviceKey);
		}
		return this;
	}
}
```

如上面的代码所示，`DelegatingAIFunction`本质是对另一个`AIFunction`对象的包装。在构造函数中指定的这个`AIFunction`对象被设置为`InnerFunction`属性。`DelegatingAIFunction`重写了所有的属性和方法，并最终将这些调用委托给`InnerFunction`对象。在如下的演示程序中，我们通过继承`DelegatingAIFunction`定义了一个`AIFunctionMiddleware`中间件类，它在执行工具之前和之后打印日志信息。我们将这个中间件类嵌套使用了三次，形成了一个中间件链，最终调用`InvokeAsync`方法来执行工具。

```csharp
using Microsoft.Extensions.AI;

var function = AIFunctionFactory.Create(()=>Console.WriteLine("Target function invoked!"));
var chain = new AIFunctionMiddleware(function, "Baz");
chain = new AIFunctionMiddleware(chain, "Bar");
chain = new AIFunctionMiddleware(chain, "Foo");

await chain.InvokeAsync([], CancellationToken.None);

class AIFunctionMiddleware(AIFunction innerFunction, string MiddlewareName) : DelegatingAIFunction(innerFunction)
{
    protected override ValueTask<object?> InvokeCoreAsync(
        AIFunctionArguments arguments, 
        CancellationToken cancellationToken)
    {
        Console.WriteLine($"{MiddlewareName}.PreInvoke");
        var result = base.InvokeCoreAsync(arguments, cancellationToken);
        Console.WriteLine($"{MiddlewareName}.PostInvoke");
        return result;
    }
}
```

输出

```log
Foo.PreInvoke
Bar.PreInvoke
Baz.PreInvoke
Target function invoked!
Baz.PostInvoke
Bar.PostInvoke
Foo.PostInvoke
```

如下这个`ApprovalRequiredAIFunction`类就是一个继承自`DelegatingAIFunction`的中间件，它可以在执行工具之前引入人工审批检查。如果没有通过审批，则不允许执行工具。这仅仅是一个**标记类**，它并没有实现任何的审批逻辑，具体的审批逻辑实现在`FunctionInvokingChatClient`这个ChatClient中间件中。`FunctionInvokingChatClient`不仅实现了针对工具函数的审核，更为核心的ReAct循环也是由它执行的，具体的实现可以参考我的文章[FunctionInvokingChatClient：ReAct循环和工具审批实现者](https://blog.csdn.net/JaydenAI/article/details/161441181)。

```csharp
public sealed class ApprovalRequiredAIFunction : DelegatingAIFunction
{
	public ApprovalRequiredAIFunction(AIFunction innerFunction)
		: base(innerFunction)
	{
	}
}
```

## 4. 创建AIFuction的工厂:AIFunctionFactory

上面的演示程序中，我们利用`AIFunctionFactory`的`Create`方法根据指定的Lambda表达式创建了一个`AIFunction`对象。`AIFunctionFactory`这个用于创建`AIFunction`的静态工厂类中还定义了如下这些重载的`Create`方法，它们可以根据不同的参数创建`AIFunction`对象。

```csharp
public static class AIFunctionFactory
{	
	public static AIFunction Create(
		Delegate method, 
		AIFunctionFactoryOptions? options);
	public static AIFunction Create(
		Delegate method, 
		string? name = null, 
		string? description = null, 
		JsonSerializerOptions? serializerOptions = null);	

	public static AIFunction Create(
		MethodInfo method, 
		object? target, 
		AIFunctionFactoryOptions? options);
	public static AIFunction Create(
		MethodInfo method, 
		object? target, 
		string? name = null, 
		string? description = null, 
		JsonSerializerOptions? serializerOptions = null);

	public static AIFunction Create(
		MethodInfo method, 
		Func<AIFunctionArguments, object> createInstanceFunc, 
		AIFunctionFactoryOptions? options = null);
}
```

这些`Create`方法的参数说明如下：

- **method**：要绑定的目标方法的`Delegate`对象;
- **target**：要绑定的目标方法的实例对象。如果没有指定，则表示目标方法是一个静态方法;
- **name**：工具的名称;
- **description**：工具的描述信息;
- **serializerOptions**：用于控制输入输出序列化和反序列化的`JsonSerializerOptions`对象;
- **createInstanceFunc**：用于创建目标方法实例的委托函数。

这些`Create`方法最终会常见一个`ReflectionAIFunction`对象，`ReflectionAIFunction`是内嵌于`AIFunctionFactory`中一个继承自`AIFunction`的私有类，它通过反射机制来调用目标方法。在默认情况下，它采用如下的反射逻辑来提供描述`AIFunction`的相关信息：

- **Name**：如果没有通过`name`参数指定：
  - 如果方法标注了`DisplayNameAttribute`特性，则使用其`Name`属性值;
  - 否则使用方法的名称，如果方法名称以Async结尾，则会去掉此后缀。
- **Description**：如果没有通过`description`参数指定：
  - 如果方法标注了`DescriptionAttribute`，则使用其`Description`属性值;
  - 否则使用空字符串。
- **JsonSchema**：根据方法的参数类型和返回值类型生成JsonSchema;
- **ReturnJsonSchema**：根据方法的返回值类型生成JsonSchema。

如果根据上述的规则生成的描述信息不符合要求，则可以通过`AIFunctionFactoryOptions`类型的参数来指定这些描述信息。

```csharp
public sealed class AIFunctionFactoryOptions
{
	public readonly record struct ParameterBindingOptions
	{
		public Func<ParameterInfo, AIFunctionArguments, object?>? BindParameter { get; init; }
		public bool ExcludeFromSchema { get; init; }
	}

	public JsonSerializerOptions? SerializerOptions { get; set; }
	public AIJsonSchemaCreateOptions? JsonSchemaCreateOptions { get; set; }
	public string? Name { get; set; }
	public string? Description { get; set; }
	public IReadOnlyDictionary<string, object?>? AdditionalProperties { get; set; }
	public Func<ParameterInfo, ParameterBindingOptions>? ConfigureParameterBinding { get; set; }
	public Func<object?, Type?, CancellationToken, ValueTask<object?>>? MarshalResult { get; set; }
	public bool ExcludeResultSchema { get; set; }
}
```

`AIFunctionFactoryOptions`各属性说明如下：

- **SerializerOptions**：用于控制输入输出序列化和反序列化的`JsonSerializerOptions`对象;
- **JsonSchemaCreateOptions**：控制如何将方法的参数类型自动生成为LLM能够理解的JSON Schema；
- **Name**：工具的名称;
- **Description**：工具的描述信息;
- **AdditionalProperties**：工具的附加属性;
- **ConfigureParameterBinding**：针对描述参数的`ParameterInfo`对象，返回一个`ParameterBindingOptions`对象：
  - **BindParameter**：根据提供的`ParameterInfo`对象和参数列表，返回一个用于绑定参数的值;
  - **ExcludeFromSchema**：指示是否在生成的`JsonSchema`中排除该参数。
- **MarshalResult**：提供一个委托根据方法指定的结果、类型和`CancellationToken`生成最终返回的结果;
- **ExcludeResultSchema**：在向LLM描述该工具时，是否排除返回值的结构信息。通常在返回值很大、很复杂，且AI不需要知道返回值结构也能正确调用工具时使用，用以节省Token。

`AIJsonSchemaCreateOptions`用于控制如何将方法参数和返回值类型自动翻译成LLM看得懂的JSON Schema。在工具调用中，LLM需要极度标准的JSON Schema来理解参数格式。这个类提供了多层级的钩子让我们能自由干预和修正这个生成过程。

```csharp
public sealed record AIJsonSchemaCreateOptions
{
	public Func<AIJsonSchemaCreateContext, JsonNode, JsonNode>? TransformSchemaNode { get; init; }
	public Func<ParameterInfo, bool>? IncludeParameter { get; init; }
	public Func<ParameterInfo, string?>? ParameterDescriptionProvider { get; init; }
	public AIJsonSchemaTransformOptions? TransformOptions { get; init; }
	public bool IncludeSchemaKeyword { get; init; }
}
```

相关属性说明如下：

- **TransformSchemaNode**：这是一个极其强大的节点转换委托。当框架把某个属性/类型转换成JSON Schema的一个节点（`JsonNode`）后，会把这个节点丢给该委托。我们可以直接用代码修改这个生成的JSON节点；
- **IncludeParameter**：全局参数过滤器。针对方法中的每一个参数，返回true表示生成Schema，返回false表示忽略。我们可以利用它批量隐藏某些特定类型的参数；
- **ParameterDescriptionProvider**：提供参数描述，用于动态决定JSON Schema中每个参数的描述文本；
- **TransformOptions**：通常包含一组更通用、更高级的Schema转换策略或配置；
- **IncludeSchemaKeyword**：控制生成的JSON Schema根节点中是否包含`$schema`这个关键字（例如`"$schema": "https://json-schema.org"`）。有些LLM在接收工具定义时，如果Schema里包含了`$schema`关键字会报错；而有些标准的JSON验证器又必须要求这个关键字。

`TransformOptions`属性返回的`AIJsonSchemaTransformOptions`类型包含了多个控制开关，用于将标准的类型生成的JSON Schema，转换和剪裁为特定LLM所严格要求的方言或格式。由于各大AI厂商（OpenAI、Anthropic、Google 等）对工具调用中的JSON Schema的支持成熟度不同，很多模型对标准的JSON Schema规范做了一些魔改或限制。这个类就是为了解决这些**兼容性痛点**而设计的。

```csharp
public sealed record AIJsonSchemaTransformOptions
{
	public Func<AIJsonSchemaTransformContext, JsonNode, JsonNode>? TransformSchemaNode { get; init; }
	public bool ConvertBooleanSchemas { get; init; }
	public bool DisallowAdditionalProperties { get; init; }
	public bool RequireAllProperties { get; init; }
	public bool UseNullableKeyword { get; init; }
	public bool MoveDefaultKeywordToDescription { get; init; }
}
```

各属性说明如下：

- **TransformSchemaNode**：这是一个极其强大的节点转换委托。当框架把某个属性/类型转换成JSON Schema的一个节点（`JsonNode`）后，会把这个节点丢给该委托。我们可以直接用代码修改这个生成的JSON节点；
- **ConvertBooleanSchemas**：是否将布尔值转换为更严格的对象类型Schema。某些LLM对布尔类型的Schema支持不佳，可能会导致工具调用失败；
- **DisallowAdditionalProperties**：是否在生成的JSON Schema中禁止额外属性（`additionalProperties`）。某些LLM在工具调用时，如果Schema中允许额外属性，可能会导致工具调用失败；
- **RequireAllProperties**：是否在生成的JSON Schema中要求所有属性都是必填的）。某些LLM在工具调用时，如果Schema中有可选属性，可能会导致工具调用失败；
- **UseNullableKeyword**：是否在生成的JSON Schema中使用`nullable`关键字。某些LLM在工具调用时，如果Schema中没有使用`nullable`关键字，可能会导致工具调用失败；
- **MoveDefaultKeywordToDescription**：是否将默认值（default）关键字移动到描述（description）中。某些LLM在工具调用时，如果Schema中有默认值，可能会导致工具调用失败。
