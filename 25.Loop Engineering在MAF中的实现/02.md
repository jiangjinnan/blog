# [Loop Engineering在MAF中的实现-02]循环调用在LoopAgent中的实现

在[上一篇文章](https://blog.csdn.net/JaydenAI/article/details/162899557)中，我们介绍了Loop Engineering基本原理，并通过两个简单的示例分别演示使用`LoopAgent`和`HarnessAgent`来实现Agent循环调用的基本方法。在本篇文章中，我们将介绍`LoopAgent`在MAF的中定义和背后的设计和实现原理。

## 1. 利用LoopEvaluator评估每次调用迭代

Loop Engineering并不是简单地循环调用Agent，必须对每次调用的结果实施评估。如果满足预先设定的条件，则停止循环调用，否则继续调用。如果决定继续，还应该将评估的结果反馈给下一次调用迭代。这样的评估工作落在了具有如下定义的`LoopEvaluator`的肩上。

```csharp
public abstract class LoopEvaluator
{
	public abstract ValueTask<LoopEvaluation> EvaluateAsync(
        LoopContext context, 
        CancellationToken cancellationToken = default);
}
```

`LoopEvaluator`这个抽象类定义了唯一的抽象方法`EvaluateAsync`，作为输入的是表示当前循环调用上下文的`LoopContext`对象，评估的结果体现为返回的`LoopEvaluation`对象上。

### 1.1 LoopContext

`LoopEvaluator`的任务是对上一次调用Agent生成的结果实施评估，所以被评估的**核心材料**有三个：分别是描述原始任务的初始消息列表、上一次Agent返回的响应和之前提供的评估反馈。它们分别体现在作为循环上下文对象`LoopContext`的`InitialMessages`、`LastResponse`和`Feedback`属性上。除了这三个核心输入之外，`LoopContext`还提供了其他一些属性来描述当前循环调用的上下文信息：

```csharp
public sealed class LoopContext
{
	public AIAgent Agent { get; }
	public AgentSession Session { get; }
	public IReadOnlyList<ChatMessage> InitialMessages { get; }
	public AgentRunOptions? RunOptions { get; }
	public int Iteration { get;  }
	public AgentResponse LastResponse { get;  }
	public IReadOnlyList<string?> Feedback { get; }
	public AdditionalPropertiesDictionary AdditionalProperties { get; } = new AdditionalPropertiesDictionary();
}
```

`LoopContext`承载的上下文信息包括：

- **Agent**：当前循环调用的Agent对象；
- **Session**：当前循环调用的Agent会话对象；
- **InitialMessages**：描述原始任务的初始消息列表；
- **RunOptions**：当前循环调用的Agent运行选项；
- **Iteration**：当前循环调用的迭代次数；
- **LastResponse**：上一次Agent调用的响应结果；
- **Feedback**：之前的评估结果反馈列表；
- **AdditionalProperties**：一个字典对象，用于存储额外的上下文信息，开发者可以在评估过程中使用这个字典来传递自定义的上下文数据。

### 1.2 LoopEvaluation

表示评估结果的`LoopEvaluation`类型定义如下。它利用`ShouldReinvoke`属性来指示是否继续循环调用，利用`Feedback`属性来提供评估的反馈信息。`Feedback`属性提供的文本会转换成一条角色为User消息反馈给后续的跌倒。我们也可以直接利用`Messages`属性来提供反馈消息，而这只能选其一。

```csharp
public sealed class LoopEvaluation
{
	public bool ShouldReinvoke { get; }
	public string? Feedback { get; }
	internal IReadOnlyList<ChatMessage>? Messages { get; }

	private LoopEvaluation(
        bool shouldReinvoke,
         string? feedback, 
         IReadOnlyList<ChatMessage>? messages)
	{
		ShouldReinvoke = shouldReinvoke;
		Feedback = feedback;
		Messages = messages;
	}
}
```

由于`LoopEvaluation`的构造函数是私有的，所以我们需要通过静态方法来创建`LoopEvaluation`对象。`LoopEvaluation`提供了三个静态方法：

```csharp
public sealed class LoopEvaluation
{
	private static readonly LoopEvaluation s_stop = new LoopEvaluation(shouldReinvoke: false, null, null);	

	public static LoopEvaluation Stop() =>s_stop;
	public static LoopEvaluation Continue(string? feedback = null)
	    => new LoopEvaluation(shouldReinvoke: true, feedback);
	public static LoopEvaluation ContinueWithMessages(IEnumerable<ChatMessage> messages)
	    => new LoopEvaluation(shouldReinvoke: true, null, (messages as IReadOnlyList<ChatMessage>) ?? messages.ToList());
}
```

三个静态方法分别是：

- **Stop**：表示停止循环调用，以单例形式返回一个`LoopEvaluation`对象，`ShouldReinvoke`属性为`false`；
- **Continue**：表示继续循环调用，`ShouldReinvoke`属性为`true`，并可提供一个反馈信息，但是`Messages`为`null`；
- **ContinueWithMessages**：表示继续循环调用，并提供下一次调用的消息列表，但是`Feedback`为`null`。

## 2. LoopAgentOptions

在正式介绍`LoopAgent`之前，我们先来看看它对应的配置选项类型`LoopAgentOptions`的定义。`LoopAgentOptions`提供的配置选项循环迭代Agent的行为作相应的控制。

```csharp
public sealed class LoopAgentOptions
{
	public int? MaxIterations { get; set; }
	public bool FreshContextPerIteration { get; set; }
	public string? OnBehalfOfAuthorName { get; set; }
	public bool ExcludeOnBehalfOfMessages { get; set; }
	public bool NonStreamingReturnsLastResponseOnly { get; set; }
	public Func<AgentSession, CancellationToken, ValueTask>? SessionCreatedCallback { get; set; }
}
```

具体的配置选项包括：

- **MaxIterations**：最大循环迭代次数，如果为`null`，则表示没有限制；
- **FreshContextPerIteration**：是否在每次迭代中使用新的Agent上下文：
  - **true**：每次迭代都会重建输入消息，只保留**原始输入 + 聚合的反馈日志**，不会把前面的对话历史带入；
  - **false**：每次迭代会在已有的对话基础上追加反馈。此为默认值。
- **OnBehalfOfAuthorName**：给循环（`LoopEvaluator`）自动注入的消息打上作者标记，区分哪些消息是循环自动生成的，哪些是用户真实输入。默认值为`null`，意味着不标记；
- **ExcludeOnBehalfOfMessages**：是否在下一次迭代中排除掉`LoopEvaluator`注入的消息：
  - **false**：调用方能看到循环的自主行为，此为默认值；
  - **true**：调用方只看到封装Agent的响应，不看到循环注入的消息。
- **NonStreamingReturnsLastResponseOnly**：控制非流式运行的返回策略：
  - **false** ：返回完整的聚合消息（包括所有迭代的消息），此为默认值；
  - **true** ： 只返回最后一次迭代的响应。

`FreshContextPerIteration`配置选项还体现了针对Session的控制。如果此选项设置为`true`,意味着：

- 如果调用方提供了`AgentSession`，此`AgentSession`会以序列化的形式生成一个快照，每次迭代都会利用此快照重建`AgentSession`对象，并以此调用Agent；
- 否则循环会在每次迭代创建一个新的`AgentSession`。

## 3. LoopAgent

作为一个继承自`DelegatingAIAgent`的Agent中间件，我们在构建一个`LoopAgent`的时候，除了需要执行`innerAgent`，还可以指定一个或者多个`LoopEvaluator`。在实施评估的时候，会依次调用每个`LoopEvaluator`，直到返回一个`ShouldReinvoke`为`false`的`LoopEvaluation`。也就是说只有所有`LoopEvaluator`决定循环可以终止才可以阻止迭代循环（前提是迭代次数没有超过`MaxIterations`选项的设置）。

```csharp
public sealed class LoopAgent : DelegatingAIAgent
{
    public LoopAgent(
        AIAgent innerAgent, 
        LoopEvaluator evaluator, 
        LoopAgentOptions? options = null, 
        ILoggerFactory? loggerFactory = null);
    public LoopAgent(
        AIAgent innerAgent, 
        IEnumerable<LoopEvaluator> evaluators, 
        LoopAgentOptions? options = null, 
        ILoggerFactory? loggerFactory = null);

    protected override async Task<AgentResponse> RunCoreAsync(
        IEnumerable<ChatMessage> messages,
        AgentSession? session = null,
        AgentRunOptions? options = null,
        CancellationToken cancellationToken = default);

    protected override async IAsyncEnumerable<AgentResponseUpdate> RunCoreStreamingAsync(
        IEnumerable<ChatMessage> messages,
        AgentSession? session = null,
        AgentRunOptions? options = null,
        CancellationToken cancellationToken = default);
}
```

`LoopAgent`针对`innerAgent`的循环调用实现在重写的`RunCoreAsync`和`RunCoreStreamingAsync`方法中，在整个流程的执行受`LoopAgentOptions`配置选项的控制。我们将在[下篇](https://jaydenai.blog.csdn.net/article/details/162921343)对整个循环的执行流程进行系统的介绍，接下来我们简单介绍`LoopAgent`默认采用的循环迭代流程。

## 4. 默认的循环迭代流程

为了探测在默认情况下（保留`LoopAgentOptions`的默认配置），`LoopAgent`采用怎样的方式循环调用Agent和实施评估，我们定义了如下这个基于**迭代次数**的`LoopEvaluator`。顾名思义，这个`InterationCountEvaluator`单纯判断迭代次数是否超过设置的阈值决定是否继续（相当于`MaxIterations`配置选项）。在重写的`EvaluateAsync`方法中，我们会输出`LoopContext`上下文提供的迭代次数、原始消息、上一次响应消息、之前的返回以及当前提供的反馈（如果决定继续）。

```csharp
class InterationCountEvaluator(int allowedIterations) : LoopEvaluator
{
    public override ValueTask<LoopEvaluation> EvaluateAsync(
        LoopContext context, 
        CancellationToken cancellationToken = default)
    {
        Console.WriteLine($"""
            {new string('-', 30)}Evaluator{new string('-', 30)}
            Iteration: {context.Iteration}
            Initial messages:
                {string.Join("\n    ", context.InitialMessages.Select(it => $"{it}"))}
            Last response:
                {string.Join("\n    ", context.LastResponse.Messages.Select(it => $"{it}"))}
            Previous feedback:
                {string.Join("\n    ", context.Feedback)}
            """);
        if(context.Iteration >= allowedIterations)
        {
            return ValueTask.FromResult(LoopEvaluation.Stop());
        }

        var feedback = $"Feedback for iteration {context.Iteration}";
        Console.WriteLine($"Feedback:{feedback}\n");
        return ValueTask.FromResult(LoopEvaluation.Continue(feedback));
    }
}
```

为了确定`LoopAgent`调用`inerAgent`提供的消息和返回的响应，我们定义了如下这个`FakeChatClient`来模拟与LLM的交互。在重写的`GetResponseAsync`方法中，我们调用`ChatMessageGenerator`的静态方法`GenerateMessage`方法生成一个响应消息（消息内容会携带自增的序号）。我们会输出传入的消息和响应的消息。

```csharp
class FakeChatClient : IChatClient
{
    public void Dispose() { }
    public Task<ChatResponse> GetResponseAsync(
        IEnumerable<ChatMessage> messages, 
        ChatOptions? options = null, 
        CancellationToken cancellationToken = default)
    {
        var message = ChatMessageGenerator.GenerateMessage(
            "Response message from LLM.", ChatRole.Assistant);
        Console.WriteLine($"""
            {new string('-', 30)}LLM{new string('-', 30)}
            Incoming messages:
                {string.Join("\n    ", messages.Select(it => $"{it}"))}

            Outgoing response:
                {message}

            """);
        return Task.FromResult(new ChatResponse(message));
    }

    public object? GetService(Type serviceType, object? serviceKey = null)=>null;
    public IAsyncEnumerable<ChatResponseUpdate> GetStreamingResponseAsync(IEnumerable<ChatMessage> messages, ChatOptions? options = null, CancellationToken cancellationToken = default)
    => throw new NotImplementedException();
}

internal static class ChatMessageGenerator
{
    private static int _counter = 0;
    public static ChatMessage GenerateMessage(string content, ChatRole role)
    {
        return new ChatMessage(
            role: role,
            content: $"[{Interlocked.Increment(ref _counter)}]{content}"
        );
    }
}
```

整个演示程序很简单。如下面的代码所示，我们创建了一个`FakeChatClient`对象并将其转换成`AIAgent`，然后根据它和创建`InterationCountEvaluator`对象将`LoopAgent`创建出来，并将允许的迭代次数设置为`3`。

```csharp
using Microsoft.Agents.AI;
using Microsoft.Extensions.AI;

var agent = new LoopAgent(
    innerAgent: new FakeChatClient().AsAIAgent(),
    evaluator: new InterationCountEvaluator(3));

List<ChatMessage> input = [
    ChatMessageGenerator.GenerateMessage("Original message from user.", ChatRole.User),
    ChatMessageGenerator.GenerateMessage("Original response from LLM.", ChatRole.Assistant),
    ChatMessageGenerator.GenerateMessage("Original message from user.", ChatRole.User),
    ];

var response = await agent.RunAsync(input);
var index = 1;
foreach (var message in response.Messages)
{
    Console.WriteLine($"""
        {new string('-', 20)}Message{index++}{new string('-', 20)}
        {message}

        """);
}
```

我们调用`ChatMessageGenerator`的`GenerateMessage`方法创建了三个消息，我们将它们组成消息列表作为输入调用`LoopAgent`的`RunAsync`后，输出响应携带的所有消息。程序运行后，针对`FakeChatClient`和`InterationCountEvaluator`的迭代调用会体现在如下的输出中：
