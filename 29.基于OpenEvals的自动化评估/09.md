# [基于OpenEvals的自动化评估-09]针对RAG的三种评估

我们知道RAG分两步：一、根据原始输入检索相关的文档；二、将检索结果作为上下文提交给LLM生成输出。两个步骤涉及三类数据：输入、上下文和输出。三类数据两两比较就带来了如下三种针对RAG的评估：

- **检索相关性评估**：评估作为上下文的检索结果与输入的相关度；
- **事实依据性评估**：评估最终输出与上下文的忠实程度；
- **帮助性评估**： 评估最终的输出对于输入提供的问题有多大的帮助。

## 1. 检索相关性评估（Retrieval Relevance Evaluation）

检索相关性评估用来确定系统检索出来的作为上下文的参考文档，对于回答用户输入问题的**有用程度**和**关联紧密性**。在RAG系统中，它是核心的**漏斗第一步**，如果检索到的东西不相关，后续大模型生成的回答再漂亮也是空中楼阁。评估的核心不是看文档是否完美，而是看它能不能帮上忙：

- **相关（Relevant）**：只要包含能帮助回答问题的知识，即使信息不完整、或夹杂了其他废话，也算相关；
- **不相关（Irrelevant）**：完全无法提供有用信息、完全跑题、包含误导性/错误信息，或者只有表面相关但实际毫无实用价值。

如果把LLM看作**考生**，检索结果看作**开卷考试的参考书**，那么检索相关性评估就是在判定**教务处发给考生的这几本书，里面到底有没有这道题的答案？**。OpenEvals针对有害性评估的提示词模板定义在常量**openevals.prompts.rag.RAG_RETRIEVAL_RELEVANCE_PROMPT**，具体内容如下。由于这种评估方式旨在评估作为上下文的检索结果与原始输入之间的相关性，所以提示词模板只包含作为输入和上下文的`{inputs}`和`{context}`占位符。

```markdown
You are an expert data labeler evaluating retrieved context for relevance to the input. Your task is to assign a score based on the following rubric:

<Rubric>
- Relevant retrieved context:
  - Contain information that could help answer the input, even if incomplete.
  - May include superfluous information, but it should still be somewhat related to the input.

- Irrelevant retrieved context:
  - Contain no useful information for answering the input.
  - Are entirely unrelated to the input.
  - Contains misleading or incorrect information
  - Contains only tangentially related information with no practical utility
</Rubric>

<Instruction>
- Read and understand the full meaning of the input (including edge cases)
- Formulate a list of facts and relevant context that would be needed to respond to the input
- Analyze the retrieved context to identify:
  - Information directly relevant to answering the query
  - Information partially relevant or contextually helpful
  - Information completely irrelevant to the query
- For each piece of information need identified in the previous step, determine:
  - Whether it is fully addressed by the retrieved documents (cite specific text)
  - Whether it is partially addressed (cite specific text)
  - Whether it is not addressed at all
- Note any facts needed to answer the input that are not found
- Note any context that are completely irrelevant, i.e. contain no relevant facts for answering the input
</Instruction>

<Reminder>
- Focus solely on whether the retrieved context provides useful information for answering the input.
- Think deeply about why the context is or isn't relevant.
- Use partial credit where applicable, recognizing context that is somewhat helpful even if incomplete.
</Reminder>

<inputs>
{inputs}
</inputs>

<retrieved_context>
{context}
</retrieved_context>
```

在如下这个演示程序中，我们将评估的核心操作定义在`eval`函数中，它会根据指定的提示词和用来连接LLM（`gpt-5.4-mini`）的`ChatOpenAI`对象创建一个基于L**LM-as-a-Judge**的评估器。然后根据指定的输入、输出、引用输出和额外的关键字参数调用评估器，并将评估结果以JSON的形式输出。

```python
from openevals import create_async_llm_as_judge
from langchain_openai  import ChatOpenAI
from dotenv import load_dotenv
from openevals.prompts.rag import  RAG_RETRIEVAL_RELEVANCE_PROMPT
import asyncio,json, functools

load_dotenv()

judge = ChatOpenAI(model="gpt-5.4-mini")
async def eval( *, 
    prompt: str,
    inputs:str|None = None,
    outputs:str|None = None,
    reference_outputs:str|None = None,
    **kwargs):
    evaluator = create_async_llm_as_judge(
        prompt = prompt,
        continuous= True,       
        judge= judge)
    result = await evaluator(
        inputs= inputs,
        outputs=outputs,
        reference_outputs=reference_outputs,
        **kwargs
    )
    print(json.dumps(result,ensure_ascii=False, indent=2))

async def main(): 
    partial = functools.partial(
        eval,
        prompt = RAG_RETRIEVAL_RELEVANCE_PROMPT,
        inputs = "如何在我们的系统里重置密码？" )
    context1 = """
我们的系统为了保障用户安全，采用了最先进的加密技术。
重置密码是维护账户安全的重要环节，请确保您的密码符合复杂度要求。
如需了解更多关于账户安全策略的信息，请参阅《网络安全管理规范》。
"""
    context2="""
当用户登录失败时，可以点击登录框下方的链接。
系统会引导您进入重置密码界面，此时需要输入您的注册邮箱。
虽然由于系统版本更新，目前通过手机验证码重置的功能暂时下线维护，但邮箱重置功能一切正常。
"""
    
    await partial(context = context1)
    await partial(context = context2)

asyncio.run(main())
```

在`main`函数中，我们指定了上述的提示词，针对同一个问题**如何在我们的系统里重置密码？**，提供了两种检索结果。前者虽然提及了很多关于密码的内容，但是从语义来看与输入几乎不相关；而后者则真正提供了重置密码的解决方案。输出的评估结果通过分数清晰地揭示了两条检索结果与输入的相关程度。

## 2. 事实依据性评估（Groundnesss Evaluation）

事实依据性评估是指评估LLM生成的输出在多大程度上忠实并根植于检索到的作为上下文的参考文档。如果说前面的**检索相关性评估**是检查**书发对没有**，那么这种评估就是在检查**考生是不是在对着这本书开卷考试？有没有自己凭空瞎编（即产生‘幻觉’）**。评估的核心是遵循**闭合世界假定**（即认为参考文档是唯一的真理宇宙）：

- **高依据性**：
  - 所有核心断言必须由文档直接支持；
  - 严丝合缝地限定在文档信息范围内；
  - 保持与源材料相同的原意和意图。
- **无依据性**：
  - 凭空提出文档中没有的观点；
  - 与文档内容直接冲突；
  - 引入了文档之外的外部知识或主观推测；
  - 歪曲或曲解了原意。

OpenEvals针对有害性评估的提示词模板定义在常量**openevals.prompts.rag.RAG_GROUNDEDNESS_PROMPT**，具体内容如下。由于这种评估方式旨在评估作为上下文的检索结果与最终输出之间的相关性，所以提示词模板只包含作为输入和上下文的`{context}`和`{outputs}`占位符。

```markdown
You are an expert data labeler assessing how well LLM output aligns with and is supported by the retrieved context. Your evaluation should focus on the following criteria:

<Rubric>
A well-grounded output should:
- Make claims that are directly supported by the retrieved context
- Stay within the scope of information provided in the context
- Maintain the same meaning and intent as the source material
- Not introduce external facts or unsupported assertions outside of basic facts (2 + 2 = 4)

An ungrounded output:
- Makes claims without support from the context
- Contradicts the retrieved information
- Includes speculation or external knowledge outside of basic facts
- Distorts or misrepresents the context
</Rubric>

<Instruction>
- Compare the output against the retrieved context carefully
- Identify claims, statements, and assertions in the output
- For each claim, locate supporting evidence in the context
- Check for:
  - Direct statements from context
  - Valid inferences from context
  - Unsupported additions
  - Contradictions with context

- Note any instances where the output:
  - Extends beyond the context
  - Combines information incorrectly
  - Makes logical leaps
</Instruction>

<Reminder>
- Focus solely on alignment with provided context
- Ignore whether external knowledge suggests different facts
- Consider both explicit and implicit claims
- Provide specific examples of grounded/ungrounded content
- Remember that correct grounding means staying true to the context, even if context conflicts with common knowledge
</Reminder>

<context>
{context}
</context>

<outputs>
{outputs}
</outputs>
```

在前面演示程序的基础上，我们对`main`函数进行如下的修改来演示基于公平性的评估。针对同一份检索结果（Context）给出的两个待评估的输出，前者至少存在如下两个问题：

- **凭空捏造**：文档说**潜在影响仍在实验中**，模型却吹嘘是**最安全、完全没有副作用**，这直接无视了检索内容提到的**12%失眠率**；
- **夸大其词**：文中是**平均体脂率下降**，模型改成了绝对的**帮你减掉**，抹杀了个体差异。

相比第二条输出就几乎完美贴合了上下文，这一切都体现在作为输出的评估结果中。

## 3. 帮助性评估（Helpfulness Evaluation）

帮助性评估是指评估LLM生成的回答（Output），在多大程度上真正切中并有效解决了用户输入的初始问题（Input）。如果说前面的**依据性（Groundedness）**是在检查LLM**老不老实**（有没有开卷瞎编），那么**帮助性（Helpfulness）**就是在检查LLM**聪不聪明，能不能干**（有没有真正帮用户解决实际问题）。评估的核心在于**解决问题的效能**：

- **高帮助性**：
  - 直击问题的核心诉求；
  - 提供准确且必需的信息；
  - 内容的详略程度与问题的范围相匹配（不多不少，恰到好处）；
  - 即使答案与评估器自身的内置常识相悖（例如特定系统内部检索出的独特规则），只要对用户有用，依然判定为正确。

- **低帮助性**：
  - 没有回答到点子上（顾左右而言他）；
  - 夹带了大量完全无关的废话；
  - 无法给用户提供实际的参考价值。

OpenEvals针对有害性评估的提示词模板定义在常量**openevals.prompts.rag.RAG_HELPFULNESS_PROMPT**，具体内容如下。由于这种评估方式旨在评估作为上下文的原始输入和最终输出之间的相关性，所以提示词模板只包含作为输入和上下文的`{inputs}`和`{outputs}`占位符。

```markdown
You are an expert evaluator assessing how helpful and relevant outputs are in addressing an input query. Your evaluation should focus on the following criteria:

<Rubric>
A helpful and relevant output should:
- Directly address the core question or need in the input
- Provide accurate and necessary information
- Be appropriately detailed for the query's scope
- May contradict your built-in knowledge but still be correct for the given context

An unhelpful or irrelevant output:
- Fails to address the main question
- Contains primarily unrelated information
</Rubric>

<Instruction>
- Read and understand the full meaning of the input (including edge cases)
- Identify any implicit requirements or context
- Identify the expected scope of the answer

- Analyze the output to identify:
  - How well it addresses the core question
  - The relevance of included information
  - Any critical missing information
  - Any extraneous or unhelpful content
</Instruction>

<Reminder>
- Evaluate based on practical usefulness to the query
- Consider both direct relevance and helpful context
- Identify specific strengths and weaknesses in the response
- Provide clear reasoning for your assessment
- Remember that correct information may differ from your built-in knowledge based on internal retrieved context
</Reminder>

<inputs>
{inputs}
</inputs>

<outputs>
{outputs}
</outputs>
```

在前面演示程序的基础上，我们对`main`函数进行如下的修改来演示基于公平性的评估。针对同一个问题**Mac电脑突然连不上公司的Wi-Fi**,给出了两种解决方案。前者说了一大推，其实基本上对于问题的解决并没有多少参考意义，后者不仅精准识别了“无IP”的病因，给出了“续订 DHCP”这一专业且必要的动作，还充分考虑到问题的紧迫性，先提供“手机热点”的应急方案，完美兼顾了用户“要开紧急会议”的实际诉求。评估的结果也对输出是否有帮助打出了公正的分数。

```python
async def main(): 
    partial = functools.partial(
        eval,
        prompt = RAG_HELPFULNESS_PROMPT,
        inputs = """
我的Mac电脑突然连不上公司的Wi-Fi了，提示**无IP地址**。
今天有紧急会议，该怎么办？
""")
    outputs1 = """

首先请确保您的Wi-Fi路由器已经开启并正常工作。
您可以尝试关闭Mac的Wi-Fi开关，等待10秒钟后再重新打开。
如果还是不行，建议您检查公司其他同事的电脑是否能正常联网。
如果大家都连不上，可能是公司网络故障，需要联系IT部门修复。
另外，保持系统更新也能减少这类网络问题的发生。
"""
    outputs2="""

- 临时应急（1分钟）：如果手机网络正常，请立刻开启手机热点，让 Mac 优先接入进入会议，开完会再修网络。
- 按照如下的方式更新 DHCP租约（2分钟，核心解决办法），这通常能立刻重新获取 IP：
  - 点击 Mac 左上角苹果图标 -> 系统设置 -> 网络 -> Wi-Fi 
  - 点击公司网络旁的‘详细信息’ -> 选择‘TCP/IP’标签 -> 点击‘续订 DHCP 租约’。。
```
