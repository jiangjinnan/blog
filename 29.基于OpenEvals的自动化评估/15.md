# [基于OpenEvals的自动化评估-15]以LLM-as-a-Judge方式评估Agent生成的代码

[基于OpenEvals的自动化评估-14:以静态代码分析方式评估Coding Agent生成的代码](https://blog.csdn.net/JaydenAI/article/details/163684839)着重介绍了基于MyPy和Pyright这两种广受欢迎的基于Python的静态代码分析引擎器来评估Agent生成的代码，其实提取出来的代码还可以直接交给LLM进行评估。相关的评估器可以利用`create_code_llm_as_judge`这个工厂函数来创建，本篇文章就来介绍如何利用这种方式实施针对代码的评估。

## 1. 代码评估器的创建

基于**LLM-as-a-Judge**的代码评估器可以利用如下所示的两个工厂函数来创建，其中`create_code_llm_as_judge`用来创建代表同步评估器的`SimpleEvaluator`对象，`create_async_code_llm_as_judge`则用来创建按代表异步评估器的`SimpleAsyncEvaluator`。这两个工厂函数的参与大体包含两个部分，一部分与代码内容的提取相关，对应的参数与`create_pyright_evaluator`/`create_async_pyright_evaluator`和`create_mypy_evaluator`/`create_async_mypy_evaluator`一致。余下的参与基于**LLM-as-a-Judge**的评估有关，与[基于OpenEvals的自动化评估-02:LLM-as-a-Judge](https://blog.csdn.net/JaydenAI/article/details/163554430)介绍的`create_llm_as_judge`和`create_async_llm_as_judge`函数一致。

```python
def create_code_llm_as_judge(
    *,
    prompt: Union[str, Runnable, Callable[..., list[ChatCompletionMessage]]],
    feedback_key: str = "code_correctness",
    code_extraction_strategy: Literal["none", "llm", "markdown_code_blocks"] = "none",
    code_extractor: Optional[Callable[[Any], str]] = None,
    judge: Optional[BaseChatModel] = None,
    model: Optional[str] = None,
    system: Optional[str] = None,
    continuous: bool = False,
    choices: Optional[list[float]] = None,
    use_reasoning: bool = True,
    few_shot_examples: Optional[list[FewShotExample]] = None,
) -> SimpleEvaluator

def create_async_code_llm_as_judge(
    *,
    prompt: Union[str, Runnable, Callable[..., list[ChatCompletionMessage]]],
    feedback_key: str = "code_correctness",
    code_extraction_strategy: Literal["none", "llm", "markdown_code_blocks"] = "none",
    code_extractor: Optional[Callable[[Any], str]] = None,
    judge: Optional[BaseChatModel] = None,
    model: Optional[str] = None,
    system: Optional[str] = None,
    continuous: bool = False,
    choices: Optional[list[float]] = None,
    use_reasoning: bool = True,
    few_shot_examples: Optional[list[FewShotExample]] = None,
) -> SimpleAsyncEvaluator
```

两个工厂函数定义的参数说明如下：

- **prompt**:定义评估提示词模板，类型可以是字符串，也可以是类似于`PromptTemplate`这样的`Runnable`对象（可以采用LCEL表达式于LLM进行连接），或者是一个用于返回LLM输入的消息列表的函数。如果以字符串定义提示词，可以包含如下的占位符：
  - {inputs}
  - {outputs}
  - {reference_outputs}
  - {由kwargs指定的参数名称}
- **feedback_key**：评估结果中存储的字段名，默认为`score`；
- **code_extraction_strategy**：指定从LLM的原始文本回复中提取纯Python代码的策略，具有如下三个选项：
  - **none**：不做任何处理。直接将LLM返回的所有文本全部塞进`.py`文件。适用于你的大模型被严格限制了只能输出纯代码、不能带有任何自然语言解释的场景；
  - **llm**：使用大模型提取。如果被评估的模型输出非常混乱（例如把代码和大量文字混杂在一起且不用Markdown标签），评估器会调用另一个独立的大模型（裁判模型）来帮你把纯代码捞出来；
  - **markdown_code_blocks**: 提取Markdown代码块。评估器会自动扫描文本，只把被```` ```python ... ``` ````包裹的代码提取出来进行测试。这是最常用的推荐设置。
- **code_extractor**：自定义代码提取函数。如果上述三种自带的`code_extraction_strategy`策略都不满足你的需求，你可以自己写一个Python函数传给它;
- **judge**/**model**: 用于提供用来提取代码和实施评估的LLM；
- **system**： 系统提示词；
- **continuous**：评估结果是否是连续值：
  - **True**： 输出为`0~1`的连续浮点数；
  - **False**： 输出为布尔值。
- **choices**：如果希望评估结果采用指定的选项，可以利用此参数指定一个列表，比如`choices=[0.0, 0.5, 1.0]`意味着最终得分只有指定的三种选择；
- **use_reasoning**：是否要求模型输出评分理由：
  - **True**：输出包含解释；
  - **False**：只输出评分。
- **few_shot_examples**: 用于在提示词中加入`few-shot`示例，提升评估一致性。

在调用`SimpleEvaluator`/`SimpleAsyncEvaluator`进行评估的时候，定义在评估提示词模板的占位符会被同名的参数替换。如果使用`model`参数指定包含提供商的模型标准名称，方法内部会利用标准的URL创建代表LangChain LLM组件的`BaseChatModel`对象。如果需要连接自定义URL指向的LLM部署地址，或者需要对LLM组件对象进行定制，可以直接利用`judge`参数指定一个`BaseChatModel`对象。也可以直接执行一个`ModelClient`对象，`ModelClient`是OpenEvals针对LLM客户端组件的表达，但是此时依然需要利用model参数指定模型名称。

## 2. 代码评估提示词

OpenEvals为代码正确性的评估定义了专门的提示词，对于此提示词，我们曾在[基于OpenEvals的自动化评估-07：评估Agent输出文本的质量](https://blog.csdn.net/JaydenAI/article/details/163603909)介绍过。而且提示词有两条，分别采用常量**CODE_CORRECTNESS_PROMP**和**CODE_CORRECTNESS_PROMPT_WITH_REFERENCE_OUTPUTS**表示。两者的区别主要体现在：后者提供作为评估基准的`{reference_outputs}`占位符。如果使用这条提示词，意味着我们至少需要提供一个填充`{inputs}`占位符的输入，倘若仅仅希望按照类似于[以静态代码分析方式评估代码](https://blog.csdn.net/JaydenAI/article/details/163684839)的方式进行代码合法有效性评估，我们需要定义一个**免输入**的提示词。为此我们定义了如下这条提示词：

```markdown
You are an expert code evaluator. You will be shown a code generation scenario, including the user's requirements, an optional reference solution, and the actual code generated by an AI assistant.
Your task is to judge whether the generated code is legally valid, syntactically correct, and functionally effective.

<Rubric>
Appropriate code implementation (TRUE) must include:
- Complete syntactical validity: No syntax errors, broken indentations, or unresolved variable references.
- Functional alignment: Seamlessly satisfying all core requirements and constraints specified in the user prompt.
- Type safety and contract adherence: Correct usage of standard type hints and legal API/method calls for specified libraries.
- Robustness: Handling basic edge cases properly without unexpected runtime crashes.

Inappropriate code implementation (FALSE) may include:
- Critical code defects: Presence of blocking bugs, syntax errors, or logical flaws that prevent execution.
- Missing core requirements: Failing to implement the foundational business logic requested by the user.
- Severe type mismatches: Returning or assigning completely incompatible data types against the function contract.
- Hallucinated APIs: Calling non-existent methods, properties, or third-party libraries that do not exist.
</Rubric>

<Instructions>
For each code evaluation:
1. Conduct a dynamic mental execution of the generated code to check for syntax and type safety.
2. Cross-reference the core business logic of the generated code against the user prompt.
3. Assign TRUE if the code is entirely valid, functional, and aligned. Assign FALSE if it contains blocking bugs, syntax errors, or misses core requirements.
</Instructions>

Please grade the following code according to the above instructions:

<conversation>
{outputs}
</conversation>
```

## 3. 同时利用LLM提取代码和实施评估

在如下的演示程序中，我们会利用`create_async_code_llm_as_judge`函数创建一个用来评估代码的`SimpleAsyncEvaluator`。在调用此函数的时候，我们利用judge参数指定的ChatOpenAI对象完成代码**提取**和**评估**两项工作。所以我们不但将`code_extraction_strategy`参数设置为`llm`，还将两段评估文本中用来包装代码片段的Markdown标签（\`\`\`pythhon...\`\`\`）剔除。

```python
from openevals.code.llm import create_async_code_llm_as_judge
from langchain_openai  import ChatOpenAI
from dotenv import load_dotenv
import json, asyncio

load_dotenv()

prompt="""
...上面定义的提示词...
"""

code1 = """
这是一个计算斐波那契数列的Python函数:

def fibonacci(n: int) -> list[int]:
    if n <= 0:
        return []
    if n == 1:
        return [0]
    
    sequence: list[int] = [0, 1]
    while len(sequence) < n:
        sequence.append(sequence[-1] + sequence[-2])
    return sequence

"""

code2 ="""
这里是一个处理用户数据的函数:

def process_user_age(age_str: str) -> int:
    if not age_str.isdigit():
        return "Invalid Age"         
    age = int(age_str)
    return age

def greet_user(name: str, age: int) -> str:
    return f"Hello {user_name}, you are {age} years old." 

"""

async def main():
    evaluator = create_async_code_llm_as_judge(
        prompt= prompt,
        code_extraction_strategy="llm",
        judge= ChatOpenAI(model="gpt-5.4-mini"))
    result = await evaluator(outputs=code1)
    print(json.dumps(result, indent= 2, ensure_ascii=False))
    
    result = await evaluator(outputs=code2)
    print(json.dumps(result, indent= 2, ensure_ascii=False))

asyncio.run(main())
```

输出：

```json
{
  "key": "code_correctness",
  "score": true,
  "comment": "The provided code is syntactically valid Python and implements a standard Fibonacci sequence generator returning the first n terms as a list of integers. It correctly handles basic edge cases for n <= 0 and n == 1, uses legal type hints, and has no unresolved references or invalid API usage. Thus, the score should be: True.",
  "metadata": null
}
```

```json
{
  "key": "code_correctness",
  "score": false,
  "comment": "The code is not fully valid or functionally correct. In process_user_age, the function is annotated to return int but returns the string 'Invalid Age' for non-digit input, which is a type contract violation. In greet_user, the parameter is named name, but the f-string references user_name, which is undefined and will raise a NameError at runtime. These issues prevent the code from being robust and correctly executable. Thus, the score should be: false.",
  "metadata": null
}
```

从输出的结果看出，两端文本中提供的python代码内容被成功提取出来。第一段代码合法有效，得到了正确的评估结果。第二段代码的存在的如下问题也被成功检测到：

- `process_user_age`函数返回值与注解类型不一致；
- `greet_use`r函数使用了未定义的变量`user_name`。
