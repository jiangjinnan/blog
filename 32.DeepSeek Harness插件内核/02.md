# [DeepSeek Harness插件内核-02]服务的注册与消费

[DeepSeek Harness插件内核-01:DeepSeek Harness三种插件形式](https://blog.csdn.net/JaydenAI/article/details/164044310)中介绍了Cordis插件的三种定义方式，我们将所有的功能实现在作为插件的函数或者对象上。真正的插件开发中，我们都倾向于将业务功能定义成服务并注册到Context上供插件以注入的方式消费。本篇文章将会通过一系列简单的实例来演示服务的定义、注册和消费。

## 1. 将服务注册到Context上

我们依然使用[DeepSeek Harness插件内核-01:DeepSeek Harness三种插件形式](https://blog.csdn.net/JaydenAI/article/details/164044310)中演示的例子：注册一个插件输出一条问候语（比如*Good morning|afternoon|evening*）。前面我们使用配置的方式来提供时间部分的内容(*morning|afternoon|evening*)，现在我们采用注册服务的形式来提供此内容。如下面的代码所示，我们在`main`函数中根据用户输入的内容创建一个`timeOfDayService`对象，提供的时间由它的`value`属性表示。我们从`Context`的`reflect`属性得到用于提供反射相关操作的`ReflectService`对象，并调用其`provide`方法完成服务的注册。

```typescript
import { Context,Service } from '@deepseek-ai/cordis'
import * as readline from "readline"

function greet(ctx: Context){
    const timeOfDayService =  (ctx as any)["timeOfDay"] as {value:string};
    console.log(`Good, ${timeOfDayService.value}`);
}

async function main() {
  const ctx = new Context();
  const rl = readline.createInterface({
      input: process.stdin,
      output: process.stdout});    

  rl.question("Enter time of day:", (answer) => {      
    const timeOfDayService = {
        value: answer
    };
    ctx.reflect.provide("timeOfDay",timeOfDayService, ()=>true);
    ctx.plugin(greet);
    });
};

main();
```

调用`provide`方法出了传入作为服务对象之外，还需要指定额外两个参数：

- 服务的注册名称（`timeOfDay`）
- 用来确定服务可用性的函数（`()=>true)`）。

完成服务注册之后，相当于会在`Context`将服务对象挂载到以注册名称命名的字段上。所以表示插件的`greet`函数可以直接从传入的`Context`对象中提取这个用于提供问候时间的服务，并从其`value`属性得到所需的时间。最终完成最后问候语的输出：

```bash
Enter time of day:morning
Good, morning
```

## 2. 为Context接口添加服务声明

虽然我们可以按照`greet`函数所示方式根据注册名称将服务实例提取出来，但是这种方式未免过于繁琐和丑陋了一些，最好的方式是直接为`Context`接口声明一个针对注册服务的属性。对于我们演示的例子，就可以按照如下的方式为Context声明一个`timeOfDay`字段来提取注册的服务。

```typescript
declare module '@deepseek-ai/cordis' {
  interface Context {
    timeOfDay: {value:string}
  }
}
function greet(ctx: Context){
    console.log(`Good, ${ctx.timeOfDay.value}`);
}
```

## 3. 以Service派生类形式定义服务

Cordis可以将任何对象注册为服务，但是大部分情况下我们倾向于将服务类型派生于`Service`基类。我们将greet插件依赖的服务定义成如下这个派生于Servie的TimeOfDayService类型，并利用其value字段提供所需的时间。构造函数以参数的形式提供当前`Context`和配置，并调用基类的构造函数完成服务的注册。

```typescript
import { Context,Service } from '@deepseek-ai/cordis'
import * as readline from "readline"

class TimeOfDayService extends Service{
    value: string;
    constructor(ctx:Context, value: string){
        super(ctx, "timeOfDay");
        this.value = value;
    }
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    timeOfDay: TimeOfDayService
  }
}
function greet(ctx: Context){
    console.log(`Good, ${ctx.timeOfDay.value}`);
}

async function main() {
  const ctx = new Context();
  const rl = readline.createInterface({
      input: process.stdin,
      output: process.stdout});    

  rl.question("Enter time of day:", (answer) => {      
    new TimeOfDayService(ctx, answer);
    ctx.plugin(greet);
    });
};

main();
```

输出：

```log
Enter time of day:morning
Good, morning
```

由于`Service`会在构造函数中完成服务的注册，所以上面我们仅仅实例化了一个`TimeOfDayService`对象而已。但这并非推荐的编程方式，更好的方式是将服务按照插件一样的方式进行注册，而且`Service`类型是以`Plugin.Constructor<T>`接口匹配的。我们按照这种方式对演示程序的`main`函数进行了如下的改造：

```typescript
async function main() {
  const ctx = new Context();
  const rl = readline.createInterface({
      input: process.stdin,
      output: process.stdout});    

  rl.question("Enter time of day:", (answer) => {   
    const fiber = ctx.plugin(TimeOfDayService, answer)   
    fiber.ctx.plugin(greet);
    });
};
```

## 4. 将服务注入插件

对于上面的演示程序，我们总是在注册作为服务消费者的`greet`插件之前就完成了针对依赖服务的注册。但是真实的场景是：

- 依赖服务可能在插件注册**之后**才注册；
- 依赖服务随着作为提供者的插件卸载而被**卸载**。

为了确保作为服务消费者插件的正常执行，需要在插件和依赖服务之间构建一种依赖关系，并提供一种检测服务可用性状态的机制。[DeepSeek Harness插件内核-01:DeepSeek Harness三种插件形式](https://blog.csdn.net/JaydenAI/article/details/164044310)中介绍的三种插件接口都是针对如下这个`Plugin.Base<T>`接口的扩展，其可缺省的`inject`属性表示的就是注入的服务名称列表或者服务名称与对应配置的映射。

```typescript
export namespace Plugin {
  export interface Base<T = any> {
    name?: string
    Config?: StandardSchemaV1<any, T>
    inject?: Inject
    provide?: string | string[]
    intercept?: Dict<boolean>
  }
}
export type Inject<M = Dict> = (keyof M)[] | { [K in keyof M]?: M[K] }
```

在如下的演示程序中，我们会在完成针对`greet`插件后延迟5秒支持其依赖的服务。为了体现插件和服务的注入关系，我们以对象的方式提供插件，并将依赖服务的名称添加到插件对象的`inject`字段。从输出可以看出，插件会等待依赖服务可用时才会执行。

```typescript
import { Context,Service } from '@deepseek-ai/cordis'
import * as readline from "readline"

class TimeOfDayService extends Service{
    value: string;
    constructor(ctx:Context, value: string){
        super(ctx, "timeOfDay");
        this.value = value;
    }
}

function timeOfDayPlugin(ctx: Context, config: {timeOfDay: string}){
    new TimeOfDayService(ctx, config.timeOfDay);
    console.log("TimeOfDayService has been registed.")
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    timeOfDay: {value:string}
  }
}

async function main() {
  const ctx = new Context();
  const rl = readline.createInterface({
      input: process.stdin,
      output: process.stdout}); 

  rl.question("Enter time of day:", (answer) => {   
    ctx.plugin({
        apply: function(ctx: Context, config: any){ console.log(`Good, ${ctx.timeOfDay.value}`)}, 
        inject:["timeOfDay"]});
    setTimeout(()=>ctx.plugin(timeOfDayPlugin, {timeOfDay:answer}), 5000);
    });
};

main();
```

输出：

```log
Enter time of day:morning
Good, morning
```

其实`RegistryService`为我们定义了如下的`inject`方法来完成基于服务注入的插件注册，可用看出最终还是像上面的演示程序一样调用`plugin`方法以对象形式进行插件的注册。

```typescript
export class RegistryService {
  inject(inject: Inject, callback: Plugin.Function<void>) {
    return this.plugin({ inject, apply: callback, name: callback.name })
  }
}
```

由于和`plugin`方法一样，`ctx.registry.inject`方法同样会被映射为`ctx.inject`方法，所以我们可用调用此方法注册`greet`插件并为其注入依赖服务。

```typescript
async function main() {
  const ctx = new Context();
  const rl = readline.createInterface({
      input: process.stdin,
      output: process.stdout}); 

  rl.question("Enter time of day:", (answer) => {   
    ctx.inject(["timeOfDay"], ctx=>console.log(`Good, ${ctx.timeOfDay.value}`));
    setTimeout(()=>ctx.plugin(TimeOfDayService,answer), 5000);
    });
};
```

## 5. 动态修改服务配置

上面注册的服务都是一个手工创建的对象，其实服务和插件一样，也有直接的配置，也需要采用配置与实现分离的方式进行设计。Cordis提供了相应的API帮助我们动态修改指定服务的配置。

### 5.1 调用Context的intercept方法修改配置

`Context`直接定义了如下的`intercept`方法对服务的配置进行动态修改。

```typescript
export class Context {
  intercept<K extends InjectKey>(name: K, config: Context[K] extends { [symbols.config]: infer T } ? T : never): this
  intercept(name: string, config: any): this  
  intercept(name: string, config: any) {
    const intercept = Object.create(this[symbols.intercept])
    intercept[name] = config
    return this.extend({ [symbols.intercept]: intercept })
  }
}
```

`intercept`方法的两个参数分别表示**服务的注册名称**和**配置对象**。该方法针对配置的修改**并不会影响正在使用的服务实例**。从方法的实现可用看出，它仅仅是调用`extend`方法创建了一个子`Context`，该`Context`具有拥有自己的配置字典，对应属性的Key为通过`symbols.intercept`预定义的Symbol。所有只有后续使用这个子Context，修改的服务配置才会起作用。

在如下的演示程序中，我们为`TimeOfDayService`的`value`从原来的属性改写成一个只读访问器，它会利用`symbols.intercept`常量从`Context`中得到上述的被拦截注入的配置字典，并利用服务注册的名称作为Key提取针对当前服务的配置。在`main`函数中，我们按照上述的方式针对根`Context`创建了一个`TimeOfDayService`对象，并注册了`greet`插件函数。接下来我们调用`Context`的`intercept`方法完成了针对服务配置的两次修改，并随后在新创建的子`Context`中重新注册了`greet`插件。

```typescript
import { Context, Service, symbols } from '@deepseek-ai/cordis'
class TimeOfDayService extends Service {
  _config: {value:string};
  get value(){
    const intercept = this.ctx[symbols.intercept];
    const config =  (intercept["timeOfDay"] ?? this._config) as {value:string};
    return config.value
  }
  constructor(ctx: Context, config: { value: string } = {value:"morning"}) {
    super(ctx, "timeOfDay")
    this._config = config;
  }
}

declare module '@deepseek-ai/cordis' {
  interface Context {
    timeOfDay: TimeOfDayService
  }
}

function greet(ctx: Context) {
  console.log(`Good, ${ctx.timeOfDay.value}`)
}

async function main() {
  let ctx = new Context()
  new TimeOfDayService(ctx);
  ctx.inject(["timeOfDay"], greet);

  ctx = ctx.intercept("timeOfDay", { value: "afternoon" });
  ctx.inject(["timeOfDay"], greet);

  ctx = ctx.intercept("timeOfDay", { value: "evening" });
  ctx.inject(["timeOfDay"], greet);
}

main()
```

输出：

```bash
Good, morning
Good, afternoon
Good, evening
```

### 5.2 在inject方法中指定配置

到目前为止，我们针对`inject`方法的调用都是为注册的插件指定注入的服务名称列表，其实该方法中可用直接指定注入服务对应的配置。所以上面的演示程序可用进一步简化成如下的形式：

```typescript
async function main() {
   let ctx = new Context()
   new TimeOfDayService(ctx);
  
   ctx.inject({timeOfDay:{ value: "morning" }}, greet);
   ctx.inject({timeOfDay:{ value: "afternoon" }}, greet);
   ctx.inject({timeOfDay:{ value: "evening" }}, greet);
}
```
