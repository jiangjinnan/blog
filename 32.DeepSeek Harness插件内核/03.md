# [DeepSeek Harness插件内核-03]利用Fiber管理Context和插件的生命周期

在Cordis中，管理插件与上下文生命周期的核心引擎并不是传统应用中的全局注册表，而是一个名为Fiber的状态机与执行单元。作为Context和Plugin生命周期的真正管理者。每一个被加载的插件实例，在Cordis运行时中都会被包裹在一个独立的`Fiber`作用域内。`Fiber`充当了状态机的角色，负责监控插件的依赖是否满足，并精确追踪该插件在Context上创建的所有待释放资源，以便在卸载时执行资源清理和释放工作。

## 1. Fiber的创建

Cordis会在如下两种场景中创建作为生命周期管理器的`Fiber`对象。一种是直接调用构造函数创建根Context的时候，创建的`Fiber`将作为Context的`fiber`字段，并作为当前Context的生命周期管理器。

```typescript
export class Context {
  constructor() {
    ...
    this.fiber = new Fiber(self, {}, Object.create(null), null, () => [])
    ...
  }
}
```

针对`Fiber`的另一个创建场景发生在调用`RegistryService`的`plugin`方法进行插件注册的时候。实际上该方法返回的就是一个`Fiber`对象，该对象将作为**插件**专属的生命周期管理器。

```typescript
export class RegistryService {
  plugin(plugin: Plugin, config?: any, getOuterStack = buildOuterStack()) {
    ...
    const fiber = new Fiber(this.ctx, config, Inject.resolve(plugin.inject), runtime, getOuterStack)
    const wrapped = Object.create(fiber) as Fiber & PromiseLike<Fiber>
    wrapped.then = (onFulfilled, onRejected) => {
      return fiber.await().then(onFulfilled, onRejected)
    }
    return wrapped
  }
}
```

## 2. 执行操作收集待释放资源

`Fiber`提供了如下两个核心的重载方法`effect`，我们将交给Fiber执行的操作封装成一个函数提交给这个effect方法，并利用此函数返回的函数执行如下的清理工作：

- 释放操作执行过程中分配的资源；
- 释放针对全局或者外部兑现的引用，比如注册的事件处理函数；
- 复位操作修改的一些配置选项。

执行的操作通过`execute`参数传入的函数表示，它可利用返回一个`SyncEffect<any>`或者`AsyncEffect<any>`类型的对象，其中`SyncEffect<T>`和`AsyncEffect<T>`分别是针对`Disposable<T>`与`Iterable<Disposable<T>, void, void>`以及`Promise<Disposable<T>>`与`AsyncIterable<Disposable<T>, void, void>`的联合类型。我们在调用这两个方法的时候还可以指定一个可选的诊断标签。

```typescript
export class Fiber {
  effect(execute: () => SyncEffect, label?: string): Disposable<Promise<void>>
  effect(execute: () => Effect, label?: string): AsyncDisposable<Promise<void>>
}

export type Effect<T = any> =
  | SyncEffect<T>
  | AsyncEffect<T>

type SyncEffect<T = any> =
  | Disposable<T>
  | Iterable<Disposable<T>, void, void>

type AsyncEffect<T = any> =
  | Promise<Disposable<T>>
  | AsyncIterable<Disposable<T>, void, void>

type Disposable<T = any> = () => T
interface AsyncDisposable<T extends Awaitable<void> = Awaitable<void>> extends PromiseLike<() => T> {
  (): T
}
```

两个重载的`effect`方法分别返回一个通过`Disposable<Promise<void>>`和`AsyncDisposable<Promise<void>>`表示的函数，我们可以直接执行它们完成清理工作。在如下的演示程序中，我们调用根Context的`fiber`的`effect`方法利用创建的`timer`以1秒为间隔输出当前时间。作为`execute`参数的函数返回另一个用来清理计时器的函数。在得到`effect`方法返回的`Disposable`类型的函数后，我们在**5**秒后执行它实现对计时器的清理。

```typescript
import { Context } from '@deepseek-ai/cordis'
const ctx = new Context();
const disposable = ctx.fiber.effect(()=>{
    const timer = setInterval(()=>console.log(new Date()),1000);
    return ()=> {
        console.log("Clear the timer...")
        clearInterval(timer);
        }
});
setTimeout(()=>disposable(), 5000);
```

输出：

```text
2026-08-25T15:45:04.915Z
2026-08-25T15:45:05.926Z
2026-08-25T15:45:06.933Z
2026-08-25T15:45:07.942Z
Clear the timer...
```

`ctx.fiber.effect`方法会被映射为`ctx.effect`方法，我们通常会调用后者以简化代码。

## 3. 调用Fiber的dispose方法执行清理工作

`effect`方法返回的`Disposable`对象还会被`Fiber`对象收集起来，我们可以如下的方式调用`Fiber`对象的`dispose`方法也能完成最终的清理工作：

```typescript
import { Context } from '@deepseek-ai/cordis'
const ctx = new Context();
ctx.fiber.effect(()=>{
    const timer = setInterval(()=>console.log(new Date()),1000);
    return ()=> {
        console.log("Clear the timer...")
        clearInterval(timer);
        }
});

setTimeout(()=>{
   ctx.fiber.dispose();
}, 5000);
```

输出：

```bash
2026-08-25T15:55:06.461Z
2026-08-25T15:55:07.462Z
2026-08-25T15:55:08.477Z
2026-08-25T15:55:09.487Z
Clear the timer...
```

## 4. 重启插件

`Fiber`提供了用于重启的`restart`方法，我们可以利用它重启注册的插件。以如下的演示程序为例，我们利用在根Context注册了一个插件，它以一秒为间隔输出从1开始的自增数字。我们在4秒之后重启得到的`Fiber`对象。为了真正终止之前正在执行的插件，我们在重启`Fiber`时必须释放之前创建的计时器。

```typescript
import { Context } from '@deepseek-ai/cordis'

const ctx = new Context();
var timeout: NodeJS.Timeout
const fiber = ctx.plugin(ctx =>{
    let counter = 1;
    const timer = setInterval(()=>console.log(counter ++),1000);
    timeout = setTimeout(()=>{
        console.log("Restart plugin...")
        timer.close();
        timeout?.close();
        fiber.restart();
    }, 4000);
});
```

输出：

```bash
1
2
3
Restart plugin...
1
2
3
Restart plugin...
1
2
...
```

由于`Fiber`的`restart`方法在执行重启过程中对当前对象实施**卸载（Unload）**， 其中会涉及针对`dispose`方法的调用。我们在[DeepSeek Harness插件内核-01：DeepSeek Harness三种插件形式](https://blog.csdn.net/JaydenAI/article/details/164044310)中就已经说过：插件函数返回的函数会在`Fiber`的`dispose`方法被调用时作为清理插件的操作被执行。所以上面演示程序中针对计时器的关闭最好采用如下的形式来完成。

```typescript
import { Context } from '@deepseek-ai/cordis'

const ctx = new Context();
const fiber = ctx.registry.plugin(ctx =>{
    let counter = 1;
    const timer = setInterval(()=>console.log(counter ++),1000);
    return ()=>timer.close();
});
setInterval(()=>{    
    console.log("Restart plugin...")
    fiber.restart();
}, 4000);
```

输出：

```bash
1
2
3
Restart plugin...
1
2
3
Restart plugin...
1
2
...
```

## 5. 修改插件配置

如果需要动态修改插件的配置，我们可以调用插件绑定`Fiber`对象的`update`方法。以如下的演示程序为例，我们利用根`Context`的`RegistryService`注册了一个插件，该插件会以一秒的间隔输出一条问候语。问候语的时间部分来源于配置对象的`timeOfDay`字段。在完成插件注册的4秒和8秒后，我们分别调用`Fiber`对象的`update`方法修改了配置。配置修改之后，如果当前`Fiber`对象仍处于激活状态，它将会重启并应用新的配置。

```typescript
import { Context } from '@deepseek-ai/cordis'

const ctx = new Context();
const fiber = ctx.plugin((ctx, config) =>{
    const timeOfDay = (config as {timeOfDay:string})?.timeOfDay??"morning";
    const timeout = setInterval(()=>  console.log(`Good ${timeOfDay}!`), 1000);
    return  ()=>timeout.close();
});

setTimeout(()=>{
    fiber.update({timeOfDay: "afternoon"})
}, 4000);

setTimeout(()=>{
    fiber.update({timeOfDay: "evening"})
}, 8000);
```

输出：

```bash
Good morning!
Good morning!
Good morning!
Good afternoon!
Good afternoon!
Good afternoon!
Good evening!
Good evening!
...
```
