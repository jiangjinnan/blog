# [DeepSeek Harness深度拆解-03]创建一个新的Profile提供自定义插件

[DeepSeek Harness深度拆解-02:Profile究竟是什么？](https://blog.csdn.net/JaydenAI/article/details/165281763)对DSH的Profile进行详细介绍，我们知道表面上看Profile是为DSH程序提供了针对不同运行形态和交互方式，但本质上它就是提供一组插件的配置而已。为了对Profile具有更加深刻的认识，我们决定创建一个全新的Profile，并利用它来提供我们自定义的插件。

## 1. 在源码上定义插件

[DeepSeek Harness深度拆解-01：DSH是如何跑起来的？](https://blog.csdn.net/JaydenAI/article/details/165280678)演示了如何以源码的形式启动DSH，现在我们就在源码基础上创建一系列在自定义Profile中使用的插件。我们在相对于源代码根目录的`./packages`目录下创建一个名为`demo`的子目录，并在其中定义了如下所示的目录结构：

```markdown
./packages/demo/
├── base/
│   ├── src/  
│   │    └──index.ts
|   ├── cordis.patch.yml
|   ├── package.json
|   └── tsconfig.json
├── foo/
│   ├── src/  
│   │    └──index.ts
|   ├── package.json
|   └── tsconfig.json
├── bar/
│   ├── src/  
│   │    └──index.ts
|   ├── package.json
|   └── tsconfig.json
├── baz/
│   ├── src/  
│   │    └──index.ts
|   ├── package.json
|   └── tsconfig.json
├── qux/
│   ├── src/  
│   │    └──index.ts
|   ├── package.json
|   └── tsconfig.json
└── utils/
    ├── src/  
    │    └──index.ts
    ├── package.json
    └── tsconfig.json
```

其中`foo`、`bar`、`baz`和`qux`用来提供四个对应的插件，它们会调用定义在`utils`的一些公共函数。这四个插件构建的插件树最终利用`base`提供的补丁文件`cordis.patch.yml`进行构建。

### 1.1 输出插件的路径和来源

我们在`utils/src/index.ts`中定义了如下这个工具函数`printPlunginPath`来输出当前插件在插件树中的路径。如代码所示，作为函数参数的`Context`为插件绑定的`Context`，所谓的插件路径本质上就是`Context`的路径。我们从`Context`中提取`Fiber`对象，进而提取出代表插件运行时的`Plugin.Runtime`对象，并使用其名称作为节点名称。参数`source`是手工指定的表示插件来源的字符串。

```typescript
import { Context } from '@deepseek-ai/cordis'

export function printPlunginPath(ctx: Context, source:string) {
  const plugins: string[] =[];
  let fiber = ctx.fiber
  while(true){
    if(fiber == fiber.parent.fiber || !fiber.runtime?.name){
      break;
    }
    plugins.unshift(fiber.runtime?.name??"")
    fiber = fiber.parent.fiber;
  }
  console.log(`${plugins.join(">")}[${source}]`);
}
```

如下所示的分别是`package.json`和`tsconfig.json`定义。`package.json`中将包名设置为`@jaydenai/utils`,并定义了用来编译的`build`脚本。`tsconfig.json`直接在现有的基础配置`tsconfig.base.json`上扩展。

```json
{
  "name": "@jaydenai/utils",
  "private":true,
  "type": "module",
  "main": "lib/index.js",
  "types": "lib/index.d.ts",
  "exports": {
        ".": {
            "types": "./lib/index.d.ts",
            "default": "./lib/index.js"
        }
    },
    "dependencies": {
      "@deepseek-ai/cordis": "workspace:*"
    },
  "scripts": {
    "build": "tsc -b tsconfig.json --force"
  }
}
```

```json
{
  "extends": "../../../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": "src",
    "outDir": "lib"
  },
  "include": [
    "src"
  ],
  "references": [
    {
      "path": "../../../vendor/cordis"
    }
  ]
}
```

### 1.2 定义四个插件

四个插件（`foo`、`bar`、`baz`和`qux`）具有完全相同的定义，所以我们只给出插件`foo`相关定义和配置。如下所示的是定义在`foo/src/index.ts`针对插件`foo`的定义。我们导出了表示插件名称的常量和插件函数`apply`。我们利用插件的配置（对应插件函数`apply`的`config`参数）来提供插件来源，并直接调用上面定义的`printPlunginPath`函数将插件的路径和来源输出来。

```typescript
import { Context } from '@deepseek-ai/cordis'
import { printPlunginPath } from '@jaydenai/utils'

export const name = 'foo'
export function apply(ctx: Context, config:{source:string}) {
  printPlunginPath(ctx,config.source);
}
```

如下所示的分别是`package.json`和`tsconfig.json`定义。`package.json`中将包名设置为`@jaydenai/foo`（其余插件对应的包也采用这种模式命名）,并定义了用来编译的`build`脚本。

```json
{

  "private":true,
  "type": "module",
  "main": "lib/index.js",
  "types": "lib/index.d.ts",
  "exports": {

        }

  "dependencies": {
      "@jaydenai/utils": "workspace:*"
  },

    "build": "tsc -b tsconfig.json --force"
  }
}
```


### 1.3 插件树的构建

DSH将基础插件整合在`@deepseek-ai/dsh-base`这个包中，我们也采用类似的做法将上述四个插件整合在一个名为`@jaydenai/base`包中，对应`./packages/demo/base`目录。其`base/src/index.ts`代码只需要导出一个空对象即可，核心在如下的`cordis.patch.yml`文件，它将四个插件整合成具有层次结构的插件树。

```yaml
- insert:
    - id: plugin1
      name: '@jaydenai/foo'
      config:
        source: package.json
    - id: plugin2
      name: '@jaydenai/bar'
      config:
        source: package.json
    - id: group1
      name: cordis:group
      group: true
      config:         
        - id: plugin3
          name: '@jaydenai/baz'
          config:
            source: package.json
        - id: group2
          name: cordis:group
          group: true
          config:         
            - id: plugin4
              name: '@jaydenai/qux'
              config:
                source: package.json
```

这个`cordis.patch.yml`文件构建的插件树由四个插件节点（`plugin1`、`plugin2`、`plugin3`和`plugin4`）和两个插件组节点（`group1`和`group2`）组成。每个插件利用通过配置（`config`）将来源设置为`package.json`（表明来源于Profile对应的`package.json`文件）。值得一提的是，作为组的名称被统一设置为`cordis:group`这个预定义的名称。整个插件树的结构如下：

```markdown
root
├── plugin1(foo)
├── plugin2(bar)
└── group1
   ├── plugin3(baz)
   └──group2
        └── plugin4(qux)
```

照例给出`package.json`和`tsconfig.json`的定义：

```json
{
  "name": "@jaydenai/base",
  "private":true,
  "type": "module",
  "main": "lib/index.js",
  "types": "lib/index.d.ts",
  "exports": {
        ".": {
        "types": "./lib/index.d.ts",
        "default": "./lib/index.js"
        }
    },
    "dsh": {
        "bundle": {
            "patch": "./cordis.patch.yml"
        }
    },
    "dependencies": {
        "@jaydenai/foo": "workspace:*",
        "@jaydenai/bar":"workspace:*",
        "@jaydenai/baz": "workspace:*",
        "@jaydenai/qux":"workspace:*"
    },
  "scripts": {
    "build": "tsc -b tsconfig.json --force"
  }
}
```

```json
{
  "extends": "../../../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": "src",
    "outDir": "lib"
  },
  "include": [
    "src"
  ],
  "references": [
    {
      "path": "../../../vendor/cordis"
    },

      "path": "../foo"
    },
    {
      "path": "../bar"
```

### 1.4 为入口程序添加针对`@jaydenai/base`的依赖

我们知道DSH的如何程序指向`apps/cli/src/bin.ts`这个TypeScript文件，为了让我们创建的Profile能够找到提供基础插件的`@jaydenai/base`包，我们只需要为在项目`apps/cli`对应的`packakge.json`以如下的方式添加针对这个包的依赖。

```json
{
  "name": "@deepseek-ai/dsh",
  ...
  "dependencies": {
    "@jaydenai/base": "workspace:^",
    ...
  }
}
```

## 2. 创建自定义的Profile

我们将创建的Profile命名为`test`，所以我们需要在`$DSH_HOME/profiles`目录下创建一个对应的目录，对于Windows来说，这个目录的地址为`%userprofile%.dsh/profiles/test`。按照在这个目录下添加如下四个必要的配置文件：

- **package.json**：配置用来提供插件的包，每个包会利用`dsh.bundle.patch`字段提供补丁文件；
- **cordis.patch.yml**：在上述包的基础上进一步提供额外的插件补丁；
- **cordis.yml**：为通过包和补丁构建的插件树提供一个统一的根，设置为一个空的数组即可；
- **pnpm-workspace.yaml**：pnpm 包管理器的多项目（Monorepo）工作区配置文件，可以从其他Profile目录拷贝进来。

如下所示的是`package.json`的完整定义。我们在`dsh.profile.bundles`中添加了两个包，一个是提供为DSH提供基础插件的`@deepseek-ai/dsh-base`，另一个就是上面构建的`@jaydenai/base`。`patchReload`字段被设置为`startup`，意味着不提供**热重载**的支持。

```json
{
  "name": "dsh-profile-test",
  "private": true,
  "dependencies": {},
  "dsh": {
    "profile": {
      "bundles": [        
        "@deepseek-ai/dsh-base",
        "@jaydenai/base"
      ],
      "patchReload": "startup"
    }
  }
}
```

我们在`cordis.patch.yml`这个补丁文件中按照如下的方式定义了另一套包含三个插件（`foo`、`bar`和`baz`）的插件树，并通过插件配置将来源设置成`cordis.patch.yml`。

```yaml
- insert:
    - id: plugin5
      name: '@jaydenai/foo'
      config:
        source: cordis.patch.yml
- id: group1
  insert:
    - id: plugin6
      name: '@jaydenai/bar'
      config:
        source: cordis.patch.yml
- id: group2
  insert:
    - id: plugin7
      name: '@jaydenai/baz'
      config:
        source: cordis.patch.yml
```

注入看三个插件被插入的位置：

- `foo`被至于最顶层；
- `bar`被添加到由Profile Bundles构建的标识为`group1`的组中；
- `baz`被添加到由Profile Bundles构建的标识为`group2`的组中。

## 3. 测试自定义的Profile

接下来我们以如下的方式执行`npx tsx apps/cli/src/bin.ts --profile test`以`test`作为Profile名称执行启动程序，会得到如下的输出：

```log
Loader>Include>foo[package.json]
Loader>Include>foo[cordis.patch.yml]
Loader>Include>bar[package.json]
Loader>Include>Group>bar[cordis.patch.yml]
Loader>Include>Group>baz[package.json]
Loader>Include>Group>Group>baz[cordis.patch.yml]
Loader>Include>Group>Group>qux[package.json]
```

上面的输出来源于注册在Profile的七个插件，其中四个来源于`package.json`，其余三个来源于`cordis.patch.yml`，整个插件树正式它们合并后的产物，它的整个结构服务我们如下的预期：

```markdown
root
├── plugin1(foo)
├── plugin2(bar)
├── plugin5(foo)
└── group1
   ├── plugin3(baz)
   ├── plugin6(baz)
   └──group2
      ├── plugin4(qux)
      └── plugin7(baz)
```

到目前位置，我们可以看到Profile提供了插件的两种来源，它们分别由注册到`package.json`中的补丁文件和自身的补丁文件`cordis.patch.yml`提供。DSF最终构建的插件还有其它的来源，这是[DeepSeek Harness深度拆解-04:完整的插件配置树如何构建？](https://jaydenai.blog.csdn.net/article/details/165428487)重点讲述的内容。
