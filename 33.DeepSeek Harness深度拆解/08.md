# [DeepSeek Harness深度拆解-08]如何实现在自定义的逻辑范围内的隔离

DSH建立在Cordis之上，而Cordis应用的核心就是具有层级结构的`Context`树。我们可以调用`isolate`方法基于指定的`Context`创建一个子`Context`，后者利用`symbols.isolate`字典提供服务名称和实例标识的映射，进而实现基于服务注册的隔离。但是这种隔离机制对于DSH来说是远远不够的。除了这种基于`Context`树结构的物理隔离，我们还需要一种逻辑隔离，即在逻辑上构建一个同样具有层级结构的Scope树，并动态地将每个Scope节点映射到对应的`Context`。`@deepseek-ai/dsh-scope`这个包正是基于这样的目的设计的。利用它提供的基于Scope的隔离机制，使我们可以将事件通知和资源注册限定在某个范围内，而这个范围并不需要映射到整个Context树的子树。比如我们在DSH中承载了A和B两个Agent，我们希望A和B不能监听来自对方的事件，它们之间注册的工具也应该独享，这样不仅保存两者之间隔离性，还解决了命名冲突的问题。总得来说，构建一个逻辑意义上的Scope树，并实现如下两个特性：

- **事件向上传递**：上级Scope能观察所有下级Scope的事件，不用逐个订阅;
- **注册向下继承**：下级Scope读取注册在上级Scope中的资源，上级Scope不用为每个下级Scope重复注册。

这篇文章旨在介绍基本的编程模式，[下一篇](https://jaydenai.blog.csdn.net/article/details/166327421)将对整个基于Scope的隔离机制的设计和实现原理进行深入介绍。

## 1. 事件向上传递

为了对`@deepseek-ai/dsh-scope`提供的基于Scope的隔离具有一个大概的认识，我们通过两个实例来演示上述的两个特性。如下这个程序就很好地体现了**事件向上传递**的特性。

```typescript
import { Context, symbols } from '@deepseek-ai/cordis'
import {createScope, bindScopeParent,scopeTarget,ScopeKey, Scoped, Scope} from '@deepseek-ai/dsh-scope'

declare module '@deepseek-ai/cordis'{
    interface Events {
      'test'(this: Scoped<{}>, scope:string): void
    }
}

const ctx = new Context()
const scopeKeys = new Map<string, ScopeKey>()
const scopes = new Map<string, Scope>()
for(const key of ["foo","bar","baz"]){
    const scopeKey = {id:key}
    const scope = createScope(ctx, scopeKey)
    scope.ctx.on("test",scope=>console.log(`[${key}]recive event test from scope '${scope}}'`))
    scopeKeys.set(key, scopeKey)
    scopes.set(key, scope)
}

const filterable = {[symbols.filter](ctx: Context): boolean {
    return true
  }
}
function emit(scope: string){
   console.log(`\nemit event 'test' from scope '${scope}'`)
   const target = scopeTarget(filterable, scopeKeys.get(scope))
   ctx.emit(target,"test",scope)
}

function buildScopeSerial(serial:string[]){
    for(let index = serial.length -1 ; index > 0; index--){
        const child = scopeKeys.get(serial[index]!)
        const parent = scopeKeys.get(serial[index -1]!)
        bindScopeParent(child!, parent!)
    }
}

buildScopeSerial(["foo","bar","baz"])
emit("foo")
emit("bar")
emit("baz")
```

如代码所示，我们创建了`scopeKeys`和`scopes`两个字典。前者用来保存作为三个Scope（`foo``bar`和`baz`）的标识，具体是一个`ScopeKey`对象（`ScopeKey`是`object`的别名，所以可以使用任意对象来标识一个Scope），后者存储的则是通过`createScope`函数针对指定的`Context`和`ScopeKey`构建的Scope对象。这里我们指定同一个根`Context`作为参数调用`createScope`函数，该函数最终会创建一个子`Context`，并绑定到创建的Scope对象的`ctx`字段上。我们在三个Scope的`ctx`字段上注册了名为`test`的事件处理函数，它们会输出一段表明事件触发和监听所在Scope的文字。

`emit`函数针对指定的Scope发出上述的`test`事件，这里会使用到`@deepseek-ai/dsh-scope`提供的一个名为`scopeTarget`函数。该函数用来针对指定的Scope创建作为事件分发的目标对象。对于事件监听方来说，该对象最终会作为事件监听函数的执行上下文（`this`）。`scopeTarget`函数的第一个对象的唯一作用就是利用其`symbols.filter`方法对作为事件处理器的`Hook`对象实施过滤。最终选择出来的`Hook`是针对它和Scope**双重过滤**的结果。这里我们指定了一个`filterable`对象，它的`symbols.filter`方法直接返回`true`，意味着最终的过滤逻辑完全由Scope决定。如果此方法返回`false`，意味着事件将不会监听到，如果没有此方法等同于返回`true`。

另一个辅助方法`buildScopeSerial`用来构建所谓的Scope树，不过这里构建的是一个表示三代单传的Scope序列。该序列最终是通过调用`@deepseek-ai/dsh-scope`提供的另一个名为`bindScopeParent`的函数，它利用提供的两个`ScopeKey`构建了两个Scope的父子关系（两个参数分别为子和父）。我们最终调用此函数构建了`foo>bar>baz`祖孙三代的关系，然后分别以`foo`、`bar`和`baz`作为Scope调用`emit`触发`test`事件，并最终得到如下的输出:

```bash
emit event 'test' from scope 'foo'
[foo]recive event test from scope 'foo}'

emit event 'test' from scope 'bar'
[foo]recive event test from scope 'bar}'
[bar]recive event test from scope 'bar}'

emit event 'test' from scope 'baz'
[foo]recive event test from scope 'baz}'
[bar]recive event test from scope 'baz}'
[baz]recive event test from scope 'baz}'
```

## 2. 利用`scopeTarget`函数的参数实施过滤

上面的输出体现了事件向上传递的特性：以某个Scope名义发起的事件只能在被自己和前辈范围内被监听到。我们可以进一步演示`scopeTarget`函数第一个参数针对事件监听器的过滤。如下面代码所示，我们对`filterable`对象的`symbols.filter`方法定义成如下形式：用来确定指定的`Context`是否通过`disabled`属性将自己禁用。在调用触发事件之前，我们将`Context`的`disabled`属性设置为`false`，然后在针对`baz`这个Scope触发事件之前，将其设置为`true`。从输出可以看出，以`baz`名义触发的事件不会被监听到。

```typescript
const filterable = {[symbols.filter](ctx: Context): boolean {
    return (ctx as any).disabled !== true
  }
}
...

Object.defineProperty(ctx,"disabled", { value: false, writable:true})
emit("foo")
emit("bar")
Reflect.set(ctx,"disabled", true)
emit("baz")
```

输出：

```bash
emit event 'test' from scope 'foo'
[foo]recive event test from scope 'foo}'

emit event 'test' from scope 'bar'
[foo]recive event test from scope 'bar}'
[bar]recive event test from scope 'bar}'

emit event 'test' from scope 'baz'
```

## 3. 注册向下继承

很多情况下我们需要在DSH中定义各种类型的注册表，比如为不同的Agent注册的工具、提示词模板以及其他资源。如果注册的主体对象存在层级关系，我们希望下级能够继承所有注册在上级的资源。这就需要使用到`@deepseek-ai/dsh-scope`提供的`ScopedLayers<T>`类型。一个`ScopedLayers<T>`对象包含一组`ScopeLayer<T>`，每个`ScopeLayer<T>`用来存储针对单一Scope的资源。在如下的演示程序中，我们定义了如下这个实现了`ScopeLayer`接口的`PromptLayer`存储基于某个Scope的提示词模板文本。

```typescript
import {ScopeLayer,NamedEntries } from '@deepseek-ai/dsh-scope'

class PromptLayer implements ScopeLayer{
    prompts = new  NamedEntries<string>(name=>Error(`duplicate prompt '${name}' is registered.`))
    isEmpty(): boolean {
        return this.prompts.isEmpty()
    }
}
```

具体的提示词保存在`prompts`字段对应的`NamedEntries<string>`对象上。这是一个命名的注册条目字典，如果指定的命名重复，会调用构造函数中指定的函数被抛出异常。另一个`isEmpty`方法是必须实现的结构成员，用来指明注册表是否为空。真正的提示词注册表体现在如下这个`PromptRegistry`类型上，其核心是通过`layers`字段返回的`ScopedLayers<PromptLayer>`对象。构造该对象时以参数的形式指定了两个函数，前者为以Lazy loading形式执行的用来创建作为**单层**的`PromptLayer`对象的工厂，后者作为注册发生改变时的回到函数。`ScopedLayers<T>`不仅拥有一组与具体Scope关联的`ScopeLayer<T>`，还拥有一个`ScopeLayer<T>`用来注册全局可用的共享条目。

```typescript
import {ScopedLayers,scopeOf} from '@deepseek-ai/dsh-scope'
class PromptRegistry{
    private layers = new ScopedLayers<PromptLayer>(
        _ => new PromptLayer(),
        function(){})

    register(ctx: Context,name:string, text:string){
       return this.layers.effect(
        ctx, 
        layer=>layer.prompts.insert(name, text),
        {label:`register_prompt:${name}`})  
    } 

    getPrompts(ctx: Context){
       return this.layers.merge(scopeOf(ctx), layer => layer.prompts)
    }
}
```

在用于注册命名提示词的`register`方法中，我们调用`layers`字段的`effect`方法返回一个用来撤销注册的函数。`effect`方法接受如下三个参数：

- 作为注册主体的`Context`；
- 一个类型为`(layer: L) => () => void`的函数用来将提供的条目注册到由`Context`决定的`ScopeLayer<T>`中：
  - 如果`Context`包含Scope，会提取或者创建对应的`ScopeLayer<T>`，然后完整针对它的注册；
  - 否则作为共享条目注册到全局`ScopeLayer<T>`中。
- 提供effect标签和是否发送通知的选项。

另一个`getPrompts`方法用来提取与指定`Context`的Scope相匹配的所有提示词，最终返回的是一个`Map<string,string>`对象。我们利用`scopeOf`函数得到指定`Context`的Scope之后，调用`layers`的`merge`方法对包括这个Scope在内及其祖先和全局Scope对应的所有`PromptLayer`进行合并。

在如下这个模拟使用`PromptRegistry`的演示程序中，我们和前面演示程序一样，构建了命名为`foo`、`bar`和`baz`的三个Scope，并调用`PromptRegistry`的`reister`方法针对这三个Scope提供的`Context`注册了对应的提示词。我们同样将三个Scope构建为`foo>bar>baz`这种三段单传的继承形式，并在最后针对它们的`Context`调用`PromptRegistry`的`getPrompts`方法将当前Scope可用的提示词读取出来。输出的结果很好地体现了表示所示的**注册向下继承**特性。

```typescript
import {ScopeKey,Scope,createScope,bindScopeParent} from '@deepseek-ai/dsh-scope'
const ctx = new Context()
const scopeKeys = new Map<string, ScopeKey>()
const scopes = new Map<string, Scope>()
const registry = new PromptRegistry()
for(const key of ["foo","bar","baz"]){
    const scopeKey = {id:key}
    const scope = createScope(ctx, scopeKey)
    scopeKeys.set(key, scopeKey)
    scopes.set(key, scope)
    registry.register(scope.ctx, key, `Prompt registered in scope ${key}`)
}

function buildScopeSerial(serial:string[]){
    for(let index = serial.length -1 ; index>0; index--){
        const child = scopeKeys.get(serial[index]!)
        const parent = scopeKeys.get(serial[index -1]!)
        bindScopeParent(child!, parent!)
    }
}

buildScopeSerial(["foo","bar","baz"])
for(const key of ["foo","bar","baz"]){
    const context = scopes.get(key)?.ctx
    console.log(`\nget prompts from scope ${key}`)
    for(const [name, text] of  registry.getPrompts(context!)!){
        console.log(`${name}:${text}`)
    }
}
```

输出：

```bash
get prompts from scope foo
foo:Prompt registered in scope foo

get prompts from scope bar
foo:Prompt registered in scope foo
bar:Prompt registered in scope bar

get prompts from scope baz
foo:Prompt registered in scope foo
bar:Prompt registered in scope bar
baz:Prompt registered in scope baz
```

## 4. 提供全局注册和撤销注册

上面我们说过，当我们调用`ScopedLayers<T>`对象的`effect`方法时，如果提供的`Context`并没有携带任何的Scope信息，此时的注册会添加到全局共享的`ScopeLayer`上。所以如果我们按照如下的方式将根`Context`作为参数调用`PromptRegistry`对象的`register`方法，最终合并的提示词将会多此一条。上面的演示程序还体现了针对注册的撤销，我们只需要调用`PromptRegistry`对象的`register`方法返回的清理函数，所有完成的注册都将一扫而空，这符合Cordis一贯的设计风格。

```typescript
...
const dispose = registry.register(ctx, "shared","Shared prompt" )
for(const key of ["foo","bar","baz"]){
    const context = scopes.get(key)?.ctx
    console.log(`\nget prompts from scope ${key}`)
    for(const [name, text] of  registry.getPrompts(context!)!){
        console.log(`${name}:${text}`)
    }
}
console.log(`----------unregister global----------`)
dispose()
for(const key of ["foo","bar","baz"]){
    const context = scopes.get(key)?.ctx
    console.log(`\nget prompts from scope ${key}`)
    for(const [name, text] of  registry.getPrompts(context!)!){
        console.log(`${name}:${text}`)
    }
}
```

```log

shared:Shared prompt
foo:Prompt registered in scope foo

get prompts from scope bar
shared:Shared prompt
foo:Prompt registered in scope foo
bar:Prompt registered in scope bar

foo:Prompt registered in scope foo
```
