# [GraphRAG实现原理-02]基于社区（Community）的知识图谱

GraphRAG的知识图谱并非简单的**节点-边**二元结构，而是一个由 Entity（实体）、Relationship（关系）、Claim/Covariate（声明/协变量）、Community（社区）和Community Report（社区报告） 五层要素构成的、兼具细粒度事实与宏观主题的层次化知识体系。它们分别承担着“点”、“线”、“细节”、“团块”和“摘要”的角色。就索引生成的产物来说，这五个要素通过.parquet文件对应的列式表格来维护，

## 1. 从索引输出了解知识图谱的五要素

我们编写了如下这个print_table辅助函数加载对应的`.parquet`文件并将其转换成DataFrame，并输出其结构和前5条记录。

```python
import pandas as pd

def print_table(fileName:str):
    df = pd.read_parquet(f"./output/{fileName}")
    print("\n----------schema----------")
    print(df.info(memory_usage=False, show_counts=False))
    print("\n----------data----------")
    for _, row in df.head(5).iterrows():
        for col in df.columns:
            print(f"{col}: {row[col]}, ")
        print() 
```

## 3. Relationship：连接实体的结构边

Relationship（关系）是实体之间的连接线，描述两个实体之间明确的、被文本所支持的关联。它的存在使得知识图谱能够支撑多跳推理，将分散在不同文档中的信息连接起来。一条关系通常包含：

- 源实体与目标实体；
- 关系描述：解释二者之间联系的具体内容；
- 溯源信息：该关系被哪些源文本片段所支持。

## 4. Claim/Covariate：附着于实体的事实性细节

这是GraphRAG中一个独特且精细的层次。在代码库中，该类被命名为Covariate（协变量），但在实际应用中，它最常用于表示Claim（声明），即关于实体的、具体的、可核实的事实性断言。Claim的核心特征在于其**事实性**”与“时间敏感性：

- 结构化的事实单元：一条Claim通常包含主体（所描述的实体）、描述（断言内容）、状态（如已核实/存疑）、起止时间、源文本片段以及置信度分数等元数据；
- 补充图谱细节：如果说实体和关系构建了图谱的“骨架”，那么Claim则为这个骨架填充了“血肉”，提供了精确的事实性细节，极大增强了回答的可溯源性和准确性；
- 时间性：Covariate特别适合表达*在特定时间段内为真*的陈述（如*某人在某年担任某职*），这是传统三元组难以优雅处理的。

## 5. Community：层次化的语义集群

Community（社区）是将图谱中连接紧密的实体进行聚类后形成的**团块**。GraphRAG通常使用Leiden算法在实体关系图上进行层次化社区检测，递归地将图划分为子社区，直至叶子节点，形成一个父子关系的树状结构。每个社区聚合了其成员的相关信息：

- 成员构成：包含的实体ID、内部关系ID以及相关的源文本单元ID；
- 层次属性：层级（level）、父社区ID、子社区列表。低层级社区更具体，高层级社区代表更宽泛的主题；
- 主题标题：概括该社区核心主题的名称；
- 关联声明：社区内实体所关联的Claim信息；
- 社区结构的意义在于，它将一个可能包含成千上万节点的扁平图谱，转变为可分层导航的主题地图，为全局性问题的回答奠定了基础。

## 6. Community Report：社区的LLM生成摘要

Community Report（社区报告）是对每个社区内容进行LLM摘要后生成的自然语言报告。它是连接结构化图谱与语言模型的关键接口，使得图谱的宏观结构能够被LLM直接**阅读**和利用。一份典型的社区报告包含：

- 标题（Title）：该社区的核心主题；
- 摘要（Summary）：对社区整体结构、实体间关系以及重要信息的执行摘要；
- 影响严重性评级（Impact Severity Rating）：一个用于评估社区信息重要性的分数；
- 完整内容：更详尽的发现与描述。

社区报告的核心价值体现在全局搜索（Global Search）中。面对*数据集的主要主题是什么？*这类需要聚合全局信息的问题，系统不再检索所有文本块，而是在预生成的社区报告层面进行Map-Reduce，高效地合成一个全面的回答。由于报告是预计算的，全局查询的复杂度与社区数量（`O(clusters)`） 相关，而非节点数量（`O(nodes)`），这使其具备了良好的可扩展性。

## 7.总结

这五个概念在GraphRAG的索引流水线中依次生成并相互嵌套，共同构成一个从微观到宏观的完整知识体系。

| 层次 | 要素 | 在知识图谱中的角色 | 核心价值 |
| :--- | :--- | :--- | :--- |
| **微观/事实层** | **Entity** | 图谱的**节点** | 提供可检索、可定位的锚点 |
| **微观/事实层** | **Relationship** | 节点间的**边** | 建立结构连接，支撑多跳推理 |
| **微观/事实层** | **Claim / Covariate** | 附着于节点的**事实细节** | 补充精确的、时间敏感的事实性断言 |
| **宏观/结构层** | **Community** | 节点的**层次化聚类** | 将扁平图谱组织为可导航的主题地图 |
| **摘要/接口层** | **Community Report** | 社区的**LLM自然语言摘要** | 作为结构化知识与LLM的接口，支撑高效的全局查询 |

简而言之，GraphRAG通过Entity和Relationship捕获细粒度的事实结构，通过Claim/Covariate嵌入可核实的事实细节，再通过Community将这些微观结构组织成层次化的主题集群，最后以Community Report的形式为语言模型提供可直接理解的宏观知识摘要。这一整套设计，使其能够同时胜任需要精确定位的局部查询和需要全局视野的聚合性查询。
