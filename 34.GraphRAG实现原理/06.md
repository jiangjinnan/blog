# [GraphRAG实现原理-06]将各种格式的数据源转换成标准文档

[GraphRAG实现原理-04:构建知识图谱的索引管道](https://jaydenai.blog.csdn.net/article/details/169133995)详细介绍了用来构建知识图谱的索引管道以及创建方式，我们知道GraphRAG默认构建了四条索引管道，其中两条（`standard`和`fast`）针对全量初始化索引，另外两条（`standard-update`和`fast-update`）针对增量更新索引。`standard`和`fast`的区别主要体现在前者使用LLM来构建知识图谱，后者则使用传统的NLP的做法，索引后者更快且免费。为了让大家对管道的完整执行流程由一个深刻认识，我决定利用本篇和后续一系列的文章介绍组成`standard`管道的每个`Workflow`。

## 1. standard管道的组成

我们回顾一下[GraphRAG实现原理-04:构建知识图谱的索引管道](https://jaydenai.blog.csdn.net/article/details/169133995)介绍的针对四种管道注册的代码。如代码所示，`standard`管道一共由10个`Workflow`按照执行的顺序构建而成。

```python
_standard_workflows = [
    "create_base_text_units",
    "create_final_documents",
    "extract_graph",
    "finalize_graph",
    "extract_covariates",
    "create_communities",
    "create_final_text_units",
    "create_community_reports",
    "generate_text_embeddings",
]
_fast_workflows = [
    "create_base_text_units",
    "create_final_documents",
    "extract_graph_nlp",
    "prune_graph",
    "finalize_graph",
    "create_communities",
    "create_final_text_units",
    "create_community_reports_text",
    "generate_text_embeddings",
]
_update_workflows = [
    "update_final_documents",
    "update_entities_relationships",
    "update_text_units",
    "update_covariates",
    "update_communities",
    "update_community_reports",
    "update_text_embeddings",
    "update_clean_state",
]
PipelineFactory.register_pipeline(
    IndexingMethod.Standard, ["load_input_documents", *_standard_workflows]
)
PipelineFactory.register_pipeline(
    IndexingMethod.Fast, ["load_input_documents", *_fast_workflows]
)
PipelineFactory.register_pipeline(
    IndexingMethod.StandardUpdate,
    ["load_update_documents", *_standard_workflows, *_update_workflows],
)
PipelineFactory.register_pipeline(
    IndexingMethod.FastUpdate,
    ["load_update_documents", *_fast_workflows, *_update_workflows],
)
```

`standard`管道核心作用是将原始文档逐步转化为可供查询的知识图谱与向量索引。各工作流按数据流顺序概括如下：

- **文本加载、切分与文档关联**
  - **load_input_documents**：从`input_storage`读取原始文档（csv、text、json等），加载为统一的文档，作为整个索引流程的输入源。若调用时直接传入了`input_documents`，该步骤会被跳过。
  - **create_base_text_units**：将输入文档按token切分为文本单元（`TextUnit`），这是后续图抽取和溯源引用的基本分析单位。
  - **create_final_documents**：建立文档与文本单元之间的双向映射，形成最终的文档表，用于追踪每个文档由哪些文本块构成。

- **图抽取与整理**
  - **extract_graph**：对每个文本单元调用LLM，抽取实体与关系，并将来自不同文本单元的相同实体/关系进行合并。
  - **finalize_graph**：对抽取出的实体和关系做收尾处理，例如计算节点度数、整理最终表结构。
  - **extract_covariates**：可选地抽取**声明**（Claims）作为独立产物Covariates，该步骤默认关闭。

- **社区发现与报告生成**
  - **create_communities**：基于实体关系图，使用层次化Leiden 算法检测社区层级结构。
  - **create_community_reports**：为每个社区调用LLM生成高层摘要报告，这是Global Search等查询模式的关键依据。
  - **create_final_text_units**：整理最终的文本单元表，将实体、关系、Covariates的ID关联回各文本单元。

- **向量化**
  - **generate_text_embeddings**：为需要向量检索的产物（实体描述、文本单元、社区报告等）生成嵌入向量，并写入配置的向量存储。

## 2. 利用InputReader抽象数据源

我们首选来介绍组成管道的第一个命名为`load_input_documents`的`Workflow`，它从`input_storage`读取原始文档（csv、text、json等），加载为统一的文档，作为整个索引流程的输入源。由于原始文档的来源各异，不同的格式要求不同的加载方式，所以GraphRAG在此抽象了这个`InputReader`类型，它负责从存储中按文件模式批量加载文档，并统一转换为`TextDocument`列表，供后续索引流程使用。

```python
class InputReader(metaclass=ABCMeta):
    def __init__(
        self,
        storage: Storage,
        file_pattern: str,
        encoding: str = "utf-8",
        **kwargs,
    )
    async def read_files(self) -> list[TextDocument]
    def __aiter__(self) -> AsyncIterator[TextDocument]

    @abstractmethod
    async def read_file(self, path: str) -> list[TextDocument]:
```

初始化一个`InputReader`对象需要提供如下的参数：

- **storage**：底层存储对象，提供`find`能力，用于按正则匹配文件。[GraphRAG实现原理-03:针对Table和Storage的抽象](https://jaydenai.blog.csdn.net/article/details/169133473)提供了针对`Storage`的详细介绍。
- **file_pattern**：文件匹配模式（正则字符串），决定读取哪些文件。
- **encoding**：文件编码，默认`utf-8`。
- **kwargs**：为子类预留的扩展参数。

具体的`InputReader`类型需要重写`read_file`完成针对指定文件路径的读取，并将读取内容转换成`TextDocument`列表。通过调用`Storage`的`find`方法实现了`__aiter__`方法，所以利用`InputReader`对象可以异步的方式依次读取文件并实时输出生成的`TextDocument`。`__aiter__`方法进一步服务于`read_files`方法，后者将异步迭代生成的`TextDocument`汇总成一个列表。

作为GraphRAG体现标准的文本文档，`TextDocument`类型提供了文档的Id、文本、标题、创建时间和原始内容（字典形式）。并定义了`get`方法根据指定的字段名称（"id", "title", "text", "creation_date"和`raw_data`字典的Key）。`collect`方法用来提取指定的字段，并将其封装成返回的字典。

```python
@dataclass
class TextDocument:
    id: str
    text: str
    title: str
    creation_date: str
    raw_data: dict[str, Any] | None = None
    def get(self, field: str, default_value: Any = None) -> Any
    def collect(self, fields: list[str]) -> dict[str, Any]
```

`StructuredFileReader`是`InputReader`的一个抽象中间层，专门服务于结构化文件（如CSV、JSON），把**如何解析文件格式**与**如何把结构化行转换成 TextDocument**这两件事分离开来。子类只需负责把文件读成`list[dict]`（每行一个字典），然后调用`process_data_columns`完成统一的文档转换。

```python
class StructuredFileReader(InputReader):
    def __init__(
        self,
        id_column: str | None = None,
        title_column: str | None = None,
        text_column: str = "text",
        **kwargs,
    ):
        super().__init__(**kwargs)
        self._id_column = id_column
        self._title_column = title_column
        self._text_column = text_column

    async def process_data_columns(
        self,
        rows: list[dict[str, Any]],
        path: str,
    ) -> list[TextDocument]:
        documents = []
        for index, row in enumerate(rows):
            text = get_property(row, self._text_column)
            id = (
                get_property(row, self._id_column)
                if self._id_column
                else gen_sha512_hash({"text": text}, ["text"])
            )
            num = f" ({index})" if len(rows) > 1 else ""
            title = (
                get_property(row, self._title_column)
                if self._title_column
                else f"{path}{num}"
            )
            creation_date = await self._storage.get_creation_date(path)
            documents.append(
                TextDocument(
                    id=id,
                    title=title,
                    text=text,
                    creation_date=creation_date,
                    raw_data=row,
                )
            )
        return documents
```

初始化`StructuredFileReader`需要提供如下参数：

- **id_column**：可选，指定哪一列作为文档ID；不指定时用文本哈希生成。
- **title_column**：可选，指定哪一列作为标题；不指定时用文件名（多行时附加序号）兜底。
- **text_column**：必填语义，默认`"text"`，指定正文内容来自哪一列。
- **kwargs**：透传给父类`InputReader`（即`storage`、`file_pattern`、`encoding`）。

### 2.1 预定义的InputReader

GraphRAG针对常用的文件类型定义了对应的`InputReader`类型，如下这个`InputType`枚举的每个选项对应一个具体的类型。

```python
class InputType(StrEnum):
    Csv = "csv"
    Text = "text"
    Json = "json"
    JsonLines = "jsonl"
    MarkItDown = "markitdown"
    Parquet = "parquet"
```

六种具体的`InputReader`类型说明如下：

- **Csv**：将CSV文件的每一行读取为一条文档，支持通过`title_column`、`text_column`等配置指定列映射。
- **Text**：将每个纯文本文件整体读取为一条文档，文件名通常作为标题。
- **Json**：解析 JSON 文件结构，将其中的对象转换为文档。
- **JsonLines**：逐行解析JSON对象，适合流式数据，并会跳过格式错误的行。
- **MarkItDown**：借助 MarkItDown 库，将PDF、Office 文档、HTML 等复杂格式转换为Markdown文本来读取。
- **Parquet**：使用pyarrow读取列式Parquet文件。

基于CSV、JSON、JSONL和Parquet这四种结构化文件对应的`InputReader`类型都派生自`StructuredFileReader`，基于纯文本和Markdown的`TextFileReader`和`MarkItDownFileReader`类型则直接派生自`InputReader`。

```python
class CSVFileReader(StructuredFileReader):
    def __init__(self, file_pattern: str | None = None, **kwargs)
class JSONFileReader(StructuredFileReader):
    def __init__(self, file_pattern: str | None = None, **kwargs)
class JSONLinesFileReader(StructuredFileReader):
    def __init__(self, file_pattern: str | None = None, **kwargs)
class ParquetFileReader(StructuredFileReader):
    def __init__(self, file_pattern: str | None = None, **kwargs)
    
class TextFileReader(InputReader):
    def __init__(self, file_pattern: str | None = None, **kwargs)
class MarkItDownFileReader(InputReader)
```

除`MarkItDownFileReader`之外五个`InputReader`类型的构造函数都可以利用`file_pattern`参数指定获取指定文件的正则表达式。如果没有指定，它们分别会使用如下的表达式兜底：

- **CSVFileReader**：`.*\\.csv$`
- **JSONFileReader**：`.*\\.json$`
- **JSONLinesFileReader**：`.*\\.jsonl$`
- **ParquetFileReader**：`.*\\.parquet$`
- **TextFileReader**:`.*\\.txt$`

对于上述六种`InputReader`类型，`CSVFileReader`、`JSONLinesFileReader`和`ParquetFileReader`会为每一行创建一个`TextDocument`对象，`JSONFileReader`则会为一个顶层对象/数组元素创建一个`TextDocument`对象，`TextFileReader`和`MarkItDownFileReader`则是一个文件对应一个`TextDocument`对象。

### 2.2 InputReader的配置

GraphRAG将针对`InputReader`的配置定义在如下这个`InputConfig`类型中，`GraphRagConfig`的`input`配置节返回的就是这个对象。`InputConfig`负责声明输入文档的格式类型与列映射规则。具体使用哪种`InputReader`由type配置选项决定，默认使用的是`TextFileReader`。

```python
class GraphRagConfig(BaseModel):
    input: InputConfig = Field(
        description="The input configuration.", default=InputConfig()
    )

class InputConfig(BaseModel):
    type: str = Field(
        description="The input file type to use.",
        default=InputType.Text,
    )
    encoding: str | None = Field(
        description="The input file encoding to use.",
        default=None,
    )
    file_pattern: str | None = Field(
        description="The input file pattern to use.",
        default=None,
    )
    id_column: str | None = Field(
        description="The input ID column to use.",
        default=None,
    )
    title_column: str | None = Field(
        description="The input title column to use.",
        default=None,
    )
    text_column: str | None = Field(
        description="The input text column to use.",
        default=None,
    )
```

除`type`之外的其他配置选项说明如下：

- **encoding**：文件编码，默认`None`（读取器内部通常回退到`utf-8`）。
- **file_pattern**：文件匹配模式（正则），默认`None`（由读取器按类型提供默认模式，如`.*\.csv$`）。
- **id_column**：指定哪一列作为文档 ID，默认`None`（结构化读取器会用文本哈希兜底）。
- **title_column**：指定哪一列作为标题，默认`None`（结构化读取器会用文件名兜底）。
- **text_column**：指定哪一列作为正文，默认`None`（结构化读取器内部默认取`text` 列）。

### 2.3 InputReader的创建

GraphRAG利用如下这个`create_input_reader`工厂函数根据指定的`InputConfig`配置和作为存储的`Storage`对象来创建对应的`InputReader`对象。

```python
def create_input_reader(config: InputConfig, storage: Storage) -> InputReader:
    config_model = config.model_dump()
    input_strategy = config.type

    if input_strategy not in input_reader_factory:
        match input_strategy:
            case InputType.Csv:
                from graphrag_input.csv import CSVFileReader
                register_input_reader(InputType.Csv, CSVFileReader)
            case InputType.Text:
                from graphrag_input.text import TextFileReader

                register_input_reader(InputType.Text, TextFileReader)
            case InputType.Json:
                from graphrag_input.json import JSONFileReader

                register_input_reader(InputType.Json, JSONFileReader)
            case InputType.JsonLines:
                from graphrag_input.jsonl import JSONLinesFileReader

                register_input_reader(InputType.JsonLines, JSONLinesFileReader)
            case InputType.MarkItDown:
                from graphrag_input.markitdown import MarkItDownFileReader

                register_input_reader(InputType.MarkItDown, MarkItDownFileReader)
            case InputType.Parquet:
                from graphrag_input.parquet import ParquetFileReader

                register_input_reader(InputType.Parquet, ParquetFileReader)
            case _:
                msg = f"InputConfig.type '{input_strategy}' is not registered in the InputReaderFactory. Registered types: {', '.join(input_reader_factory.keys())}."
                raise ValueError(msg)

    config_model["storage"] = storage
    return input_reader_factory.create(input_strategy, init_args=config_model)
```

## 3. Workflow

在了解了`InputReader`及其针对配置的创建方式后，我们最后来看看`load_input_documents`这个`Workflow`是如何利用它来加载输入文档的。这个`Workflow`对应的`WorkflowFunction`函数定义在`graphrag.index.workflows.load_input_documents`模块种，对应的如下这个`run_workflow`函数。

```python
async def run_workflow(
    config: GraphRagConfig,
    context: PipelineRunContext,
) -> WorkflowFunctionOutput:
    input_reader = create_input_reader(config.input, context.input_storage)
    async with (
        context.output_table_provider.open("documents") as documents_table,
    ):
        sample, total_count = await load_input_documents(input_reader, documents_table)

        if total_count == 0:
            msg = "Error reading documents, please see logs."
            logger.error(msg)
            raise ValueError(msg)

        logger.info("Final # of rows loaded: %s", total_count)
        context.stats.num_documents = total_count

    return WorkflowFunctionOutput(result=sample)
```

`run_workflow`的执行逻辑很简单：

- 调用上述的`create_input_reader`根据`GraphRagConfig`配置提供的`InputConfig`和`PipelineRunContext`上下文的`input_storage`字段提供的Storage创建对应的`InputReader`；
- 提供`PipelineRunContext`上下文的output_table_provider字段提供额`TableProvider`，然后调用open开启命名为`documents`的`Table`；
- 调用如下这个`load_input_documents`方法利用`InputReader`读取原始输入，并将生成的`TextDocument`的内容写入上面这个`documents`表。

`load_input_documents`会返回一个`[pd.DataFrame, int]`二元组，`DataFrame`返回的并非整个`documents`表的内容，而是通过`sample_size`参数（默认为5）指定的前N条记录。单手二元组第二部分返回的所有记录的计数。所以`Worflow`执行后的`WorkflowFunctionOutput`中最多只会返回**5**个文档。

```python
async def load_input_documents(
    input_reader: InputReader, documents_table: Table, sample_size: int = 5
) -> tuple[pd.DataFrame, int]:
    sample: list[dict] = []
    idx = 0

    async for doc in input_reader:
        row = asdict(doc)
        row["human_readable_id"] = idx
        if "raw_data" not in row:
            row["raw_data"] = None
        await documents_table.write(row)
        if len(sample) < sample_size:
            sample.append(row)
        idx += 1

    return pd.DataFrame(sample), idx
```

```python
import asyncio
import graphrag.index.workflows.load_input_documents as load_input_documents
from graphrag.index.typing.pipeline import Pipeline
from graphrag.config.load_config import load_config
from graphrag.index.run.run_pipeline import run_pipeline
from graphrag.callbacks.noop_workflow_callbacks import NoopWorkflowCallbacks
import pandas as pd


async def main():   
    pipeline = Pipeline(workflows=[
        ("load_input_documents", load_input_documents.run_workflow)
    ])
    async for _ in  run_pipeline(
        pipeline = pipeline,
        config = load_config(root_dir="./"),
        callbacks= NoopWorkflowCallbacks(),
    ):
        pass

    df = pd.read_parquet('./output/documents.parquet')
    print(df.info())
    for _, row in df.iterrows():
        for col in df.columns:
            print(f"{col}: {row[col]}, ")
        print() 
asyncio.run(main())
```
