# [GraphRAG实现原理-07]将文档分割为可供LLM处理的切片

## 1. 利用Tokenizer进行编解码和计算Token数

文本切割之前得确定长度，AI领域会使用Token来度量长度，而这又涉及到Tokenizer的使用。GraphRAG将分词器抽象成如下这个同名抽象类。

```python
class Tokenizer(ABC):
    @abstractmethod
    def __init__(self, **kwargs: Any) -> None

    @abstractmethod
    def encode(self, text: str) -> list[int]
    @abstractmethod
    def decode(self, tokens: list[int]) -> str
    def num_prompt_tokens(
        self,
        messages: "LLMCompletionMessagesParam",
    ) -> int
    def num_tokens(self, text: str) -> int
```

四个方法说明如下：

- **encode**：将输入的字符串文本转换为对应的`token_id`列表（整数列表）。
- **decode**：将`token_id`列表还原为原始的字符串文本。
- **num_prompt_tokens**：计算提示词的Token总数。
- **num_tokens**：辅助方法。通过调用`self.encode(text)`获取编码结果并返回其长度，以此得到文本的Token数量。

### 1.1 Tokenizer的两种类型

GraphRAG支持`LiteLLMTokenizer`和`TiktokenTokenizer`两种类型的`Tokenizer`，下面给出了两种类型`__init__`方法的定义。这两种类型分别对应`TokenizerType`枚举的两个选项。

```python
class LiteLLMTokenizer(Tokenizer):
    def __init__(self, *, model_id: str, **kwargs: Any) -> None

class TiktokenTokenizer(Tokenizer):
    def __init__(self, *, encoding_name: str, **kwargs: Any) -> None

class TokenizerType(StrEnum):
    LiteLLM = "litellm"
    Tiktoken = "tiktoken"
```

两种类型的`Tokenizer`说明如下：

- **LiteLLM**：委托LiteLLM库完成编解码，分词行为跟随所配置的模型自动匹配，能覆盖OpenAI、Anthropic、Bedrock等多厂商模型，适合模型来源多样或使用非OpenAI系模型的场景。
- **Tiktoken**：直接基于OpenAI的`tiktoken`库，轻量成熟且可控，但依赖其静态的模型名到编码方案映射表，遇到未收录的模型名（如本地Ollama模型）会查表失败。

总体而言，`LiteLLM`以通用性能换取对模型视为适配，`Tiktoken`以显式指定换取简单可控，需按模型来源和是否需要跨厂商适配来取舍。

### 1.2 Tokenizer的配置

`Tokenizer`的配置通过如下所示的`TokenizerConfig`类型表示，上述的两种类型体现在`type`字段上，默认值为`TokenizerType.LiteLLM`。`model_id`和`encoding_name`分别表示采用的模型和编码名称。

```python
class TokenizerConfig(BaseModel):
    type: str = Field(
        default=TokenizerType.LiteLLM,
        description="The type of tokenizer to use. [litellm] (default: litellm).",
    )

    model_id: str | None = Field(
        default=None,
        description="The identifier for the tokenizer model. Example: openai/gpt-4o. Used by the litellm tokenizer.",
    )

    encoding_name: str | None = Field(
        default=None,
        description="The encoding name for the tokenizer. Example: gpt-4o.",
    )
```

### 1.3 Tokenizer的创建

`Tokenizer`采用与索引管道一致的方式来进行创建。具体来说，它定义了派生自`Factory[Tokenizer]`的工厂类`TokenizerFactory`，并使用`register_tokenizer`函数针对指定`Tokenizer`类型注册一个初始化话函数到全局的`TokenizerFactory`对象上，并且可以选择采用`Singleton`（单例）或者`Transient`（每次创建新对象）模式进行注册。最后就可以调用这个`TokenizerFactory`对象的`create`方法来创建

```python
class TokenizerFactory(Factory[Tokenizer]):
tokenizer_factory = TokenizerFactory()
def register_tokenizer(
    tokenizer_type: str,
    tokenizer_initializer: Callable[..., Tokenizer],
    scope: "ServiceScope" = "transient",
) -> None:
    tokenizer_factory.register(tokenizer_type, tokenizer_initializer, scope)
```

GraphRAG定义了如下这个`create_tokenizer`函数根据指定的`TokenizerConfig`来创建`Tokenizer`。它会利用`TokenizerConfig`的`type`字段作为`Tokenizer`初始化函数的注册名称来确定对应的注册是否存在，如果不存在则调用`register_tokenizer`函数进行注册。最终调用全局`TokenizerFactory`对象的`create`方法创建返回的`Tokenizer`。

```python
def create_tokenizer(tokenizer_config: "TokenizerConfig") -> Tokenizer:
    strategy = tokenizer_config.type
    init_args = tokenizer_config.model_dump()

    if strategy not in tokenizer_factory:
        match strategy:
            case TokenizerType.LiteLLM:
                from graphrag_llm.tokenizer.lite_llm_tokenizer import (
                    LiteLLMTokenizer,
                )

                register_tokenizer(
                    TokenizerType.LiteLLM,
                    LiteLLMTokenizer,
                    scope="singleton",
                )
            case TokenizerType.Tiktoken:
                from graphrag_llm.tokenizer.tiktoken_tokenizer import (
                    TiktokenTokenizer,
                )

                register_tokenizer(
                    TokenizerType.Tiktoken,
                    TiktokenTokenizer,
                    scope="singleton",
                )
            case _:
                msg = f"TokenizerConfig.type '{strategy}' is not registered in the TokenizerFactory. Registered strategies: {', '.join(tokenizer_factory.keys())}"
                raise ValueError(msg)

    return tokenizer_factory.create(
        strategy=strategy,
        init_args=init_args,
    )
```

GraphRAG最终调用如下这个`get_tokenizer`函数来获取所需的`Tokenizer`，它最终调用的就是上面这个`create_tokenizer`，具体的创建流程如下：

- 如果利用`model_config`参数指定了用来承载LLM配置的`ModelConfig`对象，则利用其提供的供应商名称和模型名称决定的模型ID调用`create_tokenizer`函数创建或者提取一个`LiteLLMTokenizer`对象；
- 如果没有利用`encoding_model`参数提供编码模型，则使用`o200k_base`兜底，调用`create_tokenizer`函数创建或者提取一个`TiktokenTokenizer`对象。

```python
def get_tokenizer(
    model_config: "ModelConfig | None" = None,
    encoding_model: str | None = None,
) -> Tokenizer:
    if model_config is not None:
        return create_tokenizer(
            TokenizerConfig(
                type=TokenizerType.LiteLLM,
                model_id=f"{model_config.model_provider}/{model_config.model}",
            )
        )

    if encoding_model is None:
        encoding_model = ENCODING_MODEL
    return create_tokenizer(
        TokenizerConfig(
            type=TokenizerType.Tiktoken,
            encoding_name=encoding_model,
        )
    )
ENCODING_MODEL = "o200k_base"
```

## 2. 利用Chunker进行切片

文本分割具有不同的策略和方法，所以GraphRAG依然采用抽象的方式定义了如下这个`Chunker`作为具体文档分割类型的基类。具体的分割操作需要是实现在`chunk`方法中，该方法返回代表文本切片的`TextChunk`列表。

```python
class Chunker(ABC):
    @abstractmethod
    def __init__(self, **kwargs: Any) -> None:
    @abstractmethod
    def chunk(
        self, text: str, transform: Callable[[str], str] | None = None
    ) -> list[TextChunk]

@dataclass
class TextChunk:
    original: str
    text: str
    index: int
    start_char: int
    end_char: int
    token_count: int | None = None
```

`TextChunk`个字段说明如下：

- **original**: 变换前的原始文本块内容，用于保留切分时的原始形态。
- **text**: 经处理后的最终文本内容。
- **index**: 该块在源文档中的零基序号，用于标识块在文档中的顺序位置。
- **start_char**: 原始块文本在源文档中的起始字符索引，用于原文回指与偏移计算。
- **end_char**: 原始块文本在源文档中的结束字符索引，与`start_char`共同界定原文区间。
- **token_count**: Token数量，可选字段，未计算时为`None`。

### 2.1 两种分割策略

GraphRAG提供了`TokenChunker`和`SentenceChunker`这两种原生的`Chunker`类型。顾名思义，前者采用基于Token计数的固定窗口分割策列，后者采用基于句子边界的自然语言分割策略。两种类型分别采用它们分别如下这个`ChunkerType`枚举的两个选项。

```python
class TokenChunker(Chunker):
    def __init__(
        self,
        size: int,
        overlap: int,
        encode: Callable[[str], list[int]],
        decode: Callable[[list[int]], str],
        **kwargs: Any,
    ) -> None
class SentenceChunker(Chunker):
    def __init__(
        self, encode: Callable[[str], list[int]] | None = None, **kwargs: Any
    ) -> None

class ChunkerType(StrEnum):
    Tokens = "tokens"
    Sentence = "sentence"
```

### 2.2 Chunker的配置

如下这个`ChunkingConfig`类型用来承载`Chunker`的配置，具体使用哪种类型的`Chunker`由`type`字段决定，默认使用基于固定`Token`长度的`TokenChunker`。

```python
class ChunkingConfig(BaseModel):
    type: str = Field(
        description="The chunking type to use.",
        default=ChunkerType.Tokens,
    )
    encoding_model: str | None = Field(
        description="The encoding model to use.",
        default=None,
    )
    size: int = Field(
        description="The chunk size to use.",
        default=1200,
    )
    overlap: int = Field(
        description="The chunk overlap to use.",
        default=100,
    )
    prepend_metadata: list[str] | None = Field(
        description="Metadata fields from the source document to prepend on each chunk.",
        default=None,
    )
```

其余四个配置项说明如下：

- **encoding_model**: 分词所用的编码模型，默认`None`，用于Token计数与切分。
- **size**: 分块窗口大小，默认`1200`，即每块的目标Token数。
- **overlap**: 相邻块之间的重叠量，默认`100`，用于保留跨块上下文。
- **prepend_metadata**: 需前置到每个切片的源文档元数据字段列表，默认`None`。

作为GraphRAG整体配置的`GraphRagConfig`的`chunking`配置节返回的正是这个`ChunkingConfig`，初始化提供的模式配置选项来源于`ChunkingDefaults`。

```python
class GraphRagConfig(BaseModel):
    chunking: ChunkingConfig = Field(
        description="The chunking configuration to use.",
        default=ChunkingConfig(
            type=graphrag_config_defaults.chunking.type,
            size=graphrag_config_defaults.chunking.size,
            overlap=graphrag_config_defaults.chunking.overlap,
            encoding_model=graphrag_config_defaults.chunking.encoding_model,
            prepend_metadata=graphrag_config_defaults.chunking.prepend_metadata,
        ),
    )

@dataclass
class ChunkingDefaults:
    type: str = ChunkerType.Tokens
    size: int = 1200
    overlap: int = 100
    encoding_model: str = ENCODING_MODEL
    prepend_metadata: None = None
```

### 2.3 Chunker的创建

针对`Chunker`的创建的设计与上面介绍的`Tokenizer`创建一摸一样：定了一个派生于`Factory[Chunker]`的工厂类`ChunkerFactory`，并利用`register_chunker`函数一个`Chunker`的初始化函数针对指定的类型注册到全局`ChunkerFactory`对象上。GraphRAG最终利用`create_chunker`根据指定的`ChunkingConfig`和编解码函数来创建对应的`Chunker`。

```python
class ChunkerFactory(Factory[Chunker])
    pass

chunker_factory = ChunkerFactory()

def register_chunker(
    chunker_type: str,
    chunker_initializer: Callable[..., Chunker],
    scope: ServiceScope = "transient",
) -> None:
    chunker_factory.register(chunker_type, chunker_initializer, scope)

def create_chunker(
    config: ChunkingConfig,
    encode: Callable[[str], list[int]] | None = None,
    decode: Callable[[list[int]], str] | None = None,
) -> Chunker:
    config_model = config.model_dump()
    if encode is not None:
        config_model["encode"] = encode
    if decode is not None:
        config_model["decode"] = decode
    chunker_strategy = config.type

    if chunker_strategy not in chunker_factory:
        match chunker_strategy:
            case ChunkerType.Tokens:
                from graphrag_chunking.token_chunker import TokenChunker
                register_chunker(ChunkerType.Tokens, TokenChunker)
            case ChunkerType.Sentence:
                from graphrag_chunking.sentence_chunker import SentenceChunker
                register_chunker(ChunkerType.Sentence, SentenceChunker)
            case _:
                msg = f"ChunkingConfig.strategy '{chunker_strategy}' is not registered in the ChunkerFactory. Registered types: {', '.join(chunker_factory.keys())}."
                raise ValueError(msg)

    return chunker_factory.create(chunker_strategy, init_args=config_model)
```

## 3. 生成TextUnit列表

管道这个用来分割文档的命名为`create_base_text_units`的`Workflow`最终会将每个切片封装成一个`TextUnit`列表。`TextUnit`是GraphRAG 知识模型中的核心数据类，代表从源文档切分而来的文本块，是后续实体、关系与协变量抽取的基本单元，同时承担着将图元素溯源回原始文本的关键桥梁作用。

```python
@dataclass
class TextUnit(Identified):
    text: str
    entity_ids: list[str] | None = None
    relationship_ids: list[str] | None = None
    covariate_ids: dict[str, list[str]] | None = None
    n_tokens: int | None = None
    document_id: str | None = None
    attributes: dict[str, Any] | None = None
```

组成`TextUnit`的字段成员说明如下：

- **text**: 文本单元的实际文本内容。
- **entity_ids**: 与该文本单元相关的实体ID列表，可选。
- **relationship_ids**: 与该文本单元相关的关系ID列表，可选。
- **covariate_ids**: 按类型组织的协变量ID字典，可选。
- **n_tokens**: 文本中的Token数量，可选。
- **document_id**: 该文本单元所属文档的ID，可选。
- **attributes**: 与该文本单元关联的附加属性字典，可选。
- **from_dict**: 类方法，按可配置的键名从字典构造`TextUnit`实例。

`Workflow`之所以命名`create_base_text_units`，是因为创建的仅仅是一个基础的`TextUnit`，很多缺失的部分（比如关联的实体、关系和声明ID）还需要通过管道后续的步骤进行补充。这个`Workflow`提供的`WorkflowFunction`对应如下这个`run_workflow`函数(所在的模块路径`graphrag/workflows/create_base_text_units`)。

```python
async def run_workflow(
    config: GraphRagConfig,
    context: PipelineRunContext,
) -> WorkflowFunctionOutput:
    logger.info("Workflow started: create_base_text_units")
    tokenizer = get_tokenizer(encoding_model=config.chunking.encoding_model)
    chunker = create_chunker(config.chunking, tokenizer.encode, tokenizer.decode)

    async with (
        context.output_table_provider.open("documents") as documents_table,
        context.output_table_provider.open("text_units") as text_units_table,
    ):
        total_rows = await documents_table.length()
        sample_rows = await create_base_text_units(
            documents_table,
            text_units_table,
            total_rows,
            context.callbacks,
            tokenizer=tokenizer,
            chunker=chunker,
            prepend_metadata=config.chunking.prepend_metadata,
        )

    logger.info("Workflow completed: create_base_text_units")
    return WorkflowFunctionOutput(result=sample_rows)
```

`run_workflow`函数采用如下的流程完成针对文档的分割：

- 从提供的`GraphRagConfig`中提取`ChunkingConfig`配置；
- 根据`ChunkingConfig`对象的`encoding_model`字段提供的编码模型调用前面介绍的`get_tokenizer`函数创建或者提取`Tokenizer`；
- 根据`ChunkingConfig`配置和Tokenizer的编解码方法调用`create_chunker`函数创建`Chunker`对象；
- 从`PipelineRunContext`上下文的`output_table_provider`得到用来访问输出表格的`TableProvider`，并调用其open方法得到命名为`documents`和`text_units`的`Table`， 调用`create_base_text_units`函数从前者逐行提取每一个文档递交给`Chunker`对象进行分割，并将生成的`TextUnit`写入后者。

如下给出的是经过简化的`create_base_text_units`函数的定义，其大概的文本分割流程如下：

- 采用异步遍历的方式从documents表中逐个读取每个文档；
- 调用`chunk_document`函数对每个文档进行分割，并返回分割后的文本列表。chunk_document函数最终会调用Chunker的chunk方法实时分割并生成`TextChunk`列表，返回的切片文本来源于`TextChunk`的`text`字段；
- 针对每一段切片文档，生成一条`TextUnit`记录并写入`text_units`表。

```python
async def create_base_text_units(
    documents_table: Table,
    text_units_table: Table,
    total_rows: int,
    callbacks: WorkflowCallbacks,
    tokenizer: Tokenizer,
    chunker: Chunker,
    prepend_metadata: list[str] | None = None,
) -> list[dict[str, Any]]:
    doc_index = 0
    sample_rows: list[dict[str, Any]] = []
    sample_size = 5
    async for doc in documents_table:
        chunks = chunk_document(doc, chunker, prepend_metadata)
        for chunk_text in chunks:
            if chunk_text is None:
                continue
            row = {
                "id": "",
                "document_id": doc["id"],
                "text": chunk_text,
                "n_tokens": len(tokenizer.encode(chunk_text)),
            }
            row["id"] = gen_sha512_hash(row, ["text"])
            await text_units_table.write(row)
            if len(sample_rows) < sample_size:
                sample_rows.append(row)
        doc_index += 1
    return sample_rows


def chunk_document(
    doc: dict[str, Any],
    chunker: Chunker,
    prepend_metadata: list[str] | None = None,
) -> list[str]:
    transformer = None
    if prepend_metadata:
        document = TextDocument(
            id=doc["id"],
            title=doc.get("title", ""),
            text=doc["text"],
            creation_date=doc.get("creation_date", ""),
            raw_data=doc.get("raw_data"),
        )
        metadata = document.collect(prepend_metadata)
        transformer = add_metadata(metadata=metadata, line_delimiter=".\n")
    return [chunk.text for chunk in chunker.chunk(doc["text"], transform=transformer)]
```

从`create_base_text_units`函数的实现可以看出，每一条`TextUnit`记录只包含`id`、`document_id`、`text`和`n_tokens`四个字段。返回的字典列表只提供最初写入的N条（由`sample_size`参数决定，默认为**5**条）记录。

## 4. 查看生成的TextUnit

[GraphRAG实现原理-06:加载输入并转换成标准文档]()提供了一个实例演示了通过执行`standard`管道的第一个`Workflow`（`load_input_documents`）生成了documents表（对应`output/documents.parquet`文件），现在我们在此基础上执行第二个`Workflow`（`create_base_text_units`）通过分割这些文档，并将每个切片写入`text_units`表（对应`output/text_units.parquet`文件）。

如代码片段所示，我们创建了仅仅包含`create_base_text_units`这一个单一`Workflow`的`Pipeline`对象，并调用`run_pipeline`函数执行此管道。最后我们将生成的`./output/text_units.parquet`文件导入`DataFrame`，并输出表格的结构和所有的`TextUnit`记录。由于我们提供的每个文档内容都很多，所以没有出现分割的情况。

```python
import asyncio
import graphrag.index.workflows.create_base_text_units as create_base_text_units
from graphrag.index.typing.pipeline import Pipeline
from graphrag.config.load_config import load_config
from graphrag.index.run.run_pipeline import run_pipeline
from graphrag.callbacks.noop_workflow_callbacks import NoopWorkflowCallbacks
import pandas as pd

async def main():   
    pipeline = Pipeline(workflows=[
        ("create_base_text_units", create_base_text_units.run_workflow)
    ])
    async for output in  run_pipeline(
        pipeline = pipeline,
        config = load_config(root_dir="./"),
        callbacks= NoopWorkflowCallbacks(),
    ):
        pass

    df = pd.read_parquet('./output/text_units.parquet')
    print(df.info())
    for _, row in df.iterrows():
        for col in df.columns:
            print(f"{col}: {row[col]}, ")
        print() 
asyncio.run(main())
```
