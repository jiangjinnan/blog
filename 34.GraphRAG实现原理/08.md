# [GraphRAG实现原理-08]实现文档和切片的双向溯源

到目前为止，我们已经系统介绍了组成`standard`管道的前两个`Workflow`的作用、设计和实现。其中`load_input_documents`用来加载原始的输入文档，`create_base_text_units`则对生成的文档进行分割并生成代表切片的`TextUnit`列表。本篇文章介绍的第三个命名为`create_final_documents`的`Workflow`则负责将`TextUnit`的ID会写到文档中，使这样文档和切片就具双向引用。

## 1. 建立文档和切片双向引用

`create_final_documents`是GraphRAG 索引管道中一个轻量但关键的收尾工作流，核心作用是将原始文档与切分后的`TextUnit`建立双向映射，从而为最终输出提供可追溯的原文依据。虽然`documents`表不直接参与GraphRAG的查询与生成过程，它的存在价值在于**将文档与组成它们的切片链接起来，以便在你自己的应用中实现溯源**。换句话说，当你在GraphRAG中检索到某个实体或关系时，可以通过`text_unit_ids`一路回溯到具体的`TextUnit`，再经由`document_id`找到源文档，从而向用户展示原始出处。`create_final_documents`在整个`standard`管道的为止如下所示。

```markdown
load_input_documents
    └── create_base_text_units
            └── **create_final_documents** 
                    └── extract_graph
                            └── finalize_graph
                                    └── extract_covariates
                                            └── create_communities
                                                    └── create_final_text_units
                                                            └──create_community_reports
                                                                    └── generate_text_embeddings
```

## 2. Workflow的实现

当`create_final_documents`这个`Workflow`执行的时候，存储原始文档的`documents`表和切片的`text_units`表已经存储，它的职责就是从`text_units`表读取数据并建立`document_id`和`text_unit_id`之间的映射关系（一对多），并将`text_unit_id`列表写入`documents`表对应的文档记录中。

这个`Workflow`的`WorkflowFunction`对应如下这个`run_workflow`函数（所在模块路径为`graphrag/workflows/create_final_documents`）。如代码所示，该函数会利用`GraphRagConfig`提供的`TableProvider`开启开启三个`Table`，前两个作为输入的`documents`和`text_units`表，最后一个则是作为输出的`documents`。并在三种的联合上下文中调用`create_final_documents`函数完成上述的任务。

```python
async def run_workflow(
    _config: GraphRagConfig,
    context: PipelineRunContext,
) -> WorkflowFunctionOutput:
    async with (
        context.output_table_provider.open(
            "text_units",
        ) as text_units_table,
        context.output_table_provider.open(
            "documents",
            transformer=transform_document_row,
        ) as documents_table,
        context.output_table_provider.open(
            "documents",
        ) as output_table,
    ):
        sample = await create_final_documents(
            text_units_table,
            documents_table,
            output_table,
        )
    return WorkflowFunctionOutput(result=sample)

def transform_document_row(
    row: dict[str, Any],
) -> dict[str, Any]:
    if "human_readable_id" in row:
        row["human_readable_id"] = _safe_int(
            row["human_readable_id"],
        )
    if "text_unit_ids" in row:
        row["text_unit_ids"] = _coerce_list(row["text_unit_ids"])
    return row
```

在读取`documents`表的时候，为了确保`human_readable_id`字段返回一个合法的整数（如果原始数据不存在或者格式不正确，返回`-1`），以及`text_unit_ids`字段返回一个一个列表，在调用`TableProvider`的`open`方法的时候将`transform_document_row`函数作为了`transformer`参数。

`create_final_document`函数会逐行读取`text_units`表的每条记录，并将`document_id`和`text_unit_id`之间的映射关系添加到由`mapping`字典中。然后从`documents`表中读取每一条记录，并在附加上`text_unit_ids`字段后再次回写到原表中。和常规的`Wokflow`一样，`create_final_documents`这个`Workflow`返回的`WorkflowFunctionOutput`中默认只返回**5**条初始更新的文档记录。

```python
async def create_final_documents(
    text_units_table: Table,
    documents_table: Table,
    output_table: Table,
) -> list[dict[str, Any]]:
    mapping: dict[str, list[str]] = {}
    async for row in text_units_table:
        document_id = row.get("document_id", "")
        if document_id:
            mapping.setdefault(document_id, []).append(
                row["id"],
            )

    sample_rows: list[dict[str, Any]] = []
    async for row in documents_table:
        row["text_unit_ids"] = mapping.get(row["id"], [])
        out = {c: row.get(c) for c in DOCUMENTS_FINAL_COLUMNS}
        await output_table.write(out)
        if len(sample_rows) < 5:
            sample_rows.append(out)

    return sample_rows

DOCUMENTS_FINAL_COLUMNS = [
    ID,
    SHORT_ID,
    TITLE,
    TEXT,
    TEXT_UNIT_IDS,
    CREATION_DATE,
    RAW_DATA,
]
```

前面介绍[`load_input_documents`](https://jaydenai.blog.csdn.net/article/details/169243783)和[`create_base_text_units`](https://jaydenai.blog.csdn.net/article/details/169337244)这两个`Workflow`的时候，我们提供了相应的实例演示。通过演示程序的输出，我们确定了`documents`表目前具有如下的结果，它并不包含用来引用切片的`text_unit_ids`字段。

现在我们在此基础上对这个演示程序作进一步完善，通过如下的程序执行一个由`create_final_documents`这个单一`Workflow`构建的管道。在完成管道执行后，我们将`./output/documents.parquet`加载到一个`DataFrame`中，并将最新的`documents`表的结构和所有的记录输出来。冲输出的结果可以看出，`documents`表多了一个关联`TextUnit`的`text_unit_ids`字段。

```python
import asyncio
import graphrag.index.workflows.create_final_documents as  create_final_documents
from graphrag.index.typing.pipeline import Pipeline
from graphrag.config.load_config import load_config
from graphrag.index.run.run_pipeline import run_pipeline
from graphrag.callbacks.noop_workflow_callbacks import NoopWorkflowCallbacks
import pandas as pd

async def main():   
    pipeline = Pipeline(workflows=[
        ("create_final_documents", create_final_documents.run_workflow)
    ])
    async for output in  run_pipeline(
        pipeline = pipeline,
        config = load_config(root_dir="./"),
        callbacks= NoopWorkflowCallbacks(),
    ):
        pass

    df = pd.read_parquet('./output/documents.parquet')
    print(df.info())
    for _, row in df.iterrows():
        for col in df.columns:
            print(f"{col}: {row[col]}, ")
        print() 
asyncio.run(main())
```
