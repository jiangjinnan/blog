# [GraphRAG实现原理-11]提取声明为图谱补充事实性细节

当完整的实体关系图从提供的文本提取之后，其实很遗漏了很多动态的内容。GraphRAG将它们视为协变量（`covariate`）存储在`covariates`表中。Covariate这个名称借鉴了统计学中的**协变量**概念，意指那些与主体相关、但本身并非核心结构（实体或关系）的附加信息。GraphRAG并没有限制其类型，但是`standard`管道目前仅支持声明（`Claim`）这一种类型，代表从文本中提取的、关于实体的具体事实陈述或断言。索引管道利用`extract_covariates`这个`Workflow`利用LLM提取声明。

## 1. 我们现在在哪里？

作为关于实体的可核实事实断言，声明的作用在于为图谱补充事实性细节，弥补仅靠实体和关系所缺乏的粒度与可溯源性。与静态的实体和关系不同，声明能够捕获带有时间边界的断言，并附带验证状态、源文本片段等元数据，使知识图谱中的事实具备时效性和可审计性。这使得GraphRAG在检索时不仅能定位实体，还能精准调用附着于实体的事实细节，从而提升回答的可溯源性与真实可靠能力。索引管道利用`extract_covariates`这个`Workflow`利用LLM提取声明，这是`standard`管道的第六个个`Workflow`。

```markdown
load_input_documents
    └── create_base_text_units
            └── create_final_documents
                    └── extract_graph
                            └── finalize_graph
                                    └──**extract_covariates**
                                            └── create_communities
                                                    └── create_final_text_units
                                                            └──create_community_reports
                                                                    └── generate_text_embeddings
```

## 2. 声明提取执行流程

`extract_covariates`这个`Workflow`的`WorkflowFunction`对应如下这个`run_workflow`函数（所在模块目录为`graphrag/workflows/extract_covariates`）。整个声明的提取流程其实很简单：

- 从提供的`GraphRagConfig`中得到与**声明提取**相关的配置（对应`extract_claims`字段），这是一个`ExtractClaimsConfig`对象；
- 根据`ExtractClaimsConfig`配置创建代表LLM的`LLMCompletion`对象，并得到提示词模板；
- 从`text_units`表中加载每个`TextUnit`记录，并利用其提供的文本格式化提示词模板生成调用LLM的提示词；
- 接续LLM响应结果，并存入`covariates`表。

```python
async def run_workflow(
    config: GraphRagConfig,
    context: PipelineRunContext,
) -> WorkflowFunctionOutput:
    output = None
    if config.extract_claims.enabled:
        reader = DataReader(context.output_table_provider)
        text_units = await reader.text_units()
        model_config = config.get_completion_model_config(
            config.extract_claims.completion_model_id
        )
        model = create_completion(
            model_config,
            cache=context.cache.child(config.extract_claims.model_instance_name),
            cache_key_creator=cache_key_creator,
        )
        prompts = config.extract_claims.resolved_prompts()
        output = await extract_covariates(
            text_units=text_units,
            callbacks=context.callbacks,
            model=model,
            covariate_type="claim",
            max_gleanings=config.extract_claims.max_gleanings,
            claim_description=config.extract_claims.description,
            prompt=prompts.extraction_prompt,
            entity_types=DEFAULT_ENTITY_TYPES,
            num_threads=config.concurrent_requests,
            async_type=config.async_mode,
        )

        await context.output_table_provider.write_dataframe("covariates", output)
    return WorkflowFunctionOutput(result=output)
```

下面给出了`ExtractClaimsConfig`的完整定义，以及`extract_claims`字段在`GraphRagConfig`中的定义。

```python
class GraphRagConfig(BaseModel):
    extract_claims: ExtractClaimsConfig = Field(
        description="The claim extraction configuration to use.",
        default=ExtractClaimsConfig(
            enabled=graphrag_config_defaults.extract_claims.enabled,
        )
    )

class ExtractClaimsConfig(BaseModel):
    enabled: bool = Field(
        description="Whether claim extraction is enabled.",
        default=graphrag_config_defaults.extract_claims.enabled,
    )
    completion_model_id: str = Field(
        description="The model ID to use for claim extraction.",
        default=graphrag_config_defaults.extract_claims.completion_model_id,
    )
    model_instance_name: str = Field(
        description="The model singleton instance name. This primarily affects the cache storage partitioning.",
        default=graphrag_config_defaults.extract_claims.model_instance_name,
    )
    prompt: str | None = Field(
        description="The claim extraction prompt to use.",
        default=graphrag_config_defaults.extract_claims.prompt,
    )
    description: str = Field(
        description="The claim description to use.",
        default=graphrag_config_defaults.extract_claims.description,
    )
    max_gleanings: int = Field(
        description="The maximum number of entity gleanings to use.",
        default=graphrag_config_defaults.extract_claims.max_gleanings,
    )

    def resolved_prompts(self) -> ClaimExtractionPrompts:
        return ClaimExtractionPrompts(
            extraction_prompt=Path(self.prompt).read_text(encoding="utf-8")
            if self.prompt
            else EXTRACT_CLAIMS_PROMPT,
        )
```

相关配置选项说明如下，如下所示的`ExtractClaimsDefaults`类型提供了兜底的默认值。

- **enabled**：控制是否启用声明提取。
- **completion_model_id**：指定声明提取所用的补全模型。
- **model_instance_name**：模型单例实例名，主要用于缓存存储分区。。
- **prompt**：声明提取提示词，可为`None`；提供时作为提示词文件路径读取。
- **description**：声明提取时使用的声明描述，用于指导提取任务。
- **max_gleanings**：要使用的最大实体收集数量，即补充或追加提取的最大轮数。
- **resolved_prompts()**：解析并返回Claim提取提示词；有`prompt`则读文件，否则用内置默认提示词。

```python
class ExtractClaimsDefaults:
    enabled: bool = False
    prompt: None = None
    description: str = ("Any claims or facts that could be relevant to information discovery.")
    max_gleanings: int = 1
    completion_model_id: str = DEFAULT_COMPLETION_MODEL_ID
    model_instance_name: str = "extract_claims"
```

`ExtractClaimsConfig`的`resolved_prompts`方法会根据`prompt`字段的设置返回提示词模板的内容。如果没有设置，会使用默认的内容兜底。当我们执行`graphrag init`命令进行初始化时会将默认的提示词内容写入`output/extract_claims.txt`，内容如下。模板具有三个占位符：

- **{entity_specs}**：实体的类型，一般会使用`GraphRagConfig`的`extract_graph.entity_types`字段替换；
- **{claim_description}**：声明描述，会使用`ExtractClaimsConfig`的`description`字段替换；
- **{input_text}**：`TextUnit`提供的文本。

## 3. 调用LLM提取声明

[GraphRAG实现原理-09:调用LLM提取实体关系图](https://jaydenai.blog.csdn.net/article/details/169424286)提供了以一个例子模拟了根据当前配置调用LLM提取实体关系的例子，接下来我们采用相同的模式来提取声明。从输出可以看出LLM成功抽取出了两条关于开业决策（`BUSINESS OPENING DECISION`）和选址（`SITE SELECTION`）的声明。声明完全按照提示词描述的格式进行输出，只要采用简单的正则表达式就能将每个字段提取出来。

```python
import asyncio
from graphrag.config.load_config import load_config
from graphrag_llm.completion import create_completion
from graphrag_llm.types import LLMCompletionResponse

async def main():   
    config = load_config(root_dir="./")
    llm = create_completion(config.completion_models[config.extract_claims.completion_model_id])
    prompt = config.extract_claims.resolved_prompts().extraction_prompt.format(**{
        "entity_specs":config.extract_graph.entity_types,
        "claim_description": config.extract_claims.description,
        "input_text":"2024年3月，李明决定在杭州开一家咖啡店。他考察了三个地点：学校附近、写字楼商圈、老城区街角。学校附近人流量大，但租金每月高达两万元；写字楼商圈工作日客流稳定，周末冷清；老城区租金低，但年轻客群少。最终李明选择了写字楼商圈，月租一万五千元，签约两年"
    })
    response:LLMCompletionResponse = await llm.completion_async(messages=prompt) # type: ignore
    print(response.content)

asyncio.run(main())
```

## 4. 查看生成的声明

[GraphRAG实现原理-10:进一步完善提取的实体关系图](https://jaydenai.blog.csdn.net/article/details/169435465)提供了演示程序完成了初始实体关系图的构建，现在我们在此基础上应用`extract_covariates`这个`Workflow`完成针对声明写入。我们通过如下的程序执行一个由`extract_covariates`这个单一`Workflow`构建的管道。在完成管道执行后，我们将`./output/covariates.parquet`文件加载到一个`DataFrame`中，并将表结构和数据输出来。`covariates`表结构在[GraphRAG实现原理-02:基于社区（Community）的知识图谱](https://jaydenai.blog.csdn.net/article/details/168962194)中具有详细介绍。

```python
import asyncio
import graphrag.index.workflows.extract_covariates as  extract_covariates
from graphrag.index.typing.pipeline import Pipeline
from graphrag.config.load_config import load_config
from graphrag.index.run.run_pipeline import run_pipeline
from graphrag.callbacks.noop_workflow_callbacks import NoopWorkflowCallbacks
import pandas as pd

async def main():   
    pipeline = Pipeline(workflows=[
        ("extract_covariates", extract_covariates.run_workflow)
    ])
    async for output in  run_pipeline(
        pipeline = pipeline,
        config = load_config(root_dir="./"),
        callbacks= NoopWorkflowCallbacks(),
    ):
        pass

    print(f"----------covariates schema----------")
    df = pd.read_parquet('./output/covariates.parquet')
    print(df.info())

    print(f"----------covariates records----------")
    for _, row in df.iterrows():
        for col in df.columns:
            print(f"{col}: {row[col]}, ")
        print() 
asyncio.run(main())
```
