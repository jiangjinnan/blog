# [GraphRAG实现原理-13]构建完整的文本切片（TextUnit）

为了确保提供的文本能够被LLM正常处理（至少不能超出上下文窗口上限） ，需要将导入的文档借助`create_base_text_units`这个`Worfkow`转换成代表切片的`TextUnit`对象，并存入`text_units`表中。后续管道生成的实体关系图和协变量都由这些`TextUnit`生成，而且每个实体、关系和协变量分别利用`text_unit_ids`和`text_unit_id`保留针对`TextUnit`的引用。本篇文章介绍的`create_final_text_units`这个`Workflow`会为每个`TextUnit`反向补充其关联的实体、关系和协变量ID，生成最终版的文本单元表，从而建立从**源文本块**到**图谱元素**的双向可溯源链接。

## 1. 我们现在在哪里？

从如下的管道结构可以看出，当`TextUnit`利用`create_base_text_units`这个`Workflow`是生成之后就一致不曾改变。之所以`Workflow`被命名为`create_base_text_units`，就意味着它创建的仅仅是一个基础的`TextUnit`，还有待补充的内容。

```markdown
load_input_documents
    └── create_base_text_units
            └── create_final_documents
                    └── extract_graph
                            └── finalize_graph
                                    └──extract_covariates
                                            └── create_communities
                                                    └── **create_final_text_units**
                                                            └──create_community_reports
                                                                    └── generate_text_embeddings
```

通过[GraphRAG实现原理-07:将文档分割为可供LLM处理的切片](https://jaydenai.blog.csdn.net/article/details/169337244)提供的演示实例可知`create_base_text_units`这个`Workflow`创建的`text_units`表具有如下的结构，只包含针对文档的引用、切片文本和长度（Token数）。当`create_final_text_units`这个`Workflow`执行的时候，`extract_graph`和`finalize_graph`已经完成了实体关系图的构建，`extract_covariates`也完成了协变量的构建（可选），并且对应的元素都包含针对`TextUnit`的引用，它需要做的就是将实体、关系和协变量的ID写入`text_units`表中相应的`TextUnit`记录，由此建立双向关联。

```text
 #   Column       Non-Null Count  Dtype
---  ------       --------------  -----
 0   id           4 non-null      str  
 1   document_id  4 non-null      str  
 2   text         4 non-null      str  
 3   n_tokens     4 non-null      int64
 ```

 ## 2. Workflow的实现

 `create_final_text_units`这个`Workflow`的`WorkflowFunction`对应如下这个`run_workflow`函数（所在模块目录为`graphrag/workflows/create_final_text_units`）。实体、关系和协变量ID的写入实现在`create_final_text_units`函数中，具体逻辑不外乎先读取`entities`、`relations`和`covariates`表建立三个ID与`TextUnit`的ID的映射关系，再逐行读取每条`text_units`表的每条记录并写入对应的三个ID。

```python
 async def run_workflow(
    config: GraphRagConfig,
    context: PipelineRunContext,
) -> WorkflowFunctionOutput:
    has_covariates = (
        config.extract_claims.enabled
        and await context.output_table_provider.has("covariates")
    )

    cov_ctx = (
        context.output_table_provider.open("covariates")
        if has_covariates
        else nullcontext()
    )

    async with (
        context.output_table_provider.open(
            "text_units",
            transformer=transform_text_unit_row,
        ) as text_units_table,
        context.output_table_provider.open(
            "entities",
            transformer=transform_entity_row,
        ) as entities_table,
        context.output_table_provider.open(
            "relationships",
            transformer=transform_relationship_row,
        ) as relationships_table,
        context.output_table_provider.open("text_units") as output_table,
        cov_ctx as covariates_table,
    ):
        sample = await create_final_text_units(
            text_units_table,
            entities_table,
            relationships_table,
            output_table,
            covariates_table,
        )
    return WorkflowFunctionOutput(result=sample)
```

## 3. 查看写入的实体、关系和协变量ID

[GraphRAG实现原理-12:根据实体关系图构建层级化的社区（Community）](https://jaydenai.blog.csdn.net/article/details/169530483)提供了演示程序完成了初始实体关系图的构建，现在我们在此基础上应用`create_final_text_units`这个`Workflow`通过进一步完善`TextUnit`，实现它和实体、关系和协变量的双向溯源。我们通过如下的程序执行一个由`create_final_text_units`这个单一`Workflow`构建的管道。在完成管道执行后，我们将`./output/text_units.parquet`文件加载到一个`DataFrame`中，并将表结构和数据输出来。可以看出`text_units`表多出了`entity_ids`、`relationship_ids` 和`relationship_ids`三个字符串列表类型的字段。

```python
import asyncio
import graphrag.index.workflows.create_final_text_units as  create_final_text_units
from graphrag.index.typing.pipeline import Pipeline
from graphrag.config.load_config import load_config
from graphrag.index.run.run_pipeline import run_pipeline
from graphrag.callbacks.noop_workflow_callbacks import NoopWorkflowCallbacks
import pandas as pd

async def main():   
    pipeline = Pipeline(workflows=[
        ("create_final_text_units", create_final_text_units.run_workflow)
    ])
    async for _ in  run_pipeline(
        pipeline = pipeline,
        config = load_config(root_dir="./"),
        callbacks= NoopWorkflowCallbacks(),
    ):
        pass

    print(f"----------text_units schema----------")
    df = pd.read_parquet('./output/text_units.parquet')
    print(df.info())

    print(f"----------text_units records----------")
    for _, row in df.iterrows():
        for col in df.columns:
            print(f"{col}: {row[col]}, ")
        print() 
asyncio.run(main())
```
