# [GraphRAG实现原理-14]为每个社区生成一份服务于查询的摘要

为了解决Baseline RAG信息割裂的问题，GraghRAG先从原始文本中提取实体关系图，进而生成具有层级关系的社区。它相当于将原来非关系的完全离散的信息重新组成成树形化的可检索结构，最终解决RAG系统的终极问题：为查询提供全面（召回率）和匹配（准确率）的上下文。对于Global查询来说，它可以利用从上层社区开始检验当前社区是否与对当前查询相关，如果不相关，它就放弃当前社区并且可以选择不在继续向上追溯（可配置）。最终选择相关的社区内容，并组成上下文完成最终的查询。为了提高最终生成的上下文的质量，还需要为每个社区生成一份摘要准确地对它进行描述。这分摘要被称为社区报告，该报告由`create_community_reports`这个`Workflow`完成。

## 1. 我们现在在哪里？

`create_community_reports`这个`Workflow`是整个standard管道倒数第二个Workflow。对于Global和DRIFT查询来说，当这个Workflow将社区报告生成之后，意味着整个索引工作便宣告结束，因为这两种查询方式不需要generate_text_embeddings这个Workflow生成的向量数据库，它是为Local查询服务的。

```markdown
load_input_documents
    └── create_base_text_units
            └── create_final_documents
                    └── extract_graph
                            └── finalize_graph
                                    └──extract_covariates
                                            └── create_communities
                                                    └── create_final_text_units
                                                            └──**create_community_reports**
                                                                    └── generate_text_embeddings
```

`create_community_reports`这个`Workflow`在生成社区报告的时候不仅仅使用由`create_communities`这个`Workflow`生成的社区，还需要综合使用到前面使用到的实体关系图和协变量/声明（如果对应的开关被打开），所以`communities`、`entities`、`relationships`和`covariables`这个四个表都是它的输入，它最终将社区报告输入到`community_reports`表中。

## 2. 社区报告创建配置

`create_community_reports`这个`Workflow`对应GraphRagConfig的community_reports字段所在的配置节，对应的配置类型`CommunityReportsConfig`定义了如下的配置选项。

```python
class GraphRagConfig(BaseModel):
    community_reports: CommunityReportsConfig = Field(
        description="The community reports configuration to use.",
        default=CommunityReportsConfig(),
    )

class CommunityReportsConfig(BaseModel):
    completion_model_id: str = Field(
        description="The model ID to use for community reports.",
        default=graphrag_config_defaults.community_reports.completion_model_id,
    )
    model_instance_name: str = Field(
        description="The model singleton instance name. This primarily affects the cache storage partitioning.",
        default=graphrag_config_defaults.community_reports.model_instance_name,
    )
    graph_prompt: str | None = Field(
        description="The community report extraction prompt to use for graph-based summarization.",
        default=graphrag_config_defaults.community_reports.graph_prompt,
    )
    text_prompt: str | None = Field(
        description="The community report extraction prompt to use for text-based summarization.",
        default=graphrag_config_defaults.community_reports.text_prompt,
    )
    max_length: int = Field(
        description="The community report maximum length in tokens.",
        default=graphrag_config_defaults.community_reports.max_length,
    )
    max_input_length: int = Field(
        description="The maximum input length in tokens to use when generating reports.",
        default=graphrag_config_defaults.community_reports.max_input_length,

@dataclass
class CommunityReportDefaults:
    graph_prompt: None = None
    text_prompt: None = None
    max_length: int = 2000
    max_input_length: int = 8000
    completion_model_id: str = DEFAULT_COMPLETION_MODEL_ID
    model_instance_name: str = "community_reporting"
```

`CommunityReportsConfig`的配置选项说明如下，`CommunityReportDefaults`提供为每个选项提供的兜底的默认值：

- **completion_model_id**：指定生成社区报告所用的补全模型 ID。
- **model_instance_name**：模型单例实例名，主要用于缓存存储分区，影响不同实例的缓存隔离。
- **graph_prompt**：基于图结构生成社区报告时使用的提示词；可为`None`，提供时作为提示词文件路径读取。
- **text_prompt**：基于文本生成社区报告时使用的提示词；可为`None`，提供时作为提示词文件路径读取。
- **max_length**：社区报告的最大长度（以token计），控制生成报告的篇幅上限。
- **max_input_length**：生成报告时允许的最大输入长度（以token计），用于限制送入模型的上下文规模。

`CommunityReportsConfig`定义了量提示词模板：

- **graph_prompt**：用于基于知识图谱中的实体与关系来生成社区报告。这个图结构数据会被序列化并填入`{input_text}` 占位符，引导 LLM 输出包含标题、摘要、重要性评分和发现列表的结构化报告。
- **text_prompt**: 定位是基于`TextUnits`进行汇总，供**文本变体工作流**使用。它并不处理图结构化的实体和关系，而是直接面向原始文本片段。

`CommunityReportsConfig`定义了如下的`resolved_prompts`方法根据设置返回这两个提示词，并将其封装成返回的`CommunityReportPrompts`对象。GraphRAG目前只会使用`graph_prompt`，默认的提此词模板如下所示。执行graphrag init命令时会将此内容写入`prompts/extract_graph.txt`中。

```python
@dataclass
class CommunityReportPrompts:
    graph_prompt: str
    text_prompt: str

class CommunityReportsConfig(BaseModel):
    def resolved_prompts(self) -> CommunityReportPrompts:
        return CommunityReportPrompts(
            graph_prompt=Path(self.graph_prompt).read_text(encoding="utf-8")
            if self.graph_prompt
            else COMMUNITY_REPORT_PROMPT,
            text_prompt=Path(self.text_prompt).read_text(encoding="utf-8")
            if self.text_prompt
            else COMMUNITY_REPORT_TEXT_PROMPT,
        )
```


- **resolved_prompts**：解析并返回`CommunityReportPrompts`；`graph_prompt` 或`text_prompt` 存在时从对应文件路径读取UTF-8文本，否则分别使用内置默认提示词`COMMUNITY_REPORT_PROMPT` 和`COMMUNITY_REPORT_TEXT_PROMPT`。

## 3. Workflow实现

`create_community_reports`这个`Workflow`的`WorkflowFunction`对应如下这个`run_workflow`函数（所在模块目录为`graphrag/workflows/create_community_reports`）。如代码所示，此函数会读取`communities`、`entities`、`relationships`和`covariables`这个四个表并将它们转换成`DataFrame`，调用配置的`resolved_prompts`方法得到用于社区摘要的提示词，并根据提供的模型配置创建作为LLM的`LLMCompletion`对象。最终将这些对象传入`create_community_reports`为每个社区生成报告。

```python
async def run_workflow(
    config: GraphRagConfig,
    context: PipelineRunContext,
) -> WorkflowFunctionOutput:
    reader = DataReader(context.output_table_provider)
    relationships = await reader.relationships()
    entities = await reader.entities()
    communities = await reader.communities()

    claims = None
    if config.extract_claims.enabled and await context.output_table_provider.has(
        "covariates"
    ):
        claims = await reader.covariates()

    model_config = config.get_completion_model_config(
        config.community_reports.completion_model_id
    )
    prompts = config.community_reports.resolved_prompts()

    model = create_completion(
        model_config,
        cache=context.cache.child(config.community_reports.model_instance_name),
        cache_key_creator=cache_key_creator,
    )

    tokenizer = model.tokenizer

    output = await create_community_reports(
        relationships=relationships,
        entities=entities,
        communities=communities,
        claims_input=claims,
        callbacks=context.callbacks,
        model=model,
        tokenizer=tokenizer,
        prompt=prompts.graph_prompt,
        max_input_length=config.community_reports.max_input_length,
        max_report_length=config.community_reports.max_length,
        num_threads=config.concurrent_requests,
        async_type=config.async_mode,
    )

    await context.output_table_provider.write_dataframe("community_reports", output)

    logger.info("Workflow completed: create_community_reports")
    return WorkflowFunctionOutput(result=output)
```

`create_community_reports`函数在进行社区摘要时会按社区层级依次处理：低层（叶子社区）先生成报告，高层社区在构建上下文时可以引用低层已生成的报告，因此层级之间是串行屏障，但同一层级内的社区可以并发处理，受`concurrent_requests`配置限流。每个社区会调用LLM输出符合结构的文本，包含标题、摘要、重要性评分、评分说明和发现列表。

## 4. 查看生成的社区报告

[GraphRAG实现原理-12:根据实体关系图构建层级化的社区]()提供的实例演示将社区创建出来，现在我们在此基础上应用`create_community_reports`这个`Workflow`完成针对社区报表的创建。我们通过如下的程序执行一个由`create_community_reports`这个单一`Workflow`构建的管道。在完成管道执行后，我们将`./output/community_reports.parquet`文件加载到一个`DataFrame`中，并将表结构和第一个社区报表数出来（报表内容过程，没法全量输出）。`community_reports`表结构在[GraphRAG实现原理-02:基于社区（Community）的知识图谱](https://jaydenai.blog.csdn.net/article/details/168962194)中具有详细介绍。

```python
import asyncio
import graphrag.index.workflows.create_community_reports as  create_community_reports
from graphrag.index.typing.pipeline import Pipeline
from graphrag.config.load_config import load_config
from graphrag.index.run.run_pipeline import run_pipeline
from graphrag.callbacks.noop_workflow_callbacks import NoopWorkflowCallbacks
import pandas as pd

async def main():   
    pipeline = Pipeline(workflows=[
        ("create_community_reports", create_community_reports.run_workflow)
    ])
    async for _ in  run_pipeline(
        pipeline = pipeline,
        config = load_config(root_dir="./"),
        callbacks= NoopWorkflowCallbacks(),
    ):
        pass

    print(f"----------community_reports schema----------")
    df = pd.read_parquet('./output/community_reports.parquet')
    print(df.info())
    for _, row in df.iterrows():
        for col in df.columns:
            print(f"{col}: {row[col]}, ")
        return 
asyncio.run(main())
```

## 5. 查看LLM的输入和输出

由于社区摘要是LLM生成的，虽然我们从注册的提示词和上面实例演示可以大致猜出LLM的输入和输出，但是我们还是有必要看看LLM接收到的原始输入和输出是什么，为此我们编写了如下的演示程序。我们通过继承`LiteLLMCompletion`定义了`TraceableLLMCompletion`类型，并通过重写`completion_async`方法在调用基类同名方法前后输入了原始的输入(包含输入的消息和响应Schema)和输出（由于内容太多，我们只跟踪一次调用）。我们按照上面演示的方式创建社区报表，并在此之前通过调用`register_completion`函数完成了`TraceableLLMCompletion`的中注册。

```python
import asyncio
from typing import override,Unpack,AsyncIterator
import graphrag.index.workflows.create_community_reports as  create_community_reports
from graphrag.index.typing.pipeline import Pipeline
from graphrag.config.load_config import load_config
from graphrag.index.run.run_pipeline import run_pipeline
from graphrag.callbacks.noop_workflow_callbacks import NoopWorkflowCallbacks
from graphrag_llm.completion.lite_llm_completion import LiteLLMCompletion
from graphrag_llm.completion.completion_factory import register_completion
from graphrag_llm.config.types import LLMProviderType
from graphrag_llm.types import (
        LLMCompletionArgs,
        ResponseFormat,
    )
from graphrag_llm.types import LLMCompletionChunk, LLMCompletionResponse
trace_enabled = True
class TraceableLLMCompletion(LiteLLMCompletion):
    @override
    async def completion_async(
            self,
            /,
            **kwargs: Unpack["LLMCompletionArgs[ResponseFormat]"],
        ) -> "LLMCompletionResponse[ResponseFormat] | AsyncIterator[LLMCompletionChunk]":
        global trace_enabled
        if not trace_enabled:            
            return await super().completion_async(**kwargs)
        trace_enabled = False
        print(f"""\
----------messages----------
{kwargs.get("messages")}
----------response_format----------
{kwargs.get("response_format")}
        """)
        result:LLMCompletionResponse[ResponseFormat] = await super().completion_async(**kwargs)  # type: ignore
        print(f"""\
----------respnse----------
{result.content}
""")
        
        return result           

register_completion(LLMProviderType.LiteLLM, TraceableLLMCompletion)

async def main():   
    pipeline = Pipeline(workflows=[
        ("create_community_reports", create_community_reports.run_workflow)
    ])
    async for output in  run_pipeline(
        pipeline = pipeline,
        config = load_config(root_dir="./"),
        callbacks= NoopWorkflowCallbacks(),
    ):
        print(output)
asyncio.run(main())
```
