# [GraphRAG实现原理-16]四种查询方式之一：Basic Search

前面的系列文章主要介绍了GraphRAG索引的构建，我使用了10篇文章详细介绍了构成`standard`索引管道的10个`Workflow`。这个管道执行之后，会利用加载的输入文档生成如下这些表：

- **documents**：原始输入文档的记录表，用于追溯文档与其拆分出的文本块之间的来源关系，在GraphRAG检索中不直接使用。
- **text_units**：文档切分后的文本块，是图抽取的基本分析单元，同时为抽取出的实体、关系等提供溯源依据。
- **entities**：从文本块中抽取的实体（人物、地点、事件等），包含名称、类型和描述，是知识图谱的节点。
- **relationships**：两个实体之间的关联边，包含源实体、目标实体及关系描述，支撑图谱上的多跳推理。
- **communities**：通过Hierarchical Leiden算法对实体图进行层次化聚类得到的社区结构，用于在不同粒度上组织和导航图谱。
- **community_reports**：对每个社区内容生成的LLM摘要报告，提供多层次的全局理解，是Global Search等查询的核心依据。

管道最后执行的`Workflow`还会为实体描述、切片文本和社区内容生成嵌入向量并写入配置的向量存储。整个索引构建的这些表最终都是为查询服务的，GraphRAG之处多种查询模式，我们将通过这篇以及后续文章对它们的设计和实现原理进行系统介绍。

## 1. 四种查询模式

GraphRAG主要提供了如下四种类型查询模式：

- **Basic Search**：基础的向量RAG实现。直接在文本单元块上做向量相似度检索，取**top-k**块作为上下文生成答案，不经过知识图谱或社区结构，主要用于与传统RAG方案进行对比基线。
- **Local Search（局部搜索）**：面向具体实体的问题。通过实体嵌入找到相关实体，再结合知识图谱中的关系、社区报告以及原始文本块组装上下文，适合回答**李明的咖啡店开在哪里**”类指名道姓的问题。
- **DRIFT Search**：局部搜索的增强版，融合了全局与局部策略。先用社区报告获得宽泛的初始答案，再通过迭代追问和局部检索深入细节，适合既需要广度又需要深度的复杂、探索性问题。
- **Global Search（全局搜索）**：面向整个数据集的宏观问题。以所有社区报告为输入，采用`map-reduce`方式：先让每份报告独立评估相关性并生成中间回答，再汇总筛选出最终答案，适合**这批报告的主要趋势是什么**这类全局性问题。

本篇文章主要介绍最简单的Basic Search查询模式。我们可以按照如下的方式在执行`graphrag query`命令的时候将`--method`/`-m`参数设置为`basic`来使用这种查询模式。

```bash
(.venv) E:\graphrag\graphrag_explor>graphrag query -m basic 李明的咖啡店开在哪里？

李明的咖啡店最终开在**写字楼商圈**，不是学校附近，也不是老城区街角。他当时对比了三个地点后，认为写字楼商圈的工作日客流更稳定，尽管周末较冷清，但还是选择了这里；门店月租为**一万五千元**，并签约了**两年** [Data: Sources (0)]。
```

## 2. 针对搜索引擎的抽象

GraphRAG将执行上述四种查询的核心组件抽象成通过`BaseSearch`表示的搜索引擎。这个一个泛型类型，泛型参数`T`表示一个用来构建查询上下文的ContextBuilder。它提供了`search`和`stream_search`这两个抽象方法提供基于阻塞和流式查询，前者返回代表最终结果的`SearchResult`对象，后者利用迭代器实时返回生成的内容。

```python
class BaseSearch(ABC, Generic[T]):
    def __init__(
        self,
        model: "LLMCompletion",
        context_builder: T,
        tokenizer: Tokenizer | None = None,
        model_params: dict[str, Any] | None = None,
        context_builder_params: dict[str, Any] | None = None,
    ):
        self.model = model
        self.context_builder = context_builder
        self.tokenizer = tokenizer or model.tokenizer
        self.model_params = model_params or {}
        self.context_builder_params = context_builder_params or {}

    @abstractmethod
    async def search(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
        **kwargs,
    ) -> SearchResult:
        msg = "Subclasses must implement this method"
        raise NotImplementedError(msg)

    @abstractmethod
    async def stream_search(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
    ) -> AsyncGenerator[str, None]:
        yield ""
        msg = "Subclasses must implement this method"
        raise NotImplementedError(msg)
```

初始化`BaseSearch`对象需要提供如下的参数：

- **model**：表示Completion模型的`LLMCompletion`对象；
- **context_builder**：用来构建查询上下文的ContextBuilder；
- **tokenizer**：用来计算token数的`Tokenizer`，默认由`LLMCompletion`提供；
- **model_params**：初始化或者定制`LLMCompletion`对象的参数；
- **context_builder_params**：初始化或者定制`context_builder`的参数。

### 2.1 将对话历史作为上下文

`BaseSearch`的`search`和`stream_search`方法除了接受组为查询文本的`query`参数之外，还定义了一个`ConversationHistory`类型的可缺省参数`conversation_history`。顾名思义，`ConversationHistory`表示对话历史，我们可以利用它来实现Session的功能，即将同一个Session中的对话历史作为上下文传递了LLM。一个`ConversationHistory`对象本质上就是一个消息列表，不过和很多Agent框架的定义不同，这里的消息通过`ConversationTurn`来表示。从命名来看，这里的`ConversationTurn`想表达是一个对话的轮次，但是从定义来看，它就是一个由角色和内容组成的消息。我们常规理解的对话轮次一般是由用户发起的一轮对话，

```python
class ConversationHistory:
    turns: list[ConversationTurn]
    def __init__(self):
        self.turns = []

@dataclass
class ConversationTurn:
    role: ConversationRole
    content: str

class ConversationRole(str, Enum):
    SYSTEM = "system"
    USER = "user"
    ASSISTANT = "assistant"
```

`ConversationHistory`还定义了如下这些方法：

- **from_list**：从`{"role", "content"}`字典列表构造`ConversationHistory`，自动解析角色并填充轮次。
- **add_turn**：向历史中追加一条指定角色和内容的对话轮次。
- **to_qa_turns**：把轮次序列转换为QA对，用户轮次作为问题，其后连续的助手轮次作为该问题的回答列表。
- **get_user_turns**：按时间倒序收集最近的用户轮次内容，可限制最大数量。
- **build_context**：将对话历史构建为系统提示词可用的上下文文本和DataFrame，支持仅含用户轮次、限制QA轮数、token上限、近因偏置、列分隔符和上下文名称。

```python
class ConversationHistory:
    @classmethod
    def from_list(
        cls, conversation_turns: list[dict[str, str]]
    ) -> "ConversationHistory"
    def add_turn(self, role: ConversationRole, content: str)
    def to_qa_turns(self) -> list[QATurn]
    def get_user_turns(self, max_user_turns: int | None = 1) -> list[str]
    def build_context(
        self,
        tokenizer: Tokenizer | None = None,
        include_user_turns_only: bool = True,
        max_qa_turns: int | None = 5,
        max_context_tokens: int = 8000,
        recency_bias: bool = True,
        column_delimiter: str = "|",
        context_name: str = "Conversation History",
    ) -> tuple[str, dict[str, pd.DataFrame]]
```

`to_qa_turns`方法会将消息列表转换成一个`QATurn`列表。顾名思义，一个`QATurn`表示一轮QA对话。`user_query`字段返回的`ConversationTurn`表示用户的提问，`assistant_answers`字段表示的一组`ConversationTurn`表示LLM的答复。`get_answer_text`方法负责将这组答复转换成文本。

```python
@dataclass
class QATurn:
    user_query: ConversationTurn
    assistant_answers: list[ConversationTurn] | None = None
    def get_answer_text(self) -> str | None

```

### 2.2 查询的完整结果

`BaseSearch`的`search`方法返回的`SearchResult`对象承载了完整的查询结果。

```python
@dataclass
class SearchResult:
    response: str | dict[str, Any] | list[dict[str, Any]]
    context_data: str | list[pd.DataFrame] | dict[str, pd.DataFrame]
    context_text: str | list[str] | dict[str, str]
    completion_time: float
    llm_calls: int
    prompt_tokens: int
    output_tokens: int
    llm_calls_categories: dict[str, int] | None = None
    prompt_tokens_categories: dict[str, int] | None = None
    output_tokens_categories: dict[str, int] | None = None
```

整个查询结果由如下的信息组成：

- **response**：承载LLM针对查询的答复内容，可以是字符串、字典或字典列表。
- **context_data**：构建上下文所用的原始数据，可以是字符串、`DataFrame`列表或按名称索引的`DataFrame`字典。
- **context_text**：实际进入上下文窗口的文本字符串，由`context_data`构建生成。
- **completion_time**：完成本次查询的耗时。
- **llm_calls**：本次查询的LLM调用总次数。
- **prompt_tokens**：本次查询消耗的提示词token总数。
- **output_tokens**：本次查询生成的输出token总数。
- **llm_calls_categories**：按类别拆分的LLM调用次数，可选。
- **prompt_tokens_categories**：按类别拆分的提示词token用量，可选。
- **output_tokens_categories**：按类别拆分的输出token用量，可选。

## 3. 总体执行流程

如下这个派生自`BaseSearch[BasicContextBuilder]`的`BasicSearch`提供了针对Basic Search的实现。`BasicContextBuilder`是一个抽象类，它利用抽象方法`build_context`根据查询文本的对话历史创建RAG查询的上下文。

```python
class BasicSearch(BaseSearch[BasicContextBuilder]):
    def __init__(
        self,
        model: "LLMCompletion",
        context_builder: BasicContextBuilder,
        tokenizer: Tokenizer | None = None,
        system_prompt: str | None = None,
        response_type: str = "multiple paragraphs",
        callbacks: list[QueryCallbacks] | None = None,
        model_params: dict[str, Any] | None = None,
        context_builder_params: dict | None = None,
    )

class BasicContextBuilder(ABC):
    @abstractmethod
    def build_context(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
        **kwargs,
    ) -> ContextBuilderResult

@dataclass
class ContextBuilderResult:
    context_chunks: str | list[str]
    context_records: dict[str, pd.DataFrame]
    llm_calls: int = 0
    prompt_tokens: int = 0
    output_tokens: int = 0
```

`build_context`方法构建的上下文体现为一个`ContextBuilderResult`对象，它提供如下的上下文信息：

- **context_chunks**：构建出的上下文文本块，可以是单个字符串或字符串列表。
- **context_records**：按名称索引的`DataFrame`字典，记录构建上下文所用的结构化数据。
- **llm_calls**：构建上下文过程中产生的LLM调用次数，默认0。
- **prompt_tokens**：构建上下文消耗的提示词 token数，默认0。
- **output_tokens**：构建上下文消耗的输出token数，默认0。

下面给出了`search`方法实施查询的简化代码，我们来归纳一下大致的执行流程：

- 调用`BasicContextBuilder`的`build_context`根据指定的查询文本的对话历史创建`ContextBuilderResult`对象；
- 将`ContextBuilderResult`的`context_chunks`字段和响应类型（默认为`multiple paragraphs`）填充模板的上述两个占位符，并生成完成的系统提示词；
- 利用`CompletionMessagesBuilder`将系统提示词和查询文本转换成对应角色的消息，并组成一个消息列表；
- 将消息列表作为参数以流的形式调用代表LLM的`LLMCompletion`对象的`completion_async`方法，并实时返回生成的文本。

```python
class BasicSearch(BaseSearch[BasicContextBuilder]):
    async def stream_search(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
    ) -> AsyncGenerator[str, None]:
        context_result = self.context_builder.build_context(
            query=query,
            conversation_history=conversation_history,
            **self.context_builder_params,
        )
        search_prompt = self.system_prompt.format(
            context_data=context_result.context_chunks, response_type=self.response_type
        )

        messages_builder = (
            CompletionMessagesBuilder()
            .add_system_message(search_prompt)
            .add_user_message(query)
        )

        for callback in self.callbacks:
            callback.on_context(context_result.context_records)

        response_stream: AsyncIterator[
            LLMCompletionChunk
        ] = await self.model.completion_async(
            messages=messages_builder.build(),
            stream=True,
            **self.model_params,
        )  # type: ignore

        async for chunk in response_stream:
            response_text = chunk.choices[0].delta.content or ""
            for callback in self.callbacks:
                callback.on_llm_new_token(response_text)
            yield response_text
```

## 4. 上下文的构建

RAG核心都是如何根据原始查询检索相关内容并生成后续调用LLM的上下文。对于`BasicSearch`来说，这项核心任务自然就落在`BasicContextBuilder`对象的头上。这是一个抽象类，GraphRAG默认使用的是如下这个派生于它的`BasicSearchContext`。

```python
class BasicSearchContext(BasicContextBuilder):
    def __init__(
        self,
        text_embedder: "LLMEmbedding",
        text_unit_embeddings: VectorStore,
        text_units: list[TextUnit] | None = None,
        tokenizer: Tokenizer | None = None,
        embedding_vectorstore_key: str = "id",
    )
```

初始化`BasicSearchContext`对象需要提供如下的参数：

- **text_embedder**：用于将查询文本转换为向量的嵌入模型，具体体现为一个`LLMEmbedding`对象。
- **text_unit_embeddings**：文本单元的向量存储，用于相似度检索，具体体现为一个`VectorStore`对象。
- **text_units**：一组表示文本切片的`TextUnit`列表，用于按检索到的ID取回文本内容。
- **tokenizer**：用于token计数的分词器，默认使用全局分词器。
- **embedding_vectorstore_key**：向量库中关联文本单元的键，默认`id`。

在[GraphRAG实现原理-15:将实体、切片和社区写入向量数据库](https://jaydenai.blog.csdn.net/article/details/169811619)提供了对`LLMEmbedding`对象以及表示向量存储的`VectorStore`具有详细介绍。通过这篇文章我们知道`VectorStore`包含三个向量表，这里使用的是存储切片文本的向量表。整个检索和上下文的构建均实现在如下所示的`build_context`方法中，具体的执行流程如下：

- 调用作为向量存储的`VectorStore`对象的`similarity_search_by_text`方法针对指定的查询文本实施相似度检索，并使用`LLMEmbedding`负责嵌入向量的生成。默认采用`top 10`进行检索，并得到的是一组`VectorStoreSearchResult`对象。
- 从`VectorStoreSearchResult`列表中得到所有的`text_unit_id`。
- 利用得到的`text_unit_id`列表从构造函数中指定的`TextUnit`列表中筛选匹配的`TextUnit`。
- 根据设置`max_context_tokens`对`TextUnit`列表再度实施过滤，确保不会超出设置的token数量。
- 对得到的`TextUnit`列表以CSV形式格式化，生成的文本将作为上下文的内容。

```python
class BasicSearchContext(BasicContextBuilder):
    def build_context(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
        k: int = 10,
        max_context_tokens: int = 12_000,
        context_name: str = "Sources",
        column_delimiter: str = "|",
        text_id_col: str = "id",
        text_col: str = "text",
        **kwargs,
    ) -> ContextBuilderResult:
        if query != "":
            related_texts = self.text_unit_embeddings.similarity_search_by_text(
                text=query,
                text_embedder=lambda t: (
                    self.text_embedder.embedding(input=[t]).first_embedding
                ),
                k=k,
            )

            text_unit_ids = {t.document.id for t in related_texts}
            text_units_filtered = []
            text_units_filtered = [
                {text_id_col: t.short_id, text_col: t.text}
                for t in self.text_units or []
                if t.id in text_unit_ids
            ]
            related_text_df = pd.DataFrame(text_units_filtered)
        else:
            related_text_df = pd.DataFrame({
                text_id_col: [],
                text_col: [],
            })

        current_tokens = 0
        text_ids = []
        current_tokens = len(
            self.tokenizer.encode(text_id_col + column_delimiter + text_col + "\n")
        )
        for i, row in related_text_df.iterrows():
            text = row[text_id_col] + column_delimiter + row[text_col] + "\n"
            tokens = len(self.tokenizer.encode(text))
            if current_tokens + tokens > max_context_tokens:
                msg = f"Reached token limit: {current_tokens + tokens}. Reverting to previous context state"
                logger.warning(msg)
                break

            current_tokens += tokens
            text_ids.append(i)
        final_text_df = cast(
            "pd.DataFrame",
            related_text_df[related_text_df.index.isin(text_ids)].reset_index(
                drop=True
            ),
        )
        final_text = final_text_df.to_csv(
            index=False, escapechar="\\", sep=column_delimiter
        )

        return ContextBuilderResult(
            context_chunks=final_text,
            context_records={context_name.lower(): final_text_df},
        )
```

到此为止我们可以看出Basic RAG与传统的基于向量数据库的RAG本质上没有区别，它就是根据查询文本提取出相似度最高的K个切片（`TextUnit`）并格式化成进一步调用LLM的上下文。

## 5. BasicSearch的配置

`BasicSearch`在作为整体配置的`GraphRagConfig`中利用`basic_search`字段来配置，对应的`BasicSearchConfig`类型定义如下。

```python
class GraphRagConfig(BaseModel):
    basic_search: BasicSearchConfig = Field(
        description="The basic search configuration.", default=BasicSearchConfig()
    )

class BasicSearchConfig(BaseModel):
    prompt: str | None = Field(
        description="The basic search prompt to use.",
        default=graphrag_config_defaults.basic_search.prompt,
    )
    completion_model_id: str = Field(
        description="The model ID to use for basic search.",
        default=graphrag_config_defaults.basic_search.completion_model_id,
    )
    embedding_model_id: str = Field(
        description="The model ID to use for text embeddings.",
        default=graphrag_config_defaults.basic_search.embedding_model_id,
    )
    k: int = Field(
        description="The number of text units to include in search context.",
        default=graphrag_config_defaults.basic_search.k,
    )
    max_context_tokens: int = Field(
        description="The maximum tokens.",
        default=graphrag_config_defaults.basic_search.max_context_tokens,
    )
```

`BasicSearchConfig`提供了如下的配置选项：

- **prompt**：使用的提示词模板。
- **completion_model_id**：使用Completion模型ID。
- **embedding_model_id**：文本嵌入使用的模型ID。
- **k**：纳入搜索上下文的文本单元数量。
- **max_context_tokens**：上下文允许的最大token数。

## 6. 搜索引擎的创建

上面说过，GraphRAG利用`BaseSearch`作为不同查询模式的搜索引擎，作为Basic Search搜索引擎的`BasicSearch`通过如下这个`get_basic_search_engine`函数创建而成。具体的创建逻辑如下：

- 根据`GraphRagConfig`提供的Completion模型和嵌入模型配置创建对应的`LLMCompletion`和`LLMEmbedding`对象，以及用来计算token的`Tokenizer`对象；
- 从`GraphRagConfig`中的`basic_search`字段提取`BasicSearchConfig`配置；
- 利用`LLMCompletion`以及它提供的`Tokenizer`、`VectorStore`和`TextUnit`列表创建用来构建上下文的`BasicSearchContext`对象；
- 根据上面创建和参数指定的`LLMCompletion`、系统提示词、`BasicSearchContext`等创建返回的`BasicSearch`等对象创建返回的`BasicSearch`对象。

```python
def get_basic_search_engine(
    text_units: list[TextUnit],
    text_unit_embeddings: VectorStore,
    config: GraphRagConfig,
    response_type: str,
    system_prompt: str | None = None,
    callbacks: list[QueryCallbacks] | None = None,
) -> BasicSearch:
    chat_model_settings = config.get_completion_model_config(
        config.basic_search.completion_model_id
    )
    chat_model = create_completion(chat_model_settings)
    embedding_model_settings = config.get_embedding_model_config(
        config.basic_search.embedding_model_id
    )
    embedding_model = create_embedding(embedding_model_settings)
    tokenizer = chat_model.tokenizer

    bs_config = config.basic_search
    model_params = chat_model_settings.call_args
    return BasicSearch(
        model=chat_model,
        system_prompt=system_prompt,
        response_type=response_type,
        context_builder=BasicSearchContext(
            text_embedder=embedding_model,
            text_unit_embeddings=text_unit_embeddings,
            text_units=text_units,
            tokenizer=tokenizer,
        ),
        tokenizer=tokenizer,
        model_params=model_params,
        context_builder_params={
            "embedding_vectorstore_key": "id",
            "k": bs_config.k,
            "max_context_tokens": bs_config.max_context_tokens,
        },
        callbacks=callbacks,
    )
```

`graphrag query --method basic`命令行最终会根据`--streaming`参数选择调用`basic_search`或者`basic_search_streaming`函数。传入的`GraphRagConfig`对象通过解析配置文件（settings.yaml）生成，`text_units`参数指定的`DataFrame`来源于`text_units`索引表。`basic_search`函数最终还是会调用到`basic_search_streaming`函数上，后者会利用上面这个`get_basic_search_engine`函数得到作为搜索引擎的`BasicSearch`对象，并调用其`stream_search`完成最终的查询任务。

```python
async def basic_search(
    config: GraphRagConfig,
    text_units: pd.DataFrame,
    response_type: str,
    query: str,
    callbacks: list[QueryCallbacks] | None = None,
    verbose: bool = False,
) -> tuple[
    str | dict[str, Any] | list[dict[str, Any]],
    str | list[pd.DataFrame] | dict[str, pd.DataFrame],
]:
   
    callbacks = callbacks or []
    full_response = ""
    context_data = {}

    def on_context(context: Any) -> None:
        nonlocal context_data
        context_data = context

    local_callbacks = NoopQueryCallbacks()
    local_callbacks.on_context = on_context
    callbacks.append(local_callbacks)

    async for chunk in basic_search_streaming(
        config=config,
        text_units=text_units,
        response_type=response_type,
        query=query,
        callbacks=callbacks,
    ):
        full_response += chunk
    return full_response, context_data

def basic_search_streaming(
    config: GraphRagConfig,
    text_units: pd.DataFrame,
    response_type: str,
    query: str,
    callbacks: list[QueryCallbacks] | None = None,
    verbose: bool = False,
) -> AsyncGenerator:
    embedding_store = get_embedding_store(
        config=config.vector_store,
        embedding_name=text_unit_text_embedding,
    )
    prompt = load_search_prompt(config.basic_search.prompt)
    search_engine = get_basic_search_engine(
        config=config,
        text_units=read_indexer_text_units(text_units),
        text_unit_embeddings=embedding_store,
        response_type=response_type,
        system_prompt=prompt,
        callbacks=callbacks,
    )
    return search_engine.stream_search(query=query)
```
