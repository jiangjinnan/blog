# [GraphRAG实现原理-17]四种查询方式之二：Local Search

[GraphRAG实现原理-16：四种查询方式之一：Basic Search](https://jaydenai.blog.csdn.net/article/details/169820002)对Basic Search的设计和实现原理进行了详细介绍。我们知道这种查询模式直接检索基于`TextUnit`的向量数据表，找到与查询文本生成的嵌入向量相似度最高的`top k`个切片，并生成后续调用LLM的上下文。Local Search的执行流程可以概括为：以实体向量检索为入口，沿知识图谱扩展上下文，再按token预算筛选装配，最终交给LLM生成答案。

## 1. LocalSearch：Local Search的搜索引擎

`LocalSearch`是Local Search查询模式的搜索引擎。如代码片段所示，`LocalSearch`派生自基类`BaseSearch[LocalContextBuilder]`，泛型类型`LocalContextBuilder`为抽象类，定义的`build_context`抽象方法会根据提供的查询文本和对话历史创建作为上下文的`ContextBuilderResult`对象。

```python
class LocalSearch(BaseSearch[LocalContextBuilder]):
    def __init__(
        self,
        model: "LLMCompletion",
        context_builder: LocalContextBuilder,
        tokenizer: Tokenizer | None = None,
        system_prompt: str | None = None,
        response_type: str = "multiple paragraphs",
        callbacks: list[QueryCallbacks] | None = None,
        model_params: dict[str, Any] | None = None,
        context_builder_params: dict | None = None,
    )
    async def search(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
        **kwargs,
    ) -> SearchResult

    async def stream_search(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
    ) -> AsyncGenerator

class LocalContextBuilder(ABC):
    @abstractmethod
    def build_context(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
        **kwargs,
    ) -> ContextBuilderResult
```

构造一个`LocalSearch`对象需要提供如下的参数：

- **model**：用于生成答案的Completion模型，体现为一个`LLMCompletion`对象。它负责在上下文构建完成后，接收系统提示词和用户查询并产出回答。
- **context_builder**：用来生成检索上下文的`LocalContextBuilder`对象。它把查询转换为实体检索、图扩展和token裁剪后的结构化上下文。
- **tokenizer**：用于token计数的分词器，默认使用全局分词器。它用于统计提示词和输出文本的token用量。
- **system_prompt**：系统提示词，默认`LOCAL_SEARCH_SYSTEM_PROMPT`。它定义模型生成答案时的角色、数据引用规则和输出格式要求。
- **response_type**：期望的回答格式，默认`multiple paragraphs`。该值会被填入系统提示词，约束最终回答的篇幅与样式。
- **callbacks**：查询回调列表，用于流式token和上下文事件通知。它在生成过程中逐token触发`on_llm_new_token`，并在上下文就绪时触发`on_context`。
- **model_params**：调用模型时使用的额外参数。它会在`completion_async`调用时与消息、流式开关一起传入模型。
- **context_builder_params**：传给上下文构建器的额外参数。它在`build_context`调用时与查询、对话历史合并传入，用于覆盖构建器的默认行为。

`LocalSearch`和`BasicSearch`针对查询的执行流程几乎一样。如下所示的是它实现的`stream_search`方法的简化代码，具体的执行流程如下：

- 将提供的查询文本、对话历史和`context_builder_params`作为参数调用`LocalContextBuilder`的`build_context`方法创建出作为上下文的`ContextBuilderResult`对象；
- 将`ContextBuilderResult`的`context_chunks`字段和相应类型作为参数格式化系统提示词模板，生成完整的系统提示词；
- 利用`CompletionMessagesBuilder`将系统提示词和原始的查询文本转换成对用的系统消息和消息，并生成包含二者的消息列表；
- 将消息列表作为参数调用`LLMCompletion`对象的`completion_async`方法，以流的形式（`stream`参数设置为`True`）调用LLM，并实施返回生成的响应内容。

```python
class LocalSearch(BaseSearch[LocalContextBuilder]):
    async def stream_search(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
    ) -> AsyncGenerator:
        context_result = self.context_builder.build_context(
            query=query,
            conversation_history=conversation_history,
            **self.context_builder_params,
        )
        search_prompt = self.system_prompt.format(
            context_data=context_result.context_chunks, response_type=self.response_type
        )

        messages_builder = (
            CompletionMessagesBuilder()
            .add_system_message(search_prompt)
            .add_user_message(query)
        )

        for callback in self.callbacks:
            callback.on_context(context_result.context_records)

        response: AsyncIterator[LLMCompletionChunk] = await self.model.completion_async(
            messages=messages_builder.build(),
            stream=True,
            **self.model_params,
        ) 

        async for chunk in response:
            response_text = chunk.choices[0].delta.content or ""
            for callback in self.callbacks:
                callback.on_llm_new_token(response_text)
            yield response_text
```

## 2. LocalSearchMixedContext：上下文的构建者

不同的查询模式主要体现在上下文的构建方式上。`BasicSearch`用于构建上下文方式简单粗暴，直接提取与查询文本相似度最高的`top k`个切片（TextUnit）并将它们的文本格式化成上下文。LocalSearch针对上下文的构建就要复杂很多，从上下文内容的构成看，它会同时涉及如下的内容：

- 提供的对话历史（如果有）
- 最相关的**实体**信息
- 关键的**关系**描述
- 精选的**切片**（`TextUnit`）文本
- 相关的**社区报告**摘要

整个上下文的构建实现在`LocalSearchMixedContext`这个类型上，如下面给出了构造函数的声明。

```python
class LocalSearchMixedContext(LocalContextBuilder):
    def __init__(
        self,
        entities: list[Entity],
        entity_text_embeddings: VectorStore,
        text_embedder: "LLMEmbedding",
        text_units: list[TextUnit] | None = None,
        community_reports: list[CommunityReport] | None = None,
        relationships: list[Relationship] | None = None,
        covariates: dict[str, list[Covariate]] | None = None,
        tokenizer: Tokenizer | None = None,
        embedding_vectorstore_key: str = EntityVectorStoreKey.ID,
    )
```

构造函数的每个参数说明如下：

- **entities**：从`entities`表提取出来的`Entity`列表。
- **entity_text_embeddings**：作为向量库存储的`VectorStore`，这里一般只会使用到存储实体文本嵌入向量的表。
- **text_embedder**：代表嵌入模型的`LLMEmbedding`对象。
- **text_units**：从`text_units`表提取出来的TextUnit列表。
- **community_reports**：从`community_reports`表提取出来的`CommunityReport`列表。
- **relationships**：从`relationships`表提出来的`Relationship`列表。
- **covariates**：从`covariates`表提出出来的`Covariate`列表。
- **tokenizer**：分词器，用于统计上下文token数并执行上下文预算裁剪。
- **embedding_vectorstore_key**：指定实体向量库中用于关联/查找实体的键。

可以看出在初始化`LocalSearchMixedContext`需要将`entities`、`text_units`、`community_reports`、`relationships`和`covariates`这个五张表的数据全部提取出来生成对应列表，由此决定了GraphRAG目前这样的实现不可能应用到超大规模的知识库上。`LocalSearchMixedContext`将针对上下文的构建实现在`build_context`方法上。

```python
class LocalSearchMixedContext(LocalContextBuilder):
    def build_context(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
        include_entity_names: list[str] | None = None,
        exclude_entity_names: list[str] | None = None,
        conversation_history_max_turns: int | None = 5,
        conversation_history_user_turns_only: bool = True,
        max_context_tokens: int = 8000,
        text_unit_prop: float = 0.5,
        community_prop: float = 0.25,
        top_k_mapped_entities: int = 10,
        top_k_relationships: int = 10,
        include_community_rank: bool = False,
        include_entity_rank: bool = False,
        rank_description: str = "number of relationships",
        include_relationship_weight: bool = False,
        relationship_ranking_attribute: str = "rank",
        return_candidate_context: bool = False,
        use_community_summary: bool = False,
        min_community_rank: int = 0,
        community_context_name: str = "Reports",
        column_delimiter: str = "|",
        **kwargs: dict[str, Any],
    ) -> ContextBuilderResult:
        if include_entity_names is None:
            include_entity_names = []
        if exclude_entity_names is None:
            exclude_entity_names = []
        if community_prop + text_unit_prop > 1:
            value_error = (
                "The sum of community_prop and text_unit_prop should not exceed 1."
            )
            raise ValueError(value_error)

        if conversation_history:
            pre_user_questions = "\n".join(
                conversation_history.get_user_turns(conversation_history_max_turns)
            )
            query = f"{query}\n{pre_user_questions}"

        selected_entities = map_query_to_entities(
            query=query,
            text_embedding_vectorstore=self.entity_text_embeddings,
            text_embedder=self.text_embedder,
            all_entities_dict=self.entities,
            embedding_vectorstore_key=self.embedding_vectorstore_key,
            include_entity_names=include_entity_names,
            exclude_entity_names=exclude_entity_names,
            k=top_k_mapped_entities,
            oversample_scaler=2,
        )
        
        final_context = list[str]()
        final_context_data = dict[str, pd.DataFrame]()

        # build conversation history context
        if conversation_history:            
            (
                conversation_history_context,
                conversation_history_context_data,
            ) = conversation_history.build_context(
                include_user_turns_only=conversation_history_user_turns_only,
                max_qa_turns=conversation_history_max_turns,
                column_delimiter=column_delimiter,
                max_context_tokens=max_context_tokens,
                recency_bias=False,
            )
            if conversation_history_context.strip() != "":
                final_context.append(conversation_history_context)
                final_context_data = conversation_history_context_data
                max_context_tokens = max_context_tokens - len(self.tokenizer.encode(conversation_history_context))

        # build community context
        community_tokens = max(int(max_context_tokens * community_prop), 0)
        community_context, community_context_data = self._build_community_context(
            selected_entities=selected_entities,
            max_context_tokens=community_tokens,
            use_community_summary=use_community_summary,
            column_delimiter=column_delimiter,
            include_community_rank=include_community_rank,
            min_community_rank=min_community_rank,
            return_candidate_context=return_candidate_context,
            context_name=community_context_name,
        )
        if community_context.strip() != "":
            final_context.append(community_context)
            final_context_data = {**final_context_data, **community_context_data}

        # build local (entity-relationship-covariate) context
        local_prop = 1 - community_prop - text_unit_prop
        local_tokens = max(int(max_context_tokens * local_prop), 0)
        local_context, local_context_data = self._build_local_context(
            selected_entities=selected_entities,
            max_context_tokens=local_tokens,
            include_entity_rank=include_entity_rank,
            rank_description=rank_description,
            include_relationship_weight=include_relationship_weight,
            top_k_relationships=top_k_relationships,
            relationship_ranking_attribute=relationship_ranking_attribute,
            return_candidate_context=return_candidate_context,
            column_delimiter=column_delimiter,
        )
        if local_context.strip() != "":
            final_context.append(str(local_context))
            final_context_data = {**final_context_data, **local_context_data}

        text_unit_tokens = max(int(max_context_tokens * text_unit_prop), 0)
        text_unit_context, text_unit_context_data = self._build_text_unit_context(
            selected_entities=selected_entities,
            max_context_tokens=text_unit_tokens,
            return_candidate_context=return_candidate_context,
        )

        if text_unit_context.strip() != "":
            final_context.append(text_unit_context)
            final_context_data = {**final_context_data, **text_unit_context_data}

        return ContextBuilderResult(
            context_chunks="\n\n".join(final_context),
            context_records=final_context_data,
        )
```

`build_context`方法定义了如下的参数：

- **query**：用户查询文本，是实体映射的起点；若存在对话历史，会把历史用户问题拼接到该查询后再做嵌入检索。
- **conversation_history**：对话历史对象，提供历史轮次上下文，并从`max_context_tokens`中扣除其占用的 token 预算。
- **include_entity_names**：实体映射时强制包含的实体名称白名单，传给`map_query_to_entities`约束召回。
- **exclude_entity_names**：实体映射时排除的实体名称黑名单，传给`map_query_to_entities`过滤召回。
- **conversation_history_max_turns**：拼接到查询中的历史用户问题最大轮数，以及对话历史上下文构建的最大 QA 轮数。
- **conversation_history_user_turns_only**：对话历史上下文是否只保留用户轮次，传给`conversation_history.build_context`。
- **max_context_tokens**：最终上下文的token总预算上限，也是各子上下文按比例分配的基数。
- **text_unit_prop**：分配给文本单元上下文的 token 预算比例。
- **community_prop**：分配给社区报告上下文的 token 预算比例；与`text_unit_prop`之和不得超过 1。
- **top_k_mapped_entities**：查询映射阶段召回的实体数量上限。
- **top_k_relationships**：局部实体-关系上下文中每个实体保留的关系数量上限。
- **include_community_rank**：社区报告上下文中是否包含社区 rank 列。
- **include_entity_rank**：实体上下文中是否包含实体 rank 列。
- **rank_description**：实体 rank 列的说明文字，用于提示模板中解释 rank 含义。
- **include_relationship_weight**：关系上下文中是否包含关系权重列。
- **relationship_ranking_attribute**：关系排序所依据的属性名，用于选取 top-k 关系。
- **return_candidate_context**：是否返回所有候选记录（而非仅入选上下文的记录），并标记`in_context`字段。
- **use_community_summary**：社区报告上下文使用社区`summary`字段还是`full content`字段。
- **min_community_rank**：社区报告入选的最小`rank`阈值，低于该值的社区被过滤。
- **community_context_name**：社区报告上下文在输出中的名称/表头标识。
- **column_delimiter**：各上下文表格列之间的分隔符。
- **kwargs**：额外关键字参数，当前实现中未使用，用于向前兼容。

我们大致总结一下上下文的构建流程：

- **预处理与查询增强**：归一化包含/排除实体名参数，校验`community_prop + text_unit_prop ≤ 1`；若有对话历史，取最近若干轮用户问题拼接到查询后，形成增强查询。
- **实体锚定**：用`map_query_to_entities`将增强查询嵌入并在实体向量库中检索，结合包含/排除约束召回`top_k_mapped_entities`个实体，作为后续所有子上下文的锚点；同时初始化文本片段列表与结构化记录字典。
- **添加对话历史上下文**：若有对话历史，调用其`build_context`生成历史QA上下文，非空则追加并合并记录，并从`max_context_tokens`中扣除其消耗。
- **添加社区报告上下文**：按`community_prop`分配剩余预算，调用`_build_community_context`方法统计**锚点实体所属社区的命中次数**，按**命中次数、rank**降序排序，再按参数`use_community_summary`、`min_community_ran`和`max_context_tokens`裁剪和格式化。
- **添加局部上下文**：按`1 - community_prop - text_unit_prop`分配预算，调用`_build_local_context`函数先整体构建实体表，再按**锚点顺序**逐个追加关系与协变量上下文，累计token超限即回退到上一状态，保证实体表完整、附加信息不越界。
- **添加文本单元上下文**：按`text_unit_prop`分配预算，调用`_build_text_unit_context`方法去重收集锚点实体的文本单元，按**实体顺序、关系命中数降序**排序后按`max_context_tokens`裁剪。
- **组装返回**：将对话历史、社区报告、局部上下文、文本单元四段按序以空行拼接为`context_chunks`，汇总各子上下文`DataFrame`为`context_records`，封装为`ContextBuilderResult`返回。

## 3. LocalSearchDefaults：Local Search的配置

`LocalSearchMixedContext`用来构建上下文的`build_context`方法的很多参数来源于Local Search的配置。对应的配置类型为`LocalSearchConfig`，`GraphRagConfig`的`local_search`字段返回的正是这个对象。`LocalSearchDefaults`类型为各配置选项提供了兜底的默认值。

```python
class GraphRagConfig(BaseModel):
    local_search: LocalSearchConfig = Field(
        description="The local search configuration.", default=LocalSearchConfig()
    )

class LocalSearchConfig(BaseModel):
    prompt: str | None = Field(
        description="The local search prompt to use.",
        default=graphrag_config_defaults.local_search.prompt,
    )
    completion_model_id: str = Field(
        description="The model ID to use for local search.",
        default=graphrag_config_defaults.local_search.completion_model_id,
    )
    embedding_model_id: str = Field(
        description="The model ID to use for text embeddings.",
        default=graphrag_config_defaults.local_search.embedding_model_id,
    )
    text_unit_prop: float = Field(
        description="The text unit proportion.",
        default=graphrag_config_defaults.local_search.text_unit_prop,
    )
    community_prop: float = Field(
        description="The community proportion.",
        default=graphrag_config_defaults.local_search.community_prop,
    )
    conversation_history_max_turns: int = Field(
        description="The conversation history maximum turns.",
        default=graphrag_config_defaults.local_search.conversation_history_max_turns,
    )
    top_k_entities: int = Field(

@dataclass
class LocalSearchDefaults:
    prompt: None = None
    text_unit_prop: float = 0.5
    community_prop: float = 0.15
    conversation_history_max_turns: int = 5
    top_k_entities: int = 10
    top_k_relationships: int = 10
    max_context_tokens: int = 12_000
    completion_model_id: str = DEFAULT_COMPLETION_MODEL_ID
    embedding_model_id: str = DEFAULT_EMBEDDING_MODEL_ID
```

`LocalSearchConfig`提供了如下的配置选项：

- **prompt**：提示词模板，决定最终把上下文与问题组织成何种提示发送给LLM。
- **completion_model_id**：生成回答所用的Completion模型ID。
- **embedding_model_id**：嵌入模型ID，用于将查询嵌入为向量，以便在实体向量库中检索锚点实体。
- **text_unit_prop**：基于`TextUnit`上下文占`max_context_tokens`的预算比例。
- **community_prop**：社区报告上下文占`max_context_tokens`的预算比例；与`text_unit_prop`之和不得超过 1，剩余部分即局部（实体-关系-协变量）上下文比例。
- **conversation_history_max_turns**：拼接到查询及构建历史上下文时使用的最大对话轮数。
- **top_k_entities**：查询映射阶段召回的锚点实体数量上限。
- **top_k_relationships**：局部上下文中每个实体保留的关系数量上限。
- **max_context_tokens**：最终上下文的总token预算上限，是各子上下文按比例分配的基数。

## 4. 搜索引擎的创建

GraphRAG最终会调用如下这个`get_local_search_engine`函数来创建作为搜索引擎的`LocalSearch`对象，其大致的创建流程如下：

- 根据`GraphRagConfig`配置分别创建Completion模型和嵌入模型的`LLMCompletion`和`LLMEmbedding`对象，并提取`LLMCompletion`的`Tokenizer`。
- 根据参数提供的对象将用于构建上下文的`LocalSearchMixedContext`创建出来。
- 根据`LocalSearchMixedContext`和之前创建和参数提供的对象创建返回的`LocalSearch`对象。

## 5. 两种调用模式

GraphRAG同样Local Search查询模式定义了如下所示的`local_search`和`local_search_streaming`两个函数，它们分别实现了阻塞形式和流形式的调用。`local_search_streaming`函数的实现很简单：

- 调用`get_embedding_store`函数根据配置将作为向量存储的`VectorStore`对象创建出来；
- 读取参数提供的针对六个`DataFrame`将读取所有的`Entity`、`Community`、`CommunityResport`、`TextUnit`、`Relationship`和`Covariate`；
- 调用`load_search_prompt`函数根据配置读取系统提示词模板；
- 调用`get_local_search_engine`根据上面这些对象创建作为搜索引擎的`LocalSearch`对象；
- 将原始查询文本作为参数调用`LocalSearch`的`stream_search`方法以流的形式执行查询并实时输出响应文本。

```python
async def local_search(
    config: GraphRagConfig,
    entities: pd.DataFrame,
    communities: pd.DataFrame,
    community_reports: pd.DataFrame,
    text_units: pd.DataFrame,
    relationships: pd.DataFrame,
    covariates: pd.DataFrame | None,
    community_level: int,
    response_type: str,
    query: str,
    callbacks: list[QueryCallbacks] | None = None,
    verbose: bool = False,
) -> tuple[
    str | dict[str, Any] | list[dict[str, Any]],
    str | list[pd.DataFrame] | dict[str, pd.DataFrame],
]:    
    callbacks = callbacks or []
    full_response = ""
    context_data = {}

    def on_context(context: Any) -> None:
        nonlocal context_data
        context_data = context

    local_callbacks = NoopQueryCallbacks()
    local_callbacks.on_context = on_context
    callbacks.append(local_callbacks)

    async for chunk in local_search_streaming(
        config=config,
        entities=entities,
        communities=communities,
        community_reports=community_reports,
        text_units=text_units,
        relationships=relationships,
        covariates=covariates,
        community_level=community_level,
        response_type=response_type,
        query=query,
        callbacks=callbacks,
    ):
        full_response += chunk
    return full_response, context_data

def local_search_streaming(
    config: GraphRagConfig,
    entities: pd.DataFrame,
    communities: pd.DataFrame,
    community_reports: pd.DataFrame,
    text_units: pd.DataFrame,
    relationships: pd.DataFrame,
    covariates: pd.DataFrame | None,
    community_level: int,
    response_type: str,
    query: str,
    callbacks: list[QueryCallbacks] | None = None,
    verbose: bool = False,
) -> AsyncGenerator
    description_embedding_store = get_embedding_store(
        config=config.vector_store,
        embedding_name=entity_description_embedding,
    )

    entities_ = read_indexer_entities(entities, communities, community_level)
    covariates_ = read_indexer_covariates(covariates) if covariates is not None else []
    prompt = load_search_prompt(config.local_search.prompt)
    search_engine = get_local_search_engine(
        config=config,
        reports=read_indexer_reports(community_reports, communities, community_level),
        text_units=read_indexer_text_units(text_units),
        entities=entities_,
        relationships=read_indexer_relationships(relationships),
        covariates={"claims": covariates_},
        description_embedding_store=description_embedding_store,
        response_type=response_type,
        system_prompt=prompt,
        callbacks=callbacks,
    )
    return search_engine.stream_search(query=query)
```

基于阻塞式调用的`local_search`函数内部也会调用`local_search_streaming`，它仅仅是将实时输出的响应结构汇总后进行统一输出罢了。
