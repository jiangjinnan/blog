# [GraphRAG实现原理-20]四种查询方式之四：Global Search

Global Search是 GraphRAG中专门用于回答语料库级**全局性**问题的查询模式，例如*这个数据集的主要主题是什么*”或*有哪些跨领域的趋势*。它不依赖某个具体的实体锚点，而是通过Map-Reduce方式对预先构建的社区报告进行遍历和合成。

## 1. Global Search的优劣势

传统的向量检索（Baseline RAG）在面对**全局性**问题时表现不佳。这类问题（如*数据中的前5个主题是什么*）的答案分布在许多文档中，查询本身没有足够的语义信号去命中所有相关片段，向量检索只能捞取最相似的几块，导致答案片面。Global Search 利用索引阶段生成的社区报告（Community Reports）来解决这个问题。社区报告本身就是对知识图谱中紧密关联的实体群的预先总结，代表了数据中的**主题**或**语义聚类**。

Global Search通过对这些社区报告做Map-Reduce，系统能覆盖整个语料库的主题，而不是只盯着查询词附近的内容。Map和Reduce两阶段大致的执行流程为：

- **Map阶段：逐社区打分/提取**

系统加载指定层级的所有社区报告。对于每一份社区报告，将其与用户查询一起送入LLM，生成一个中间响应。这个中间响应通常包含从该社区视角出发的要点，以及一个0-10的相关性评分，表示该社区对回答这个问题的价值。这一步是高度并行的，可以通过配置控制并发度。

- **Reduce 阶段：过滤与合成**

并非所有社区都同等重要。系统会根据Map阶段给出的评分进行过滤：

  - **过滤**：只保留评分大于等于指定最低评分的社区，并按评分排序，保留的最大个数由配置指定。
  - **合成**：将保留下来的、高相关社区的中间响应（要点）汇总，作为上下文送入LLM，生成最终的、连贯的全局性答案。

Global Search具有如下的关键特征与代价

- **广度优先，成本较高**：Global Search的核心优势是覆盖全面。它会对指定层级下的每一个社区报告发起一次LLM 调用（Map），因此成本与社区数量直接挂钩，属于资源密集型操作。一个实测对比显示，在全局性问题上，扁平检索的主题覆盖率仅为0.44，而Global Search能达到1.00。

- **层级选择影响质量与成本**：community_level参数决定使用哪一层的社区报告。层级越低（越接近叶子），报告越详细，回答可能更深入，但报告数量更多，Map调用次数和成本也越高；层级越高，报告越宏观，成本相对较低。

[Local Search](https://jaydenai.blog.csdn.net/article/details/169919728)从具体实体出发做邻域展开，适合回答*X 和 Y 有什么关系*”。[DRIFT](https://jaydenai.blog.csdn.net/article/details/169920210) 是**全局引导 + 局部深挖**的混合体。Global Search是唯一一种纯粹为了语料库级**主题归纳**而设计的模式，它不关心某个具体实体的细节，只关心整个数据集在讲什么。

与之前讨论的 Local Search和DRIFT 相比，Global Search 的上下文构建对象不是实体或文本单元，而是社区报告。它的检索逻辑不是相似度匹配，而是对每个社区进行相关性评分后再聚合，所以它是唯一一种不需要向量数据库参与的查询模式。这种设计使它天然适合做语料库的**摘要器**，代价是每次查询都要遍历大量社区，成本显著高于Local Search。

`GlobalSearchConfig`利用其字段承载了如下的配置选项：

- **map_prompt**：Map阶段提示词模板，用于对每个社区报告结合查询生成中间响应与相关性评分。
- **reduce_prompt**：Reduce 阶段提示词模板，用于把高分社区的中间响应合成为最终答案。
- **completion_model_id**：使用的补全模型 ID。
- **knowledge_prompt**：通用知识提示词模板，作为Map/Reduce之外的基础提示使用。
- **max_context_tokens**：送入LLM的上下文最大token 数。
- **data_max_tokens**：数据侧LLM的最大token数，控制数据上下文的规模。
- **map_max_length**：Map阶段LLM 响应的最大长度（以词计）。
- **reduce_max_length**：Reduce阶段LLM响应的最大长度（以词计）。
- **dynamic_search_threshold**：社区报告入选的评分阈值，评分达到该值才纳入上下文。
- **dynamic_search_keep_parent**：若任一子社区相关，是否保留其父社区（用于动态社区选择）。
- **dynamic_search_num_repeats**：对同一社区报告重复评分的次数，用于提升评分稳定性。
- **dynamic_search_use_summary**：社区上下文使用`summary`摘要还是`full_context`全文。
- **dynamic_search_max_level**：当已处理社区均不相关时，允许向上回溯的社区层级上限。

## 3. 上下文的构建

负责构建Map阶段所需的社区报告上下文的`GlobalContextBuilder`是如下这样一个抽象类，抽象方法`build_context`会根据指定的查询文本和对话历史创建承载上下文数据的`ContextBuilderResult`对象。`GlobalCommunityContext`是对`GlobalContextBuilder`的默认实现。

```python
class GlobalContextBuilder(ABC):
    @abstractmethod
    async def build_context(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
        **kwargs,
    ) -> ContextBuilderResult
class GlobalCommunityContext(GlobalContextBuilder):
```

### 3.1 GlobalCommunityContext的构建

构建这个`GlobalCommunityContext`对象需要提供如下的参数：

- **community_reports**：加载索引表`community_reports`生成的社区报告列表，作为默认上下文来源。
- **communities**：加载索引表`communities`生成的社区层级结构列表，供动态社区选择时沿层级回溯/判断父子关系使用。
- **entities**：加载索引表`entities`生成的实体列表，可选，用于在构建社区上下文时关联实体信息（如社区权重计算）。
- **tokenizer**：用于统计上下文token数并执行预算裁剪`Tokenizer`。
- **dynamic_community_selection**：是否启用动态社区选择。
- **dynamic_community_selection_kwargs**：动态社区选择的配置字典。
- **random_state**：随机种子，传给`build_community_context` 用于`shuffle_data`时的可复现打乱。

```python
class GlobalCommunityContext(GlobalContextBuilder):
    def __init__(
        self,
        community_reports: list[CommunityReport],
        communities: list[Community],
        entities: list[Entity] | None = None,
        tokenizer: Tokenizer | None = None,
        dynamic_community_selection: bool = False,
        dynamic_community_selection_kwargs: dict[str, Any] | None = None,
        random_state: int = 86,
    ):
        self.community_reports = community_reports
        self.entities = entities
        self.tokenizer = tokenizer or get_tokenizer()
        self.dynamic_community_selection = None
        if dynamic_community_selection and isinstance(
            dynamic_community_selection_kwargs, dict
        ):
            self.dynamic_community_selection = DynamicCommunitySelection(
                community_reports=community_reports,
                communities=communities,
                model=dynamic_community_selection_kwargs.pop("model"),
                tokenizer=dynamic_community_selection_kwargs.pop("tokenizer"),
                **dynamic_community_selection_kwargs,
            )
        self.random_state = random_state
```

### 3.2 动态社区选择

如果利用`dynamic_community_selection`参数开启动态社区选择，会创建一个`DynamicCommunitySelection`对象赋值给`dynamic_community_selection`字段。`DynamicCommunitySelection`的`select`方法实现的是**自顶向下**的**广度优先搜索 + LLM 相关性剪枝**：它不一次性把所有社区报告塞给Map阶段，而是从最高层社区开始，用轻量模型对每个社区与查询的相关性打分，只有得分超过阈值的社区才会**解锁**其子社区进入下一轮评估，低分分支被直接剪掉。

```python
class DynamicCommunitySelection:
    def __init__(
        self,
        community_reports: list[CommunityReport],
        communities: list[Community],
        model: "LLMCompletion",
        tokenizer: Tokenizer,
        rate_query: str = RATE_QUERY,
        use_summary: bool = False,
        threshold: int = 1,
        keep_parent: bool = False,
        num_repeats: int = 1,
        max_level: int = 2,
        concurrent_coroutines: int = 8,
        model_params: dict[str, Any] | None = None,
    )
    async def select(self, query: str) -> tuple[list[CommunityReport], dict[str, Any]]
```

`DynamicCommunitySelection`在进行社区选择时需要利用构造函数的参数提供候选社区、LLM、分词器和控制选择行为的配置选项：

- **community_reports**：社区报告列表，作为动态选择的候选报告来源，用于构建报告映射与后续筛选。
- **communities**：社区层级结构列表，提供父子关系与层级信息，驱动自顶向下的 BFS 遍历。
- **model**：用于对社区与查询相关性打分的 LLM 模型（通常为轻量模型）。
- **tokenizer**：分词器，用于统计打分过程消耗的 token 数。
- **dynamic_search_threshold**：相关性评分阈值，得分达到该值的社区才会解锁其子社区进入下一轮评估。
- **dynamic_search_keep_parent**：若任一子社区相关，是否保留其父社区。
- **dynamic_search_num_repeats**：对同一社区报告重复评分的次数，用于提升评分稳定性。
- **dynamic_search_use_summary**：打分时使用社区summary摘要还是full_context全文。
- **dynamic_search_max_level**：允许向下探索的最大社区层级，达到该层级后停止下钻。

**广度优先(BFS) + LLM 打分 + 阈值剪枝**是动态社区选择的核心机制，整个执行流程如下：

- **初始化**：构建`社区ID → 报告`、`短ID → 社区对象`、`层级 →社区列表`等映射字典，为逐层遍历做准备。
- **逐层打分**：从根层级（Level 0）开始，用 LLM（通常是轻量模型如 GPT-4o-mini）对当前层级每个社区与查询的相关性打一个整数分。
- **阈值剪枝**：只有得分达到`dynamic_search_threshold`的社区，其子社区才会被加入下一轮待评估队列；低于阈值的社区及其整个子树被跳过。
- **逐层下钻**：重复上述过程，直到没有新社区被解锁或达到`dynamic_search_max_level`上限。

最终被选中的社区集合，就是用于构建Map上下文的报告来源。

### 3.3 完整的流程

实现在`build_context`方法中针对上下文的构建流程如下。最终返回的ContextBuilderResult对象的上下文的数据来源有两个：提供的对话历史（可选）和社区报告。如果开启了动态社区选择，则会利用`DynamicCommunitySelection`对候选的社区报告进行过滤。

```python
class GlobalCommunityContext(GlobalContextBuilder):
    async def build_context(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
        use_community_summary: bool = True,
        column_delimiter: str = "|",
        shuffle_data: bool = True,
        include_community_rank: bool = False,
        min_community_rank: int = 0,
        community_rank_name: str = "rank",
        include_community_weight: bool = True,
        community_weight_name: str = "occurrence",
        normalize_community_weight: bool = True,
        max_context_tokens: int = 8000,
        context_name: str = "Reports",
        conversation_history_user_turns_only: bool = True,
        conversation_history_max_turns: int | None = 5,
        **kwargs: Any,
    ) -> ContextBuilderResult:
        conversation_history_context = ""
        final_context_data = {}
        llm_calls, prompt_tokens, output_tokens = 0, 0, 0

        # build conversation history context
        if conversation_history:            
            (
                conversation_history_context,
                conversation_history_context_data,
            ) = conversation_history.build_context(
                include_user_turns_only=conversation_history_user_turns_only,
                max_qa_turns=conversation_history_max_turns,
                column_delimiter=column_delimiter,
                max_context_tokens=max_context_tokens,
                recency_bias=False,
            )
            if conversation_history_context != "":
                final_context_data = conversation_history_context_data

        community_reports = self.community_reports
        if self.dynamic_community_selection is not None:
            (
                community_reports,
                dynamic_info,
            ) = await self.dynamic_community_selection.select(query)
            llm_calls += dynamic_info["llm_calls"]
            prompt_tokens += dynamic_info["prompt_tokens"]
            output_tokens += dynamic_info["output_tokens"]

        community_context, community_context_data = build_community_context(
            community_reports=community_reports,
            entities=self.entities,
            tokenizer=self.tokenizer,
            use_community_summary=use_community_summary,
            column_delimiter=column_delimiter,
            shuffle_data=shuffle_data,
            include_community_rank=include_community_rank,
            min_community_rank=min_community_rank,
            community_rank_name=community_rank_name,
            include_community_weight=include_community_weight,
            community_weight_name=community_weight_name,
            normalize_community_weight=normalize_community_weight,
            max_context_tokens=max_context_tokens,
            single_batch=False,
            context_name=context_name,
            random_state=self.random_state,
        )

        # Prepare context_prefix based on whether conversation_history_context exists
        context_prefix = (
            f"{conversation_history_context}\n\n"
            if conversation_history_context
            else ""
        )

        final_context = (
            [f"{context_prefix}{context}" for context in community_context]
            if isinstance(community_context, list)
            else f"{context_prefix}{community_context}"
        )

        # Update the final context data with the provided community_context_data
        final_context_data.update(community_context_data)

        return ContextBuilderResult(
            context_chunks=final_context,
            context_records=final_context_data,
            llm_calls=llm_calls,
            prompt_tokens=prompt_tokens,
            output_tokens=output_tokens,
        )
```

针对社区报告生成上下文的核心操作实现在`build_community_context`函数中，它把社区报告列表按token预算整理成一个或多个带表头的表格批次。流程可概括为：

- **过滤**：只保留`rank`非空且不低于`min_community_rank`的报告；若传入实体且报告尚无权重属性，先计算社区权重。
- **打乱**：`shuffle_data == True`时按打乱报告顺序。
- **生成表头**：固定 id、title 开头，接报告属性列，再接摘要或全文，按需追加`rank`列。
- **按token预算分批填充**：逐条渲染报告行并累计token，超出`max_context_tokens`时切出一个批次。`single_batch=True`时只产出一个批次后停止，否则时继续开新批次。
- **收尾**：把最后未切出的批次补切，避免遗漏；若无任何批次则告警并返回空。
- **返回**：上下文文本（单批为字符串、多批为字符串列表）与合并后的结构化`DataFrame`。

在如下的演示程序中，我们加载索引表`communities`和`community_reports`将社区和社区报告提取出来。我们使用这两组列表创建了`GlobalCommunityContext`对象，并指定查询文本（*总结李明为咖啡店所作的促销手段。*）调用其`build_context`方法为Map阶段生成上下文，并将整个上下文的内容输出。为了体现针对上下文的分批处理，我们刻意将max_context_tokens参数设置成一个较小的值1000，最终导致划分为两个批次。

```python
import asyncio
import pandas as pd
from graphrag.query.indexer_adapters import (
   read_indexer_entities,
   read_indexer_communities,
   read_indexer_reports)
from graphrag.query.structured_search.global_search.community_context import GlobalCommunityContext

async def main():     
    entities = pd.read_parquet('./output/entities.parquet')  
    communities = pd.read_parquet('./output/communities.parquet')
    community_reports = pd.read_parquet('./output/community_reports.parquet')
    context_builder = GlobalCommunityContext(
```

## 4. 搜索引擎

`GlobalSearch`作为Global Search查询模式的搜索引擎，它派生于基类`BaseSearch[GlobalContextBuilder]`，上面介绍的抽象类`GlobalContextBuilder`用来为其构建最终调用LLM的上下文。

### 4.1 GlobalSearch的构造

下面给出了`GlobalSearch`类型构造函数的定义。当我们调用构造函数创建一个`GlobalSearch`对象时需要提供如下的参数：

- **model**：作为Completion模式的`LLMCompletion`对象，Map与 Reduce阶段实际调用的LLM。
- **context_builder**：负责构建Map阶段所需的社区报告上下文的`GlobalContextBuilder`对象。
- **tokenizer**：用于统计 Map/Reduce提示词与响应的token数的`Tokenizer`。
- **map_system_prompt**：Map阶段系统提示词模板；未传时使用默认模板兜底。
- **reduce_system_prompt**：Reduce阶段系统提示词模板；未传时使用默认模板兜底。
- **response_type**：期望的最终回答形态（如`multiple paragraphs`），用来替换Reduce提示词中对应占位符。
- **allow_general_knowledge**：是否允许LLM在Reduce阶段引入数据集之外的通用知识（有增加幻觉的风险）。
- **general_knowledge_inclusion_prompt**：允许通用知识时追加到Reduce提示词末尾的说明；未传时使用默认指令兜底。
- **json_mode**：是否要求Map阶段以JSON对象格式响应。
- **callbacks**：查询回调列表，用于在 Map/Reduce 各阶段及流式token生成时触发外部钩子。
- **max_data_tokens**：Reduce阶段拼装中间答案数据时的最大token 数，超出即截断。
- **map_llm_params**：Map阶段传给模型的额外参数字典；未传时为空字典。
- **reduce_llm_params**：Reduce阶段传给模型的额外参数字典；未传时为空字典。
- **map_max_length**：Map阶段每个批次响应允许的最大长度（词）。
- **reduce_max_length**：Reduce阶段最终响应允许的最大长度（词）。
- **context_builder_params**：传给`GlobalContextBuilder`对象的额外参数。
- **concurrent_coroutines**：Map阶段并发LLM调用的最大并发数，用于初始化`asyncio.Semaphore`。

### 4.2 基于Map-Reduce的执行流程

基于Map-Reduce的两阶段执行流程基本体现在如下所示的`stream_search`方法中，总体流程如下：

- 调用`GlobalContextBuilder`的`build_context`方法生成作为上下文的`ContextBuilderResult`对象。
- 针对社区报告上下文（`ContextBuilderResult`的`context_chunks`列表的每个元素）并发调用`_map_response_single_batch`方法，后者对一个社区报告上下文批次（chunk）发起一次LLM调用，让模型针对用户查询从该批次中提取带重要性评分的要点，并把结果包装成`SearchResult`返回。
- 统计LLM调用次数和token消费指标。
- 调用把`_stream_reduce_response`方法Map阶段各批次产出的要点汇总、过滤、排序、裁剪后，组装成Reduce提示词，调用一次 LLM 流式生成最终答案。

```python
class GlobalSearch(BaseSearch[GlobalContextBuilder]):
    async def stream_search(
        self,
        query: str,
        conversation_history: ConversationHistory | None = None,
    ) -> AsyncGenerator[str, None]:
        context_result = await self.context_builder.build_context(
            query=query,
            conversation_history=conversation_history,
            **self.context_builder_params,
        )
        for callback in self.callbacks:
            callback.on_map_response_start(context_result.context_chunks)  # type: ignore

        map_responses = await asyncio.gather(*[
            self._map_response_single_batch(
                context_data=data,
                query=query,
                max_length=self.map_max_length,
                **self.map_llm_params,
            )
            for data in context_result.context_chunks
        ])

        for callback in self.callbacks:
            callback.on_map_response_end(map_responses)  # type: ignore
            callback.on_context(context_result.context_records)

        async for response in self._stream_reduce_response(
            map_responses=map_responses,  # type: ignore
            query=query,
            max_length=self.reduce_max_length,
            model_parameters=self.reduce_llm_params,
        ):
            yield response
```

#### 4.2.1 Map

Map阶段主要体现在针对构建的上下文并发调用`_map_response_single_batch`方法，它会对一个社区报告上下文批次（chunk）发起一次LLM调用，让模型针对用户查询从该批次中提取带重要性评分的要点，并把结果包装成如下这个`SearchResult`并返回。

```python
@dataclass
class SearchResult:
    response: str | dict[str, Any] | list[dict[str, Any]]
    context_data: str | list[pd.DataFrame] | dict[str, pd.DataFrame]
    context_text: str | list[str] | dict[str, str]
    completion_time: float
    llm_calls: int
    prompt_tokens: int
    output_tokens: int
    llm_calls_categories: dict[str, int] | None = None
    prompt_tokens_categories: dict[str, int] | None = None
    output_tokens_categories: dict[str, int] | None = None
```

一个`SearchResult`对象承载着如下的信息：

- **response**：搜索结果的主体内容，可以是最终答案字符串、结构化字典或要点列表；在不同阶段分别承载Map要点、Reduce最终答案等。
- **context_data**：生成结果所依据的结构化上下文数据，可以是字符串、DataFrame列表或按名称索引的DataFrame字典。
- **context_text**：实际进入上下文窗口的文本字符串，由`context_data` 构建而来，是喂给 LLM 的文本形态。
- **completion_time**：本次搜索/调用耗时（秒）。
- **llm_calls**：本次结果涉及的LLM调用总次数。
- **prompt_tokens**：本次结果消耗的提示token总数。
- **output_tokens**：本次结果消耗的输出token 总数。
- **llm_calls_categories**：LLM调用次数按类别（如 build_context、map、reduce）的细分统计，可选。
- **prompt_tokens_categories**：提示token按类别的细分统计，可选。
- **output_tokens_categories**：输出token按类别的细分统计，可选。

`_map_response_single_batch`方法的定义如下，具体的LLM调用和结果解析流程如下：

- 将上下文（`context_data`）和最大响应文本数（`max_length`）填充模板（`map_system_prompt`）生成完整的系统提示词；
- 利用`CompletionMessagesBuilder`将系统提示词和查询文本生成转换成对应的消息；
- 将消息列表和额外执行的参数作为输入调用`LLMCompletion`的`completion_async`方法对LLM发起调用；
- 以JSON格式将响应内容并生成返回的`SearchResult`对象。

```python
class GlobalSearch(BaseSearch[GlobalContextBuilder]):
    async def _map_response_single_batch(
        self,
        context_data: str,
        query: str,
        max_length: int,
        **llm_kwargs,
    ) -> SearchResult:
        start_time = time.time()
        search_prompt = ""
        try:
            search_prompt = self.map_system_prompt.format(
                context_data=context_data, max_length=max_length
            )

            messages_builder = (
                CompletionMessagesBuilder()
                .add_system_message(search_prompt)
                .add_user_message(query)
            )

            async with self.semaphore:
                model_response = await self.model.completion_async(
                    messages=messages_builder.build(),
                    response_format_json_object=True,
                    **llm_kwargs,
                )
                search_response = await gather_completion_response_async(model_response)
                logger.debug("Map response: %s", search_response)
            try:
                processed_response = self._parse_search_response(search_response)
            except ValueError:
                logger.warning(
                    "Warning: Error parsing search response json - skipping this batch"
                )
                processed_response = []

            return SearchResult(
                response=processed_response,
                context_data=context_data,
                context_text=context_data,
                completion_time=time.time() - start_time,
                llm_calls=1,
                prompt_tokens=len(self.tokenizer.encode(search_prompt)),
                output_tokens=len(self.tokenizer.encode(search_response)),
            )

        except Exception:
            logger.exception("Exception in _map_response_single_batch")
            return SearchResult(
                response=[{"answer": "", "score": 0}],
                context_data=context_data,
                context_text=context_data,
                completion_time=time.time() - start_time,
                llm_calls=1,
                prompt_tokens=len(self.tokenizer.encode(search_prompt)),
                output_tokens=0,
            )
```

#### 4.2.2 Reduce

Map阶段针对每条社区上下文分片生成的一组`SearchResult`会在`Reduce`阶段交给如下这个`_stream_reduce_response`方法进行处理，具体处理流程如下：

- 按照如下的方式生成用来替换提示词模板`{report_data}`占位符的社区报告数据
    - 遍历每个`SearchResult`列表，并试着从`SearchResult`的`response`字段中提取答案和分数，并连同列表索引组成一个字典并保存在key_points列表中；
    - 剔除得分`<=0`的point；
    - 按照分数从高到底排序；
    - 提取每个point的答案、得分和索引按照指定的模板格式化，最终使用`\n\n`作为分隔符进行拼接。
- 将上面生成的文本两桶最大响应文本数（`max_length`）和响应类型填充模板（`reduce_system_prompt`）生成完整的系统提示词；
- 利用`CompletionMessagesBuilder`将系统提示词和查询文本生成转换成对应的消息；
- 将消息列表和额外执行的参数作为输入调用`LLMCompletion`的`completion_async`方法以流的形式（`stream=True`）对LLM发起调用，并实时返回响应结果。

```python
class GlobalSearch(BaseSearch[GlobalContextBuilder]):
    async def _stream_reduce_response(
        self,
        map_responses: list[SearchResult],
        query: str,
        max_length: int,
        **llm_kwargs,
    ) -> AsyncGenerator[str, None]:
        key_points = []
        for index, response in enumerate(map_responses):
            if not isinstance(response.response, list):
                continue
            for element in response.response:
                if not isinstance(element, dict):
                    continue
                if "answer" not in element or "score" not in element:
                    continue
                key_points.append({
                    "analyst": index,
                    "answer": element["answer"],
                    "score": element["score"],
                })

        # filter response with score = 0 and rank responses by descending order of score
        filtered_key_points = [
            point
            for point in key_points
            if point["score"] > 0  # type: ignore
        ]

        if len(filtered_key_points) == 0 and not self.allow_general_knowledge:
            # return no data answer if no key points are found
            yield NO_DATA_ANSWER
            return

        filtered_key_points = sorted(
            filtered_key_points,
            key=lambda x: x["score"],  # type: ignore
            reverse=True,  # type: ignore
        )

        data = []
        total_tokens = 0
        for point in filtered_key_points:
            formatted_response_data = [
                f"----Analyst {point['analyst'] + 1}----",
                f"Importance Score: {point['score']}",
                point["answer"],
            ]
            formatted_response_text = "\n".join(formatted_response_data)
            if (
                total_tokens + len(self.tokenizer.encode(formatted_response_text))
                > self.max_data_tokens
            ):
                break
            data.append(formatted_response_text)
            total_tokens += len(self.tokenizer.encode(formatted_response_text))
        text_data = "\n\n".join(data)

        search_prompt = self.reduce_system_prompt.format(
            report_data=text_data,
            response_type=self.response_type,
            max_length=max_length,
        )
        if self.allow_general_knowledge:
            search_prompt += "\n" + self.general_knowledge_inclusion_prompt

        messages_builder = (
            CompletionMessagesBuilder()
            .add_system_message(search_prompt)
            .add_user_message(query)
        )

        response_search: AsyncIterator[LLMCompletionChunk] = await self.model.completion_async(
            messages=messages_builder.build(),
            stream=True,
            **llm_kwargs.get("model_parameters", {}),
        ) 

        async for chunk in response_search:
            response_text = chunk.choices[0].delta.content or ""
            for callback in self.callbacks:
                callback.on_llm_new_token(response_text)
            yield response_text
```
