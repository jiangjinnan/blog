# [LLM Wiki理论与实践-05]解读OpenWiki的Personal模式构建的知识库目录结构

[LLM Wiki理论与实践-04：使用OpenWiki的Personal模式构建知识库](https://jaydenai.blog.csdn.net/article/details/170335769)介绍了如何执行安装OpenWiki和通过执行`openwiki personal --init`命令以个人模式进行初始化，最终调用`openwiki personal --update`和`openwiki ingest`命令利用配置的Connector加载外部数据源来生成构建个人知识库的Wiki页。这篇文章我们就来看看采用OpenWiki的Personal模式构建的知识库对应目录的结构以及具体文件的内容。

## 1. Wiki目录结构

由于OpenWiki的Personal模式旨在为当前登录用户构建专属的个人知识库，所以默认的wiki目录所在的位置为`~/.openwiki/wiki`（或者`%UserProfile%.openwiki/wiki`），但是我通过OPENWIKI_CONFIG_DIR环境变量修改了默认的根目录地址。如下所示的是最终生成的目录结构。

```markdown
📁 wiki
├── 📁 large_tool_results
├── 📁 sources
├── 📄 .last-update.json 
├── 📄 commitments.md 
├── 📄 index.md 
├── 📄 open-questions.md 
├── 📄 personal-logistics.md 
├── 📄 quickstart.md
└── 📄 themes.md
```

接下来我们就结合上面这个目录结构介绍每个文件针对构建的个人知识库所承载的内容。在这之前，我们有必要再次说明在[LLM Wiki理论与实践-04：使用OpenWiki的Personal模式构建知识库](https://jaydenai.blog.csdn.net/article/details/170335769)中配置的Connector：

- Harker News
- Notion
- Git
- Web-Search(Tavily )

## 2. index.md

作为索引文件的`index.md`包含版本声明和页面列表，用于组织整个知识库的结构，并遵循[OKF规范](https://jaydenai.blog.csdn.net/article/details/170288112)，帮助 Agent和人类理解Wiki的整体框架。如下所示的是该文件的内容：

```markdown
---
okf_version: "0.2"
---

# Files

- [Commitments](commitments.md) - Active work tasks, follow-ups, and scheduled commitments extracted from connected sources. Includes owner and due date when available.
- [Open Questions](open-questions.md) - Active uncertainties about the wiki's core memory model and unresolved coverage gaps that matter for future assistance.
- [Personal logistics](personal-logistics.md) - Non-work errands, appointments, travel, and other life-admin items captured from connected sources. Currently empty until durable evidence appears.
- [OpenWiki quickstart](quickstart.md) - Entry point for the local knowledge wiki. Summarizes current coverage, canonical pages, source indexes, and deferred work for future updates.
- [Themes](themes.md) - Compact index of recurring signals across sources. Use this as a trend map, not a narrative log.

# Directories

- [large_tool_results](large_tool_results/)
- [sources](sources/)
```

## 3. commitments.md

`commitments.md`记录了从连接的外部数据源中提取的活跃工作任务、后续跟进和调度提交。包含负责人和到期日（如果有的话）。这是面向**行动**的待办清单。OpenWiki会从邮件、Slack 消息或 Notion 中识别出需要你（或团队）采取行动的信息，并提炼成具有结构化的任务（谁在什么时候要做什么），供Agent随时调取以提醒用户。该文件目前的内容如下：

```markdown
---
type: Commitment Index
title: Commitments
description: Active work tasks, follow-ups, and scheduled commitments extracted from connected sources. Includes owner and due date when available.
tags: [commitments, tasks, follow-up]
generated: { by: "openwiki/0.5.1", at: "2026-11-08T13:08:12.029Z" }
---

# Commitments

## Active

### study-llm-wiki: Study LLM wiki
- Owner: me
- Due: 2026-11-15
- Status: Not started
- Source: [Notion source index](./sources/notion.md)
- Notes: Assigned task in the`Todo List`database.

### repo-note-triage: Review the architecture-note corpus in the local Git repo for durable wiki topics
- Owner: me

- Source: [Git repository source index](./sources/git-repo.md)
- Notes: The latest manifest indicates broad markdown churn across architecture-note topics and suggests a follow-up to decide which note clusters deserve canonical pages.
```

这两条数据反映了Agent的提取能力:

- 从Notion提取：第一条任务是从Notion的Todo List数据库中抓取的（Agent甚至知道它是一个数据库）。它成功提取了标题、负责人、截止日和状态。Notion对应Connector摄取的内容保存在`./sources/notion.md`。
- 从Git提交/清单中洞察：Agent在读取了本地Git仓库生成的清单后，基于*大量 Markdown文件的变动（churn）*这一信号（因为指定的git仓库中存储了我写的300+博客文章），主动推断/建议你需要跟进的一项工作（*Review the architecture-note corpus...*）。

## 4. open-questions.md

Wiki的核心内存模型存在一些不确定性，并且存在一些尚未解决的覆盖范围缺口。这些都会对未来的援助产生重要影响，并记录在`open-questions.md`中。这是Agent的**自我反思与待求证清单**。当数据源存在矛盾，或者Agent发现缺少某方面的关键信息时，会记录在这里。它指导着Agent在未来的交互中，遇到相关话题时主动向用户提问或寻找答案，以完善知识库。该文件目前的内容如下：

```markdown
---
type: Question Index
title: Open Questions
description: Active uncertainties about the wiki's core memory model and unresolved coverage gaps that matter for future assistance.
tags: [questions, uncertainty, memory]
generated: { by: "openwiki/0.5.1", at: "2026-11-08T13:08:12.029Z" }
---

# Open Questions

## Active

- Evidence: [Git repository source index](./sources/git-repo.md)
- Notes: The repo manifest shows broad documentation churn across many note-style markdown files, but the manifest was truncated and does not yet identify which topics are durable enough for standalone pages.

## Answered

### notion-content-gap: Where are the durable product specs, meeting notes, and research pages?
- Evidence: [Notion source index](./sources/notion.md)
- Answered: 2026-11-06

```

上面内容记录了两个问题：

- 仓库清单显示，文档在许多笔记风格的Markdown文件中频繁更新，但清单已被截断，尚未明确哪些主题应该作为独立页面被持久化存储。这是一个活跃（Answered）的待解决的问题。
- 在早期的配置或扫描中，Agent可能发现Notion连接器没有抓取希望的内容，但是后续针对内容摄取命令的执行解决了这个问题，所以这个问题的状态为Answered。

## 5. personal-logistics.md

记录Connector摄取于工作无关的差事、预约、旅行和其他生活琐事。目前为空，待出现确凿证据后才会更新。这是工作与生活的边界隔离。OpenWiki刻意将生活琐事（如*下周去医院的预约*、*买猫粮*）与工作承诺分开存放，避免生活信息污染工作上下文。由于摄取的内容没有包含这样的内容，所以该文件的正文部分没有实质性内容。

## 6. quickstart.md

`quickstart.md`是本地知识Wiki的入口。总结当前的数据覆盖率、规范页面、数据源索引以及未来更新的延迟工作。这是整个个人大脑的**仪表盘**，它告诉Agent*目前掌握了多少信息，主要分为哪几块，还有哪些没处理完*。Agent在回答用户问题或执行任务前，通常会先读取此文件来建立全局认知。当你或Agent打开这个知识库时，这里是第一站。它不提供长篇大论的具体细节，而是提供全局视野、导航入口、当前数据状态以及下一步的行动计划（Backlog），这可以从如下的内容看出来。

```markdown
---
type: Start Page
title: OpenWiki quickstart
description: Entry point for the local knowledge wiki. Summarizes current coverage, canonical pages, source indexes, and deferred work for future updates.
```

## 8. sources和large_tool_results目录

`sources/`目录存储的Connector摄取的原始内容是**证据溯源层**。`themes.md`或`commitments.md`里的结论不是凭空产生的，`sources/`下面存放了各个连接器（Gmail, Notion等）的来源索引。当 Agent 需要向用户解释*你为什么认为我这周有 3 个任务*”时，它会去`sources/`里找到具体的证据出处。每个Connector在这个目录下面都有对应的markdown文件。

```markdown
sources/
├── git-repo.md
├── hackernews.md
├── index.md
├── notion.md
└── web-search.md
```

`large_tool_results/`目录是**计算中间件缓存**。当 Agent 执行搜索或读取大文件时，由于上下文窗口限制，它不能把几百页的原始数据都塞进脑子里。它会把大体积的工具输出暂存在这里，通过文件系统工具按需分块读取。

还有一个`.last-update.json`文件记录了上次更新何时完成、哪些源拉取失败等。它是保证增量更新和错误恢复的关键（比如确保没有把半成品数据合成进Wiki里）。我最后一次执行的`openwiki personal --update`命令就记录在这里。

```json
{
  "updatedAt": "2026-11-08T13:09:15.430Z",
  "command": "update",
  "model": "gpt-5.4-mini",
  "status": "complete",
  "language": "en"
}
```
