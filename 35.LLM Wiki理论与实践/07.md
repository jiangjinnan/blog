# [LLM Wiki理论与实践-07]用来生成OpenWiki知识库和完成对话的Agent

[LLM Wiki理论与实践-06：详细解析OpenWiki如何摄取外部数据源](https://blog.csdn.net/JaydenAI/article/details/170411322)介绍的Connector仅仅是将内容导入到对应的源文件中，并更新自身的状态，并不涉及Wiki页面的生成。为构建的知识库生成Wiki，以及针对Wiki完成与用户（针对Personal模式）和Coding Agent的交互需要借助LLM的力量，其背后自然是一个Agent。作为LangChain生态的一部分，OpenWiki背后的这个Agent是通过DeepAgents创建的。

## 1. 创建一个基于Wiki的Chat Agent

不论是Wiki内容的生成，还是最终使用Wiki来完成与用户和Coding Agent的对话，其实都不算复杂。为了让大家对背后的这个Agent有一个大概的认识，接下来我会用最少的代码创建一个LangChain Agent，这个Agent会利用[LLM Wiki理论与实践-04：使用OpenWiki的Personal模式构建知识库](https://blog.csdn.net/JaydenAI/article/details/170335769)生成的Wiki知识库来回答用户的提问。

OpenWiki（这里只考虑Personal模式）的知识库就是存储在`~/.openwiki/wiki`/`%UserProfile%.openwiki/wiki`（可以通过环境变量`OPENWIKI_CONFIG_DIR`进行设置）的几个通过交叉链接相互引用的Markdown文件。如果我们使用最简单的`create_agent`函数来创建一个Agent，只需要注册`FilesystemMiddleware`中间件映射到知识库目录，并提供相应的工具函数来读取Wiki的内容即可。如下面的演示程序所示，我们针对上述的目录创建了一个`LocalShellBackend`作为`FilesystemMiddleware`中间件的存储后端。在调用`create_agent`函数针对指定的LLM（针对`gpt-5.4-mini`的`ChatOpenAI`）和这个中间件创建Agent时，我们还提供了系统提示词来指导LLM如何基于Wiki知识库来检索上下文。

```typescript
from deepagents.backends import  LocalShellBackend
from langchain.agents import create_agent
from langchain_core.runnables import RunnableConfig
from deepagents.middleware.filesystem import FilesystemMiddleware
from langchain_openai import ChatOpenAI
from langgraph.checkpoint.memory import MemorySaver
from dotenv import load_dotenv
import os, asyncio

load_dotenv()

system_prompt = f"""
You are a data retrieval and analysis expert. You need to retrieve relevant context based on the user's questions, and provide the final answer through induction, analysis, and summarization.

**How to retrieve context**

- Retrieve a Wiki knowledge base built via a virtual file system. Each Wiki page is generated from raw data ingested by registered Connectors.
- Read the content of Wiki page files by calling the file system tool functions`ls`,`read_file`,`glob`, and`grep`.
- It is recommended to use`/quickstart.md`as the entry point to start retrieval in the Wiki knowledge base.
"""

open_wiki_home = os.getenv("OPENWIKI_CONFIG_DIR") or os.path.expanduser("~/.openwiki")
open_wiki_kb = os.path.join(open_wiki_home,"wiki")
backend = LocalShellBackend(root_dir=open_wiki_kb,virtual_mode=True)

agent = create_agent(
    model= ChatOpenAI(model="gpt-5.4-mini"),
    middleware=[FilesystemMiddleware(backend=backend)],
    system_prompt=system_prompt,
    checkpointer= MemorySaver())

config:RunnableConfig = {
    "configurable":{
        "thread_id":"thread_123"
    }
}

while(True):
    user_input = input("\n$: ")
    if user_input.lower() in ["quit", "exit"]:
        break

    stream =  agent.stream_events(
        input= {"messages": [{"role": "user", "content": user_input}]},
        config=config,
        version="v3")

    for event in stream:
        if event.get("method") == "messages":
            data = event.get("params", {}).get("data", [])
            for item in data:
                block = item.get("delta") or {}
                if block.get("type") == "text-delta":
                    print(block.get("text", ""), end="", flush=True)
```

## 2. 创建Agent的工厂函数

虽然如下这个`createOpenWikiAgent`工厂函数并没有真正用于命令行的内部执行，但它体现了Agent的创建逻辑。返回的Agent类型为`DeepAgent`，代表DeepAgents通过`createDeepAgent`函数（Python SDK对应的函数名称为`create_deep_agent`）。关于DeepAgents，在我们的系列文章[12.DeepAgents:LC的Harness](https://blog.csdn.net/jaydenai/category_13163101.html)中具有系统介绍，不过我们介绍的是Python版本，OpenWiki使用的是TypeScript版本。

```typescript
export async function createOpenWikiAgent(
  options: OpenWikiAgentOptions,
): Promise<DeepAgent> {
  if (!path.isAbsolute(options.cwd)) {
    throw new Error("OpenWiki agent cwd must be an absolute path.");
  }

  if (options.outputMode === "repository" && options.command !== "chat") {
    throw new Error(
      "Repository init/update use the OpenWiki page-job runner; call runOpenWikiAgent instead of createOpenWikiAgent.",
    );
  }

  await syncBundledSkills();
  const openWikiIgnore =
    options.outputMode === "repository"
      ? await OpenWikiIgnore.load(options.cwd)
      : new OpenWikiIgnore([]);
  const context = await createRunContext(
    options.cwd,
    options.outputMode,
    options.language,
  );
  const checkpointer = await createCheckpointer(
    resolveCheckpointTarget(options.command),
  );

  return createOpenWikiAgentGraph({
    ...options,
    checkpointer,
    context,
    openWikiIgnore,
    runTimestamp: new Date().toISOString(),
  });
}
```

我们知道三种命令（`init`、`update`和`chat`）和两种执行模式（`personal/local-wiki`和`code/repository`）一共有6种组合，但是`createOpenWikiAgent`函数在Code模式下只支持`chat`命令，所以`createOpenWikiAgent`针对Agent的创建仅限于如下四个命令：

- openwiki
- openwiki personal
- openwiki personal --init
- openwiki personal --update

### 2.1 OpenWikiAgentOptions

`createOpenWikiAgent`函数的`options`是一个具有如下定义的`OpenWikiAgentOptions`对象。作为OpenWiki Agent的配置选项，`OpenWikiAgentOptions`通过解析`openwiki`命令行参数生成。

```typescript
export type OpenWikiAgentOptions = {
  command: OpenWikiCommand;
  cwd: string;
  language?: string | null;
  model: BaseChatModel;
  onEvent?: (event: OpenWikiRunEvent) => void;
  outputMode: OpenWikiOutputMode;
};

export type OpenWikiCommand = "chat" | "init" | "update";
export type OpenWikiOutputMode = "local-wiki" | "repository";
```

- **command**：本次运行要执行的OpenWiki命令，决定Agent的行为分支；
- **cwd**：运行时的当前工作目录，作为文件操作的根路径；
- **language**：输出文档的目标语言；
- **model**：Agent使用的聊天模型实例（`BaseChatModel`）；
- **onEvent**：运行过程中的事件回调，用于接收`OpenWikiRunEvent`流式输出；
- **outputMode**：输出模式，控制结果的呈现方式（`OpenWikiOutputMode`）；

`outputMode`参数对应的`OpenWikiOutputMode`类型体现了OpenWiki的Code（`repository`）和Personal（`local-wiki`）两种执行模式。`command`参数对应的OpenWikiCommand体现对话（chat）、初始化（`init`）和增量Wiki更新（`update`）三种命令。`OpenWikiCommand`和`OpenWikiOutputMode`之间一共有6种组合，但是`createOpenWikiAgent`函数的验证逻辑排除了**repository+init**和**repository+update**的组合，所以创建的Agent会应用在如下两种场景下：

- **Personal模式**：用来更新Wiki和完成与用户的对话；
- **Code模式**：用来完成与用户（独立运行openwiki命令）或者Coding Agent（作为其连接的MCP）的对话。

当Agent被创建出来后，会将用户输入作为参数以流的方式对其发起调用，并将实施接收到的Chunk解析由`OpenWikiRunEvent`类型表示的事件，`OpenWikiAgentOptions`的`onEvent`字段提供了处理这些事件的函数。如代码所示，`OpenWikiRunEvent`事件主要体现为三种类型：

- **反映Wiki生成进度的事件**：OpenWiki专为长周期、多页面的原生仓库生成任务设计的结构化进度控制事件。它的核心功能是实时反馈当前的状态机阶段（如规划中、生成中、收尾中、无需操作等），以及具体的页面处理进度（如当前页面索引、总页面数、已完成数量、正在并发处理的页面列表）;
- **跟踪工具执行事件**：当OpenWiki（Code模式）以MCP服务器挂载到Coding Agent时，后者以工具调用的方式与OpenWiki交互。工具函数在开始和结束调用时会触发此类事件；
- **获取调试信息的事件**：用于输出底层运行时的诊断日志。

```typescript
export type OpenWikiRunEvent =
  | RepositoryGenerationProgressEvent
  | {
      source?: "main" | "subgraph";
      type: "text";
      text: string;
    }
  | {
      type: "tool_start";
      call: string;
      id: string;
      input: unknown;
      name: string;
      page?: string;
    }
  | {
      type: "tool_end";
      id: string;
      name: string;
      page?: string;
      status: "error" | "finished";
    }
  | {
      type: "debug";
      message: string;
    };

export interface RepositoryGenerationProgressEvent {
  type: "repository_progress";
  stage: "planning" | "generating" | "finalizing" | "replanning" | "noop";
  resumed?: boolean;
  page?: string;
  pageIndex?: number;
  pageCount?: number;
  completedCount?: number;
  inFlightPages?: string[];
}
```

### 2.2 OpenWikiAgentGraphOptions

`DeepAgent`对象的最终创建体现在针对`createOpenWikiAgentGraph`函数的调用上，传入的参数另一个类型为`OpenWikiAgentGraphOptions`的对象，它在`OpenWikiAgentOptions`的基础上为创建的`DeepAgent`提供了如下的配置选项：

- **checkpointer**：用于持久化的·对象；
- **context**：作为调用Agent传入的静态上下文；
- **openWikiIgnore**：`.openwikiignore`文件的规则加载与匹配器，遵循`gitignore`式的**按文件顺序、最后匹配者胜出、! 可重新包含**语义；
- **runTimestamp**：调用时间戳。

### 2.3 createOpenWikiAgentGraph

`DeepAgent`的最终创建体现在如下这个`createOpenWikiAgentGraph`函数上，从针对`createDeepAgent`函数的调用上可以看出，最终创建的`DeepAgent`具有的能力和特性体现在如下几个方面：

- 注册了了通过`createOpenWikiConnectorTools`函数创建的工具函数；
- 采用`OpenWikiAgentGraphOptions`提供的`SqliteSaver`作为Checkpointer，意味着基于Thread的状态会持久化在SQLite数据库中；
- 创建的`OpenWikiLocalShellBackend`对象被`createAgentBackend`函数进一步加工，最终生成的`CompositeBackend`将作为Agent的后端；
- 将目录`/skills/`下的Markdown文件注册为Agent Skill；
- 注册了由`createSystemPrompt`函数创建的系统提示词；
- 注册了如下的中间件：
  - 针对Personal模式：通过`createFilesystemMiddleware`函数创建的`FilesystemMiddleware`中间件；
  - 针对非`chat`命令：
    - 如果需要翻译：通过`createWikiTranslationMiddleware`函数创建的用来翻译的中间件；
    - 通过`createOpenWikiIndexMiddleware`函数创建的中间件用来辅助生成更符合OKF规范的Wiki。

```typescript
function createOpenWikiAgentGraph(
  options: OpenWikiAgentGraphOptions,
): DeepAgent {
  const wikiBackend = new OpenWikiLocalShellBackend({
    docsOnly: options.command !== "chat",
    openWikiIgnore: options.openWikiIgnore,
    maxOutputBytes: 100_000,
    outputMode: options.outputMode,
    rootDir: options.cwd,
    timeout: 120,
    virtualMode: true,
  });
  const backend = createAgentBackend(wikiBackend);
  const translation = resolveTranslationPlan(
    options.command,
    requireResolvedLanguage(options.language),
    options.context.lastUpdate?.language,
  );
  
  const indexLabels = resolveIndexLabels(options.context.language);
  const conceptType = resolveConceptTypeLabel(options.context.language);

  return createDeepAgent({
    model: options.model,
    tools: createOpenWikiConnectorTools(options.outputMode),
    checkpointer: options.checkpointer,
    backend,
    middleware: [
      ...(options.outputMode === "local-wiki"
        ? [
            createFilesystemMiddleware({
              backend,
              permissions: AGENT_FILESYSTEM_PERMISSIONS,
              tools: [
                "ls",
                "read_file",
                "glob",
                "grep",
                "write_file",
                "edit_file",
              ],
            }),
          ]
        : []),
      ...(options.command === "chat"
        ? []
        : [
            ...(translation
              ? [
                  createWikiTranslationMiddleware(
                    wikiBackend,
                    options.outputMode,
                    options.model,
                    translation,
                    (message) => {
                      options.onEvent?.({ type: "text", text: message });
                      process.stderr.write(`${message}\n`);
                    },
                    (message) => {
                      options.onEvent?.({
                        type: "text",
                        text:`${message}\n\n`,
                      });
                    },
                  ),
                ]
              : []),
            createOpenWikiIndexMiddleware(
              wikiBackend,
              options.outputMode,
              indexLabels,
              conceptType,
              options.runTimestamp,
            ),
          ]),
    ],
    skills: ["/skills/"],
    subagents: [],
    permissions: AGENT_FILESYSTEM_PERMISSIONS,
    systemPrompt: createSystemPrompt(
      options.command,
      options.outputMode,
      options.context.language,
      options.openWikiIgnore,
    ),
  });
}
```

## 3. 工具函数的注册

OpenWiki之所以能够提取定义在Notion中的会议，但是我们开篇演示的实例没有这个能力，正是因为上述工具(主要是openwiki_list_mcp_tools和openwiki_call_mcp_tool，因为Notion是通过MCP连接的)注册的缺失。

## 4. 读写Wiki的后端存储

和开篇演示实例一样，`DeepAgent`利用`FilesystemMiddleware`中间件提供的工具来完成针对Wiki的读写，涉及的后端类型为`OpenWikiLocalShellBackend`。如代码所示，它派生于`LocalShellBackend`，意味着它可以利用本地的Shell执行bash命令。

```typescript
export class OpenWikiLocalShellBackend extends LocalShellBackend {
  constructor(options: OpenWikiBackendOptions) 
}
```

`OpenWikiLocalShellBackend`在`LocalShellBackend`之上叠加了四类访问控制：

-`.openwikiignore`路径排除；
- Grounded Claims状态所有权保护；
-`docs-only`写入约束（仅限`openwiki/`且可选页面白名单）；
- shell执行限制（Personal模式禁用、Code模式仅允许部分维护命令）。

`createOpenWikiAgentGraph`函数在根据当前配置将`OpenWikiLocalShellBackend`创建出来后，会将其传入如下这个`createAgentBackend`函数，它会合并针对如下两个路径的后端生成一个`CompositeBackend`对象：

- **/skills/**： 映射到物理路径`{openwiki-home}/skills`上的`FilesystemBackend`，用来提供Agent Skill；
- **/conversation_history/**： 映射到物理路径`{openwiki-home}/conversation_history`上的`FilesystemBackend`，用来存储对话历史。

```typescript
export function createAgentBackend(
  wikiBackend: OpenWikiLocalShellBackend,
  {
    historyDir = openWikiConversationHistoryDir,
    skillsDir = openWikiSkillsDir,
  }: AgentBackendMountOptions = {},
): CompositeBackend {
  return new OpenWikiCompositeBackend(wikiBackend, {
    [CONVERSATION_HISTORY_MOUNT]: new FilesystemBackend({
      rootDir: historyDir,
      virtualMode: true,
    }),
    "/skills/": new FilesystemBackend({
      rootDir: skillsDir,
      virtualMode: true,
    }),
  });
}
export const CONVERSATION_HISTORY_MOUNT = "/conversation_history/"
```

`DeepAgent`后端正是此`CompositeBackend`对象。`{openwiki-home}/skills`目录下默认会定义如下两个Skill。`mermaid-diagrams`用于在生成的Wiki页面中嵌入 Mermaid 图表，用可视化方式呈现运行时流程、状态机、数据模型等用文字难以清晰表达的内容。`write-connector`是OpenWiki内置连接器的开发规范文档，规定了从选型到交付的完整流程。。

```markdown
📁 skills
├── 📁 mermaid-diagrams
|    └── 📄 skill.md
└── 📁 write-connector
     └── 📄 skill.md
```

Personal模型下注册的`FilesystemMiddleware`中间件也是基于此`CompositeBackend`对象创建的，所以在进行对话的时候会利用此中间件提供的工具函数读写Wiki。Code模式下没有注册该中间件，文件的读写完直接落在`CompositeBackend`对象上。

## 5. 辅助翻译的中间件

如果执行`openwiki --update`或者`openwiki personal --update`命令生成Wiki时通过`--language`（或`-l`）参数指定了具体的语言，用来创建DeepAgent的`createOpenWikiAgentGraph`函数会调用`createWikiTranslationMiddleware`函数创建一个用来实施翻译的中间件。承载原始和目标语言`TranslationPlan`通过`resolveTranslationPlan`函数解析生成，并作为`createWikiTranslationMiddleware`函数的核心参数，其`translateAll`字段决定采用全量翻译还是增量翻译。

```typescript
export function resolveTranslationPlan(
  command: OpenWikiCommand,
  requestedLanguage: string | undefined,
  currentWikiLanguage: string | undefined,
): TranslationPlan | undefined

export function createWikiTranslationMiddleware(
  backend: BackendProtocolV2,
  outputMode: OpenWikiOutputMode,
  model: BaseChatModel,
  plan: TranslationPlan,
  onWarning: (message: string) => void = (message) => {
    process.stderr.write(`${message}\n`);
  },
  onStatus: (message: string) => void = (message) => {
    process.stderr.write(`${message}\n`);
  },
) {
  return createMiddleware({
    name: "OpenWikiTranslationMiddleware",
    beforeAgent: async () => {
      await translateWiki(
        backend,
        outputMode,
        model,
        plan,
        onWarning,
        onStatus,
      );
    },
  });
}

export interface TranslationPlan {
  target: string;
  source: string;
  translateAll: boolean;
}
```

创建的翻译中间件会在调用LLM之前调用`translateWiki`将Wiki现有的内容翻译成指定的语言。与此同时，语言相关的指令也会出现在调用LLM的提示词中，确保生成的Wiki采用指定的语言。

## 6. 索引中间件

`createOpenWikiAgentGraph`函数针对`openwiki --update`或者`openwiki personal --update`命令会调用`createOpenWikiIndexMiddleware`函数创建一个中间件。该中间件对于OpenWiki来说非常重要，它是确保生成的Wiki具有可靠质量的保障。

```typescript
export interface IndexLabels {
  files: string;
  directories: string;
}

export const ENGLISH_INDEX_LABELS: IndexLabels = {
  files: "Files",
  directories: "Directories",
};

export function createOpenWikiIndexMiddleware(
  backend: BackendProtocolV2,
  outputMode: OpenWikiOutputMode,
  labels: IndexLabels = ENGLISH_INDEX_LABELS,
  conceptType: string = ENGLISH_CONCEPT_TYPE,
  now: string = new Date().toISOString(),
  claimSources?: () => ClaimEvidenceResources,
) {
  let preparedWiki: PreparedWikiState | undefined;

  return createMiddleware({
    name: "OpenWikiIndexMiddleware",
    beforeAgent: async () => {
      preparedWiki = undefined;
      preparedWiki = await prepareWikiForAuthoring({
        backend,
        outputMode,
        conceptType,
        runOperation: (operation, task) =>
          inStage("build", task, {
            errorClass: "okf_error",
            errorDetail: operation,
          }),
      });
    },
    wrapToolCall: async (request, handler) => {
      const result = await handler(request);
      return addFrontmatterWarning(
        result,
        backend,
        outputMode,
        request.toolCall.name,
        conceptType,
      );
    },
    afterAgent: async () => {
      if (!preparedWiki) {
        throw new Error("Wiki finalization requires prepared run state.");
      }
      await finalizeWikiArtifacts({
        backend,
        outputMode,
        labels,
        conceptType,
        prepared: preparedWiki,
        at: now,
        claimSources: claimSources?.(),
        runOperation: (operation, task) =>
          inStage("finalize", task, {
            errorClass: "okf_error",
            errorDetail: operation,
          }),
      });
    },
  });
}
```

中间件定义了如下三个钩子：

- **beforeAgent**：是Agent开始写作前的准备工作，做两件事：
  - 按照OKF规范对现有的Wiki页进行修改（如果只有在验证内容不符合规范才会实施文件更新）；
  - 为每个页面生成一个概念快照（`ConceptSnapshot`），记录下从Yaml元数据的`generated`字段（比如`generated: { by: "openwiki/0.5.1", at: "2026-11-08T13:08:12.029Z" }`）；
- **wrapToolCall**：通过封装工具调用拦截针对Wiki页的写入，并重新加载其内容按照OKF规范进行验证，并在不符合规范的情况下对内容进行修正；
- **afterAgent**：在Agent结束执行后对Wiki页面的内容进行总体验证和修正：
  - 验证Wiki页中生成的Mermaid图表，如果没有通过验证会将mermaid围栏（mermaid fence）降级成纯文本形式；
  - 扫描每个子目录，并在其中生成`index.md`索引页；
  - 遍历所有Markdown文件，检查相对链接和GitHub风格标题锚点是否有效，把断链就地打上标记（而非让运行失败），并返回统计报告;
  - 将执行本轮update命令的Actor（`openwiki/${OPENWIKI_VERSION}`）和时间戳以`generated`字段的形式写入更新的Wiki页。
