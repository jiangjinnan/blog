# [基于JEV的决策模型-02]从TypeSafe SDK详细介绍针对Jev模型的调用

[基于JEV的决策模型-01:利用概率回答四种典型的问题](https://jaydenai.blog.csdn.net/article/details/170837800)演示了如何利用TypeSafe SDK提供的客户端对象`TypeSafeClient`针对同一个上下文状态调用Jev/System-One模型，并一次获得多个不同类型问题的答案（主要体现为相应的概率分布），本篇文章着重介绍这个`TypeSafeClient`类型，看看它具体提供哪些配置选项，以及输入和输出都包含什么内容。

## 1. TypeSafeClient的初始化

`TypeSafeClient`构造函数创建面向TypeSafe AI API的HTTP客户端，解析配置与重试策略，并初始化或复用底层HTTP客户端。HTTP客户端会在`close`方法中关闭，后者会在实现的`__exit__`方法中调用。

```python
class TypeSafeClient:
    def __init__(
        self,
        *,
        api_key: str | None = None,
        model: str | None = None,
        retry: RetryPolicy | None = None,
        timeout: float | httpx2.Timeout | None = None,
        headers: Mapping[str, str] | None = None,
        transport: httpx2.BaseTransport | None = None,
        http_client: httpx2.Client | None = None,
        base_url: str | None = None,
        compression: Literal["zstd", False] | None = None,
    ) -> None

    def close(self) -> None:
        self._http_client.close()

    def __enter__(self) -> Self:
        return self

    def __exit__(self, exc_type: type[BaseException] | None, exc_value: BaseException | None, traceback: TracebackType | None) -> None:
        self.close()
```

各参数说明如下：

- **api_key**：必需的 API key，可通过环境变量`TYPESAFE_API_KEY`设置。首尾空白会被去除；空 key、内部空白、控制字符及非 ASCII 字符会被拒绝；缺失或非法时抛出`TypeSafeError`。
- **model**：模型名称，可通过环境变量`TYPESAFE_DEFAULT_MODEL`设置。
- **retry**：控制重试行为的`RetryPolicy`，详见其选项与默认值；传`RetryPolicy(max_retries=0)`可禁用重试。
- **timeout**：HTTP 操作超时时间。若传入`http_client`则继承其`timeout`，否则使用 SDK 默认值；非法超时抛出`TypeSafeError`。
- **headers**：额外设置的请求头。
- **transport**：可选的自定义HTTP transport，SDK 客户端关闭时一并关闭；与`http_client`互斥，同时传入抛出`ValueError`。
- **http_client**：可选的`httpx2.Client`，与`transport`互斥；SDK客户端关闭时一并关闭（包括外部传入的客户端）。
- **base_url**：API 根地址，可通过环境变量`TYPESAFE_BASE_URL`设置。
- **compression**：请求体压缩方式，`zstd`或`False`（不压缩）；默认在可用时使用`zstd`，`zstd`不可用时抛出`TypeSafeError`。

调用构造函数时可以利用retry参数指定的`RetryPolicy`对象提供具体的重试策略，该类型定义如下：

```python
@dataclass(frozen=True)
class RetryPolicy:
    max_retries: int = 2
    backoff_initial: float = 0.5
    backoff_max: float = 5.0
    backoff_jitter: float = 0.25
    http_statuses: set[int] = field(default_factory=lambda: {408, 429, *range(500, 600)})
    respect_retry_after: bool = True
    api_connection_error: bool = True
    api_timeout_error: bool = True
    exceptions: set[type[BaseException]] = field(default_factory=set)
    predicate: Callable[[BaseException], bool] | None = None
    timeout: float | None = 30.0
```

和常规的调用重试类似，这里也采用退避延时的策略，具体的策略选项包括：

- **max_retries**：初始尝试之后的最大重试次数，默认`2`；`0`表示禁用重试。
- **backoff_initial**：首次退避延迟（秒），默认`0.5`；每次尝试翻倍，直至`backoff_max`；为`0`时禁用退避。
- **backoff_max**：最大退避延迟（秒），默认`5.0`；为`0`时禁用退避。
- **backoff_jitter**：每次退避延迟中被随机减去的比例，取值`0`到`1`，默认`0.25`。
- **http_statuses**：会触发重试的 HTTP 状态码集合，默认`{408, 429, 500..599}`。
- **respect_retry_after**：是否遵循响应头`Retry-After`与`retry-after-ms`，默认`True`。
- **api_connection_error**：是否重试`TypeSafeAPIConnectionError`（请求无法到达或读取服务器），默认`True`。
- **api_timeout_error**：是否重试`TypeSafeAPITimeoutError`（请求超时），默认`True`。
- **exceptions**：在内置规则之外，额外触发重试的异常类型集合，默认空集合。
- **predicate**：可选谓词，接收抛出的异常；返回`True`时在其他规则之外额外触发重试，默认`None`。
- **timeout**：每次 SDK 调用的总重试预算（秒），包含初始尝试与延迟；`None`表示不限制，默认`30.0`。若下一次重试的延迟会达到或超过预算，则停止重试并重新抛出最后一次错误。

## 2. 列出所有的模型

我们可以利用`TypeSafeClient`的`models`属性提供的`Models`对象，后者利用`list`方法通过远程调用的方式获取当前可用的模型列表。

```python
class TypeSafeClient:
    @cached_property
    def models(self) -> Models:

class Models:
    def __init__(self, config: Config, http_client: httpx2.Client, retry: Retrying) -> None
    def list(
        self,
        *,
        retry: RetryPolicy | None = None,
        timeout: float | httpx2.Timeout | None = None,
        extra_headers: Mapping[str, str] | None = None,
    ) -> ListModelsResponse
```

`list`方法返回的`ListModelsResponse`对象利用`models`字段返回一组`ModelMetadata`对象列表，每个`ModelMetadata`对应一个模型，并提供模型的名称、描述和发布日期。

```python
class ListModelsResponse(Response):
    models: tuple[ModelMetadata, ...]

class ModelMetadata(Schema):
    name: str
    description: str
    release_date: str
```

在如下的演示程序中，我们得到TypeSafeClient的models，并调用这个`Models`对象的`list`方法将模型列表列出来。

```python
import os
from dotenv import load_dotenv
from typesafe_sdk import  TypeSafeClient

load_dotenv()

with TypeSafeClient() as client:
    for model in client.models.list().models:
        print(f"""
model: {model.name}
description: {model.description}
release_date: {model.release_date}"""    
)
```

输出：


## 3. 四种类型的问题

Jev/System-One模型旨在回答如下四种类型的问题：

- **Noul**：是/否（布尔或概率）判断型问题。
- **Choice**：多选一分类问题。
- **Score**：评分型问题（按你给出的名称），用于对内容按某种标准打分。
- **Box**：框选/定位型问题（按你给出的名称），通常用于在文本或图像中定位目标区域。

上述四种问题类型都具有对应的类型定义，如下这个派生于`pydantic.BaseModel`的`_Question`基类。它通过设置`model_config`禁止提供不可识别数据成员，利用标准了`@model_serializer`的`_omit_none`方法过滤掉值为`None`的成员。

```python
class _Question(BaseModel):
    model_config = ConfigDict(extra="forbid")

    @model_serializer(mode="wrap")
    def _omit_none(self, handler: SerializerFunctionWrapHandler) -> dict[str, Any]:
        return {key: value for key, value in handler(self).items() if value is not None}
```

核心类型`Question`定义如下，可用看出它是这对五个类型的联合。`Noul`/`NoulModel`、`Choice`/`ChoiceModel`、`Score`/`ScoreModel`和`Box`/`BoxModel`分别对应四种典型的问题类型，`QuestionModel`是对`NoulModel`、`ChoiceModel`、`ScoreModel`和`BoxModel`的联合。

```python
Question: TypeAlias = Noul | Choice | Score | Box | QuestionModel
QuestionModel: TypeAlias = NoulModel | ChoiceModel | ScoreModel | BoxModel
```

### 3.1 Content

在正是介绍四种问题类型之前，我们先来认识一下它们都会涉及到的`Content`类型。这个类型也是核心`system_one`方法中 state 参数的类型别名，用来描述**可以被评估的输入状态**的合法形态。它本身是一个递归类型：值可以是标量、结构化的JSON对象/数组，或多媒体资产（`Asset`）。

```python
Content = TypeAliasType(
    "Content",
    "str | Mapping[str, ContentValue | None] | Sequence[ContentValue | None] | Asset",
)

ContentValue = TypeAliasType(
    "ContentValue",
    "str | int | float | bool | Sequence[ContentValue | None] | Mapping[str, ContentValue | None] | Asset",
)
```

所谓的多媒体资产在这里只有一种，就是通过如下这个`Image`类型表示的图片，`Asset`仅仅是它的别名而已。

```python
Asset: TypeAlias = Image
@dataclass(frozen=True, eq=False)
class Image:
    type: Literal["image"] = field(default="image", init=False)
    data: Buffer | PathLike[str]   

    @classmethod
    def from_base64(cls, data: str | Buffer) -> Self:

    @classmethod
    def from_pil(cls, image: "PIL.Image.Image", format: str = "jpeg") -> Self
```


### 3.2 Noul/NoulModel

表示二元是非问题的类型被命名为`Noul`，并非源自单词`Noul`，而是源于数学家伯努利（Bernoulli）的名字，具体应该源自基于二元随机变量的伯努利试验。`Noul`派生于`wire.NoulQuestion`基类，它仅仅为每个字段指定了默认值，并将`instructions`字段类型改写成`Content`而已。

```python
class Noul(_Question, wire.NoulQuestion):
    type: Literal["noul"] = "noul"
    instructions: Content | None = None  
    criteria: NoulCriteria | None = None

class NoulQuestion(BaseModel):
    type: Literal["noul"] 
    instructions: str | dict[str, Any] | list[Any] | None
    criteria: NoulCriteria | None

class NoulCriteria(TypedDict, total=False, closed=True):
    true: Content | None
    false: Content | None
```

`instructions`字段是除Box之外的所有类型的问题都具有的字段，它是给模型看的自然语言提示，用来说明*这个问题到底要问什么、按什么标准判断*。它不是问题名，也不是答案，而是对提问意图/判定规则的描述。`Noul`对象的`criteria`字段返回一个`NoulCriteria`对象，用来补充说明**是**和**否**分别意味着什么，从而把`instructions`里那句`yes/no`问题的边界讲清楚。`NoulModel`类型也具有类似的结构。

```python
class NoulModel(TypedDict, closed=True):
    type: Literal["noul"]
    instructions: NotRequired[Content | None]
    criteria: NotRequired[NoulCriteria | None]
```

### 3.3 Choice/ChoiceModel

`Choice`/`ChoiceModel`用来描述多选一的问题，它们和`Noul`/`NoulModel`具有相同的字段成员，唯一不同在于它`criteria`需要返回一个字典来描述每个提供的选项。

```python
class Choice(_Question, wire.ChoiceQuestion):
    type: Literal["choice"] = "choice"
    criteria: Mapping[str, Content | None]
    instructions: Content | None = None  

class ChoiceQuestion(BaseModel):
    type: Literal["choice"] 
    instructions: str | dict[str, Any] | list[Any] | None
    criteria: dict[str, str | dict[str, Any] | list[Any] | None]

class ChoiceModel(TypedDict, closed=True):
    type: Literal["choice"]
    instructions: NotRequired[Content | None]
    criteria: Mapping[str, Content | None]
```

### 3.4 Score/ScoreModel

`Score`/`ScoreModel`用来回答评分问题，它一般会设置几个分数挡位，最终会将它们视为随机变量并按照模型得到的概率分布计算期望值（基于概率的加权平均）作为分数。它们和`Noul`/`NoulModel`具有相同的字段成员，唯一不同在于它`criteria`需要返回一个列表来提供和描述分数挡位。

```python
class Score(_Question, wire.ScoreQuestion):
    type: Literal["score"] = "score"
    criteria: Sequence[Content] 
    instructions: Content | None = None

class ScoreQuestion(BaseModel):
    type: Literal["score"] 
    instructions: str | dict[str, Any] | list[Any] | None 
    criteria: list[str | dict[str, Any] | list[Any]]

class ScoreModel(TypedDict, closed=True):
    type: Literal["score"]
    instructions: NotRequired[Content | None]
    criteria: Sequence[Content]
```

### 3.5 Box/BoxModel

`Box`问题解决的是**某个东西在图片的什么位置**这个问题。它接收一张图片和一段自然语言描述，返回该目标在图片中的边界框坐标，而不是像`Noul`那样只回答**是/否**，也不像`Choice`那样从选项里挑一个。相关的`Box`/`BoxModel`定义如下，它们不需要`criteria`字段。

```python
class Box(_Question, wire.BoxQuestion):
    type: Literal["box"] = "box"
    instructions: Content | None = None  

class BoxQuestion(BaseModel):
    type: Literal["box"]
    instructions: str | dict[str, Any] | list[Any] | None

class BoxModel(TypedDict, closed=True):
    type: Literal["box"]
    instructions: NotRequired[Content | None]
```

## 4. 问题的答案

Jev模型会针对不同类型的问题返回对应的答案，所以TypeSafe SDK针对四种问题类型定义了对应的答案类型。`NoulAnswer`最简单，只需要利用`noul`字段返回真值概率就可以。

```python
class NoulAnswer(wire.NoulAnswer):
    model_config = ConfigDict(extra="ignore", frozen=True, strict=True)
    type: Literal["noul"] = "noul"  
    
#wire.NoulAnswer
class NoulAnswer(BaseModel):
    type: Literal["noul"] 
    noul: float 
```

`ChoiceAnswer`会返回指定的选项（`choice`）和它们的概率分布（`probabilities`），并利用此分布计算一个置信度（`confidence`）。至于相似计算公式可以参考[基于JEV的决策模型-01:利用概率回答四种典型的问题]()。

```python
class ChoiceAnswer(wire.ChoiceAnswer):
    model_config = ConfigDict(extra="ignore", frozen=True, strict=True)
    type: Literal["choice"] = "choice" 

# wire.ChoiceAnswer
class ChoiceAnswer(BaseModel):
    type: Literal["choice"]
    choice: str 
    confidence: float 
    probabilities: dict[str, float] 
```

`ScoreAnswer`返回的内容会一些，除了针对每个分数挡位的概率分布（`probabilities`）和置信度（`confidence`），还有作为期望值的分数（`score`）和针对每个分数挡位的描述（`legend`）。

```python
class ScoreAnswer(wire.ScoreAnswer):
    model_config = ConfigDict(extra="ignore", frozen=True, strict=True)

    type: Literal["score"] = "score" 
    legend: dict[int, str | dict[str, Any] | list[Any]] 
    probabilities: dict[int, float] 

# wire.ScoreAnswer
class ScoreAnswer(BaseModel):
    type: Literal["score"] 
    score: float
    confidence: float 
    legend: dict[str, str | dict[str, Any] | list[Any]] 
    probabilities: dict[str, float] 
```

`BoxAnswer`会利用`box`字段给出图片选中部分的四个边框的坐标和置信度。

```python
class BoxAnswer(wire.BoxAnswer):
    model_config = ConfigDict(extra="ignore", frozen=True, strict=True)
    type: Literal["box"] = "box"  
    box: BoxCoordinates  
    confidence: float | None  

class BoxCoordinates(wire.BoxCoordinates):
    model_config = ConfigDict(extra="ignore", frozen=True, strict=True)

# wire.BoxAnswer
class BoxAnswer(BaseModel):
    type: Literal["box"] 
    box: BoxCoordinates 
    confidence: float | None 

# wire.BoxCoordinates
class BoxCoordinates(BaseModel):
    top: float = 
    bottom: float 
    left: float 
    right: float 
```

## 5. System-One模型的调用

`TypeSafeClient`定义了三个重载的`system_one`方法来完成针对System-One模型调用，目的是让类型检查器根据是否传`response_model`推断出不同的返回类型。

```python
class TypeSafeClient:
    @overload
    def system_one(
        self,
        state: Content,
        questions: Mapping[str, Question],
        *,
        model: str | None = None,
        assets: Mapping[str, Asset] | None = None,
        retry: RetryPolicy | None = None,
        timeout: float | httpx2.Timeout | None = None,
        extra_headers: Mapping[str, str] | None = None,
        extra_body: Mapping[str, JSONValue | None] | None = None,
        response_model: None = None,
    ) -> SystemOneResponse: ...

    @overload
    def system_one(
        self,
        state: Content,
        questions: Mapping[str, Question],
        *,
        model: str | None = None,
        assets: Mapping[str, Asset] | None = None,
        retry: RetryPolicy | None = None,
        timeout: float | httpx2.Timeout | None = None,
        extra_headers: Mapping[str, str] | None = None,
        extra_body: Mapping[str, JSONValue | None] | None = None,
        response_model: type[ResponseT],
    ) -> ResponseT: ...

    def system_one(
        self,
        state: Content,
        questions: Mapping[str, Question],
        *,
        model: str | None = None,
        assets: Mapping[str, Asset] | None = None,
        retry: RetryPolicy | None = None,
        timeout: float | httpx2.Timeout | None = None,
        extra_headers: Mapping[str, str] | None = None,
        extra_body: Mapping[str, JSONValue | None] | None = None,
        response_model: type[ResponseT] | None = None,
    ) -> SystemOneResponse | ResponseT
```

涉及的相关参数说明如下：

- **state**：`Content`，必填。待评估的内容：文本、JSON 对象、数组或资产。
- **questions**：`Mapping[str, Question]`，必填。问题名到问题对象的映射，非空。
- **model**：`str | None = None`，可选。模型覆盖；`None`继承客户端默认值。
- **assets**：`Mapping[str, Asset] | None = None`，可选。按引用键组织的资产，用于在`state`或问题中引用。
- **retry**：`RetryPolicy | None = None`，可选。仅本次调用的重试策略覆盖。
- **timeout**：`float | httpx2.Timeout | None = None`，可选。仅本次调用的HTTP超时覆盖（秒）。
- **extra_headers**：`Mapping[str, str] | None = None`，可选。额外请求头。
- **extra_body**：`Mapping[str, JSONValue | None] | None = None`，可选。额外顶层请求体字段，在`state`/`model`/`questions`/`assets`之后浅合并，键冲突时覆盖，对象值替换而非深合并。
- **response_model**：`type[ResponseT] | None = None`，可选。描述响应体JSON的Pydantic`BaseModel`类型；不传返回`SystemOneResponse`，传入返回该模型实例。

作为相应结果的`SystemOneResponse`类型定义如下，我们可以从中得到调用的模型名称、输入和输出Token数量、以及答案。

```python
class SystemOneResponse(Response):
    model: str
    usage: Usage
    answers: dict[str, Answer] 

    @cached_property
    def nouls(self) -> dict[str, NoulAnswer]

    @cached_property
    def choices(self) -> dict[str, ChoiceAnswer]

    @cached_property
    def scores(self) -> dict[str, ScoreAnswer]

    @cached_property
    def boxes(self) -> dict[str, BoxAnswer]

class Usage(wire.Usage):
    model_config = ConfigDict(extra="ignore", frozen=True, strict=True)
    input_tokens: int | None = None  
    output_tokens: int | None = None 
```
